# 预演视频拆镜

用户想先看整体节奏和构图，再逐个生成正式镜头时使用。这里的预演是生成出来的一条视频，不是画板上的机位预演节点：先生成一条包含多个镜头的预演，用镜头拆解按切点拆成镜头，每段的中间帧作为该镜头的首帧，再用首帧逐个生成正式镜头。效果取决于所用模型，开始前在回复里说明这一点。

## 先确认

- 要有分镜脚本或剧本。没有时先按“剧本拆镜头”方法列出镜头，再回到这里。
- 预演和正式镜头都要付费生成。预演用哪个模型、多长，用 mioon_ask 问一次：选项写成 provider.list 里可用的具体模型和时长，优先便宜或快速的模型和较低的分辨率。
- 加载 video、scenes 和 canvas 组。用 provider.list 读所选模型的 durations 和 inputModes：预演只用文字生成；正式镜头要用首帧，模型的 inputModes 里要有 image 或 frames。
- 每轮默认最多 30 步。镜头较多时分几轮做：第一轮生成预演并拆成镜头，之后每轮补全并生成一批镜头。

## 写预演提示词

- 按脚本顺序写成一条提示词：“镜头1：……；镜头2：……”。每个镜头只写一个关键画面：谁在哪里、在做什么、什么景别。
- 镜头之间一律硬切。不要叠化、淡入淡出或其他转场，否则拆解找不到切点。
- 不要台词、字幕和画面文字。角色外貌、服装和场景按项目说明写，前后镜头用同一组词。
- 镜头数要和预演时长相配，每个镜头至少留半秒左右；镜头太多时分成几条预演。
- 所选模型有提示词长度上限（maxPromptLength）时控制在上限以内。

## 生成预演

1. 用 shot.create 建一个预演镜头：标题写“预演”，提示词是上面那条，时长取所选模型 durations 里的值，画幅用项目时间线的画幅。
2. 用 generation.submit 提交，按正常流程确认费用；用 task.wait（kind 为 job）等结果。
3. 拆解只接受 8 位 yuv420p 的 MP4 或 WebM，最长 600 秒。生成参数里能选分辨率时，选 720p 或更低。

## 拆成镜头

1. 从任务结果或 version.list 找到预演视频的素材 ID，再用 asset.list 读到它的 sha256，作为 sourceHash。
2. 调用 scene.detect。预演里的镜头较短，把 options.minShotSeconds 设为 0.3 左右；sensitivity 先用默认值。用 task.wait（kind 为 scene）等任务结束，再用 scene.result.get 读切点和结果 ID。
3. 段数应等于计划的镜头数。少了就调高 sensitivity 重新检测（每次加 10，不超过 70）；多了就调低，或者只选需要的段。仍然对不上时，告诉用户哪几个镜头没拆开，不要硬凑。
4. 用 scene.shots.create 按选中的段建镜头（默认先确认），titlePrefix 写场景名；用 task.wait（kind 为 scene）等结果，任务结果里有每段对应的镜头 ID。新镜头的提示词是空的，时长是段长取整，首帧参考是该段的中间帧。

## 补全并生成正式镜头

- 用 shot.update 给每个新镜头写标题和提示词：内容按原脚本，写法按“镜头提示词”方法，首帧里已有的外貌和场景不要改写。时长改成正式所用模型 durations 里的值。
- 预演画面分辨率低，也可能有瑕疵，而首帧会决定正式镜头的画面。某个首帧不能用时在回复里指出，由用户决定换图，还是去掉首帧（shot.update 把 referenceAssetIds 设为空）。
- 正式镜头每个都要单独付费生成。先在回复里列出镜头数和所选模型，用户同意后再逐个提交。
- 预演镜头留在画板上供对照，不要删除。

## 回复

说明预演拆成了几个镜头、和计划差几个，哪些首帧可能需要替换，以及正式生成还剩几条。
