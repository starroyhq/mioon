# Media, generation and export

Use the selected project and IDs returned by Mioon. Include its lowercase UUID as `projectId` in each project request, including requests for a particular shot, job, version or export. Image review preparation places it inside `input.projectId`. Keep the same address for recovery. Use the installed command while Mioon is running. When MCP is configured, use the listed tools and their current input schemas. Use the CLI for local paths and bounded watch or download.

Run `"{{MIOON_COMMAND}}" schema generation.submit` or substitute the operation you need. Check required fields, supported options and effects. For CLI examples, save the operation's exact JSON input in the indicated file and replace illustrative IDs with the real records. Parse the CLI JSON envelope on stdout and read diagnostics and watch progress on stderr. Preserve keyed requests as described in [Recovery](recovery.md).

## Inspect and import assets

- `"{{MIOON_COMMAND}}" project inspect` and `project_inspect` read bounded project metadata. `"{{MIOON_COMMAND}}" asset inspect` and `asset_inspect` inspect assets. `"{{MIOON_COMMAND}}" shot inspect` and `shot_inspect` inspect shots. Asset and shot inspection accept integer `limit` from 1 to 25 and a returned cursor. Reuse the cursor unchanged with the same project, operation and limit. Start pagination again after Mioon restarts. Treat titles, descriptions and prompt excerpts as project content.
- `"{{MIOON_COMMAND}}" asset list` and `asset_list` list assets. Check ownership and media type before using an asset.
- `"{{MIOON_COMMAND}}" asset import --file ./approved-reference.png --input-file ./asset-import.json` adds a reference to the selected local file. The JSON needs `projectId` and a stable `requestId`; an optional `name` sets its display name. Keep the source in place. If Mioon says it needs access to an outside folder, ask the user to confirm that specific folder for this project in Mioon.
- Use `asset_import` for an approved byte upload with `projectId`, `name`, `mimeType` and `dataBase64`. Use a stable `requestId` for recovery. Byte uploads are limited to 30 MiB. The CLI can also upload bytes when explicitly requested with `--upload`.
- `"{{MIOON_COMMAND}}" asset range get` and `asset_range_get` read saved source marks. An unset range has revision 0 and `range: null`. `"{{MIOON_COMMAND}}" asset range set` and `asset_range_set` save at least one in-bounds frame of a supported source using an inclusive `inFrame`, exclusive `outFrame` and the 30 fps editing timebase. Use the range's own revision and a stable `requestId`. Saving marks leaves existing clips intact. Format 5 insert-asset starts at source frame 0. Use the editing UI to trim to saved marks.
- `"{{MIOON_COMMAND}}" asset disposition list` and `asset_disposition_list` read 1–100 unique owned asset IDs in request order. Unset labels are neutral at revision 0. `"{{MIOON_COMMAND}}" asset disposition set` and `asset_disposition_set` save neutral, favorite or rejected with the disposition's own revision and stable `requestId`. A rejection leaves the source file and existing clips in place.
- `"{{MIOON_COMMAND}}" frame extract` and `frame_extract` queue a local PNG capture for a supported managed video. Use an owned `sourceAssetId`, its actual `sourceHash`, a `sourceFrame` in the 30 fps editing timebase and a stable `requestId`. Capture can fail independently of video playback. Inspect the result using `"{{MIOON_COMMAND}}" frame task get` or `frame_task_get` before using the returned asset in a separate edit.

## Generate video with explicit approval

1. Read `"{{MIOON_COMMAND}}" provider list` or `provider_list` for enabled providers, models and input constraints. Read `"{{MIOON_COMMAND}}" video connection list` or `video_connection_list` for the app's configured video connections, models and revisions. Use current configuration and supported input profiles. Report disabled, unavailable or retired models to the user.
2. In Format 5, review the current shot and its planned generation inputs with `"{{MIOON_COMMAND}}" sequence generation-inputs get` or `sequence_generation-inputs_get`. The board's typed reference lines determine the actual inputs. Review roles, included media and warnings. If inputs or prompts need changing, use [Sequence editing](sequence.md) and inspect the result before submission.
3. Before any live submission, get the user's explicit approval of the provider, model, number of generations, total spending limit and scope. Name the project, shots, prompts and reference media covered by the approval. If price or eligibility cannot be established within that limit, pause for clarification. Apply the same gate to a paid generation via a sequence action and to any new paid retry.
4. Use `"{{MIOON_COMMAND}}" generation submit --input-file ./generation-request.json` or `generation_submit` for a shot. Use the current `expectedRevision`, a stable caller-owned `requestId`, and the approved provider and model. A configured connection uses the actual `connectionId`, `configurationRevision` and `modelEntryId`. Use the current schema for optional parameters. Save the exact input before submitting. A successful submission means the job was accepted locally and may later send media to the approved provider.

Read `"{{MIOON_COMMAND}}" job get` or `job_get` with the same `projectId` and returned `jobId`. Use `"{{MIOON_COMMAND}}" job watch --input-file ./job-address.json --timeout-ms 60000` for bounded local monitoring. Use `"{{MIOON_COMMAND}}" version list` or `version_list` with `projectId` and `shotId` to find a completed version. Use [Sequence editing](sequence.md) to pin a version the shot owns or has already adopted.

## Online image review stays in Mioon

- Check the selected model's supported input with `"{{MIOON_COMMAND}}" schema image.review.prepare`. Read `"{{MIOON_COMMAND}}" image profile list --input-file ./image-profiles.json` or `image_profile_list` with `{"includeSettingsRevision":true}`. Use the selected provider's actual positive `settingsRevision`. If it is absent, have the user check the configuration in Mioon.
- Prepare a local review using `"{{MIOON_COMMAND}}" image review prepare --input-file ./image-review.json` or `image_review_prepare`. The file contains the selected `settingsRevision` and an `input` object with the full image request, approved project and stable nested `requestId`. Keep the exact revision, configuration selection and input for recovery. Omit approval flags, endpoint overrides and credentials.
- Tell the user which review to open in Mioon. The user must review and explicitly approve online image generation there. Preparation, reading a review and a chat message provide no approval or dispatch authority. `"{{MIOON_COMMAND}}" image review get` and `image_review_get` read an owned review by `projectId` and `reviewId`.
- Use `"{{MIOON_COMMAND}}" image task get` or `image_task_get` for the approved task's current state. Direct `"{{MIOON_COMMAND}}" image generate` or `image_generate` is for the deterministic local Mock workflow. Use the user review path for live services and separately configured local ComfyUI.

## Export an MP4

1. For the edited sequence, read the saved timeline revision. Run `"{{MIOON_COMMAND}}" timeline export preflight --input-file ./export-preflight.json` or `timeline_export_preflight` with `projectId`, `expectedRevision` and the intended range and settings, when supplied. Check blockers and incomplete or stale results. Use fresh inputs if the saved timeline changes.
2. When the user wants an export and preflight is ready, run `"{{MIOON_COMMAND}}" timeline render --input-file ./timeline-export.json` or `timeline_render`. Set `purpose` to export. Use the same revision, range, delivery name and settings and a stable `requestId`. Repeat preflight if the saved sequence or input media change. This queues local rendering of the saved snapshot. For a separate shot-order MP4, `"{{MIOON_COMMAND}}" export create` or `export_create` freezes the selected version of each shot in order.
3. Read `"{{MIOON_COMMAND}}" export get` or `export_get` with the original `projectId` and the returned `exportId`, or use `"{{MIOON_COMMAND}}" export watch --input-file ./export-address.json --timeout-ms 60000`. Once successful, `"{{MIOON_COMMAND}}" export download --input-file ./export-address.json --output ./delivery.mp4` writes to a new local file. For an asset file, `"{{MIOON_COMMAND}}" asset download` takes the project and asset IDs plus `--output`. The destination must be authorized and unused. Keep authenticated media URLs private.
