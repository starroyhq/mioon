## 基线复现

未修改的隔离副本完成冻结安装、类型检查及 development 构建。浏览器全新数据目录新建项目和刷新均出现 `Cannot read properties of null (reading 'list')`，工作台没有挂载，见 [浏览器记录](baseline-browser.json)与[截图](browser/baseline-project-blank.png)

根因是主体库在 hook 首帧或项目切换时将合法的空状态强制当成非空状态读取。修复保留 hook 的项目隔离语义，在组件边界显示加载状态

## 结果

白屏已修复，用户列出的入口及设置差异已调整。修改位于独立工作树的 `codex/project-open-design-fixes` 分支，尚未提交或推送

- 主体库接受 hook 合法的首帧空状态，显示加载提示；不再强制转换为非空状态。保留项目切换隔离、错误提示及旧回调失效机制
- 登录使用应用语言选择组件，已填令牌的主按钮立即显示白底黑字，空令牌仍禁用
- 空首页保留中央 36px 主按钮，移除重复顶栏创建及多余说明，标题改为“全部项目”；帮助入口承接只读状态和手动刷新
- 新建项目恢复“新建项目”“创建项目”，三种原生 1080 画幅补充图标与选中态
- 通用设置改为分段控件，保存栏固定在底部；修复英文时间码、日文主题标签裁切及 Switch 点击区造成的横向滚动
- 模型页显示 Seedance 2.5、Veo 3.1、本地模拟和检测按钮；真实生成开关反映服务端状态。它仍由启动配置控制，界面只读，不引入新的配置写入接口
- 助理设置直接展示表单和已授权目标，说明改为同一完整目标地址、模型及范围持久授权；工作区备份默认展开
- 视频工具显示本机版本、编码能力与缺失能力警告。未改动官方 Base UI 源文件和依赖清单
- 补齐语言菜单及帮助 Portal 的宿主可见性约束，隐藏、卸载和关闭后保留的旧回调不能继续操作
