# 第三轮 R2：单片段响度分析与匹配补全

2026-10-20，用户明确授权补齐 LRA、目标响度与匹配能力。改动仍在 `codex/project-open-design-fixes` 工作树，未提交、未推送；此前第二轮提交为 `01a83cb`

## 最终行为

- 音频属性卡显示综合响度、估算真峰值、LRA、目标LUFS与峰值上限。默认目标−14 LUFS / −1 dBTP只在本地，显式点击分析后才发送；打开、切选、重连和恢复可见性不自动分析
- 单片段 LRA 使用独立完整窗口 profile：3秒窗口、100毫秒步进、绝对/相对门限、10/95百分位差。短于3秒明确无LRA结果；恒定音频可以真实测得0，不用0冒充缺失值
- 有目标时，后端保留最多23,040,000字节解码后浮点PCM，施加恒定倍率，再完整重新门控、K加权和真峰值计量；目标和峰值许可基于真实第二次测量，保留0.5dB余量
- 增益必须为正且≤2；不裁剪峰值，不降低目标，不默默把越界值截成2。无法满足时显示原因并禁用匹配
- “匹配到草稿”只暂存通过校验的gain；点击“保存片段”才通过原有 `timeline.clip.update` 生效，沿用精确版本、原requestId、未知结果恢复及一次撤销/重做
- 当前响度已在0.1 LU目标容差内时不生成无意义的反复微调，显示避免−0.00dB；真实候选值保留原精度

独立片段分析不等于整片混音或AAC成片峰值保证。此功能没有limiter、批量归一化或自动导出

## 接口、兼容与审查

既有 `timeline.clip.loudness` 新增可选 `target`，复用现有目标字段 `integratedLufs` / `truePeakCeilingDbtp`。省略目标保持旧请求和响应有效；有目标必须返回精确绑定的实际候选。LRA位于独立可选 `loudnessRange` 字段，没有改变已有BS.1770测量profile或持久measurement schema

HTTP、真实CLI与官方MCP共享严格schema，仍是只读操作，`applyAllowed`始终false；没有新增mutation、数据库schema或生产依赖。contracts包只增加LRA子路径导出。内置助理工具目录未扩大

原始、候选与来源保持完整身份、两次hash、取消和子进程清理门禁；分析不写SQL/历史/任务/媒体。有目标的单Buffer复测每64KiB让出事件循环并重复栅栏

历史备份证据分类器仍只准入旧单片段报告形状，显式排除新增LRA/target/candidate字段，不因共享读协议扩展而放宽旧工作区profile。合法旧报告、历史回执及现有备份分类回归通过

独立审查发现并修复了两处绑定边界：极小正gain不能使用带1绝对底数的误差比较；LRA必须与同一PCM的sample peak精确一致。候选sample peak还绑定实际float32缩放后的最大样本。新增getter/极小值/目标双字段/候选缺失等回归

## 实际验证

[浏览器检查](browser-checks.json)、[8张截图](SCREENS.md)、[原始测试日志和哈希](tests.json)

- 浏览器原测量−28.00 LUFS / −27.06 dBTP / LRA0.00 LU；目标−26 LUFS候选实际测得−26.00 LUFS / −25.06 dBTP，增益调整+2dB
- 默认−14 LUFS因超出现有gain范围拒绝；−20 LUFS / −20 dBTP候选因峰值冲突拒绝；空目标保留原输入、禁用分析，编辑目标清除旧报告且不自动重测
- 匹配前后数据库时间线完全相同（修订7）；保存后修订8，gain从0.5011872336272722变为0.6308545553349859；撤销修订9精确恢复原gain，重做修订10精确恢复新gain
- 保存后重新分析，已达目标的微差不会再次开放匹配；布局变化清除旧候选，不复活旧按钮或自动分析
- 1440×900与1050×680，简体中文/英文、深色/浅色代表状态；无page error，小窗口没有整页越界。长属性区正常内部滚动，固定保存栏可见
- 真实WAV、fade及envelope候选与保存后的FFmpeg音频管线，LUFS/真峰值偏差均小于1e−5dB；重启及一次撤销/重做通过
- LRA有2组真实FFmpeg `ebur128` / `loudnorm`独立对照，动态音频差不超过0.2 LU。实现采用[EBU Tech3342](https://tech.ebu.ch/files/live/sites/tech/files/shared/tech/tech3342.pdf)门限和百分位算法，但明确只取文件内完整窗口，不补首尾静音，不声称EBU模式认证
- 既有60秒完整片段资格检查在Node24.21.0下通过，分析约6.5秒；新增60秒目标候选边界也通过，候选阶段约8.4秒，覆盖23,040,000字节PCM、571个LRA短时窗口、单次实际解码、两次来源hash、子进程退休及零持久写入。未延长120秒操作时限，未据此声称FFmpeg RSS有界

`node scripts/tooling.ts typecheck` 与 `node scripts/tooling.ts build --channel=development` 最终均退出0；开发构建保留现有包体警告。针对性最终检查为契约/客户端/传输25项、后端整合56项、真实保存媒体12项、兼容66项、UI及邻接123项、独立审查15项、最终媒体/应用/Web RPC 21项，两个60秒资格检查各1项，均通过；各组有重叠，不相加为全仓总数

首次类型检查发现测试fixture未声明新target返回类型，已修正；UI整合初次119/120，唯一失败是新增科学单位的文案ledger，已用精确四语言模板修复，未放宽审计；随后微调回归加入后最终123/123
