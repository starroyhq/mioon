## 2. 控制与兼容边界

- `appendText` 的既有事务、文本事件、配额校验及模型请求不可变规则保持；变化仅影响后续流式追加的频率。
- 说明容量仍只计算已经落库的正文；内存缓冲不被预计为已知内容。已有拒绝回执、说明绑定及冻结 intent 不变。
- 已写入正文继续由公开快照和面板流式通道展示。非空缓冲即使不再有 delta，也在当前 250 ms 窗口的截止时写出。定时器、大小条件、正常结束与异常补写共用同一刷写路径，不生成空文本事件。
- 停止选择不补写尚未持久化的缓冲：停止操作已经固定步骤的未知状态和控制回执，返回后不能再追加正文或完成步骤；已持久正文保留。关闭同样清理定时器且不补写。
- 进程中断／关闭丢失尚未写入的缓冲，已持久正文保留。已发请求没有完成回执时仍是未知结果，不能因为缓冲丢失自动重发；继续前仍须明确处置。
- 未发送的 intent 仍直接使用原请求，旧执行记录和恢复副本继续按原规则读取。没有新的持久格式或旧记录迁移。
