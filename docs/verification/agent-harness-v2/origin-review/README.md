审查采用规范与需求两个独立维度，覆盖当前工作区中的未提交新增文件；不使用空的 `origin/main...HEAD` 代替实际代码差异。第一轮完整快照保存在本机临时审查目录，原基线上的审查已因用户修正目标而停止，不计入本轮结果。

| 维度 | 首轮确认的问题 | 修复进展 |
| --- | --- | --- |
| Standards | 当前窗口 owner 身份包含工作区前缀，但恢复占用列表未正确排除；显式解除后控制器未同步失效 | 已修复；统一 owner 身份、关闭旧准入，epoch 阻断迟到读取和 ACK |
| Standards | 非终态显示可用撤销按钮，而服务端仅允许终态撤销 | 已修复；界面和服务端终态准入一致 |
| Spec：执行 | `task.wait` 遗漏抽帧取消终态和图像／抽帧本地结果待恢复状态 | 已修复；取消返回原结果，待恢复状态进入未知结果处置，不驱动 worker |
| Spec：执行 | 无关项目重命名使镜头排序的聚合 CAS 失败 | 已修复；目标修订和完整镜头成员集合不变时使用当前项目 CAS，新增／修改／ABA 仍阻断 |

| Standards：第二轮 | 面板隐藏或往返显示后，旧确认回调仍可解除占用 | 已修复；确认返回时检查当前 view token，已发送请求仍查询原回执 |
