# R5：格式 5 编辑丢响应时不重复执行

- 范围：格式 5 的 `sequence.preview → sequence.commit` 在提交响应丢失时，保留这次已接受的 envelope + planDigest + `envelope.requestId`，标记「结果未确认」，在核对出结论前拒绝新的格式 5 编辑，自动只读核对一次回执；查不到回执时提供「重试」（同一 requestId 重发，服务端按回执重放、不会重复写）与「放弃」。格式 3/4 的路径与响应完全不变。
- 服务端：`packages/business/src/request-outcome.ts` 的只读回执查询新增格式 5 `main.editor_requests`（只有格式 5 的 history schema 有该表，格式 3/4 先查 `main.sqlite_master` 安全跳过）。命中回执按 projectId+requestId 双绑定读取、用 `sequenceEditReceiptSchema` 校验并交叉核对回执内的项目/请求号；`status:'not_applied'` 如实返回未应用及原因码（带 `status`/`code` 字段），坏/超大/跨项目回执一律 `REQUEST_OUTCOME_UNAVAILABLE`（503），不当结论。HTTP 路由仍是非 RPC 的只读项目 HTTP，响应只对格式 5 回执加两个字段。
- 界面：`apps/web/src/edit-ui/lost-response.ts` 是两只会话共用的最小状态机（保留信封、一次有界只读核对、重试/放弃、`onChange` 同步 App 状态）。`Format5EditSession` 与 `BoardUiSession` 在提交结果未知时 retain、挡新写并返回 `EDIT_RESULT_UNCONFIRMED`；明确拒绝（4xx 业务码/`not_applied` 回执）照旧走原错误显示。App 在 `main-stage` 之后渲染 `EditUiUnknownBar`（状态 + 一句原因 + 重试/放弃，无关闭按钮），画板与剪辑两种工作区都可见；切换项目/回首页会丢弃保留信封（无法跨项目核对或重试）。
- 六类动作：主轨、片段属性、轨道经 `Format5EditSession`（`run`/`requestMove`/`confirmCopy`/`runTrack`），画板经 `BoardUiSession`（`run`/`runMany`/`runSubject`）均已接同一状态机；字幕与画幅的会话入口来自在途的 UI-E3/FR-B2 卡，合入后沿同一 `commitPending` 路径自动获得该行为（本次未在本卡复制其 preview 逻辑）。
- 测试：`tests/request-outcome-http.test.ts`（格式 5 回执 applied/not_applied、双绑定、格式 3/4 两字段不变、坏回执 503、HTTP 键集、真实格式 5 项目回执、客户端有界解析）；`tests/edit-ui-session.test.ts` 与 `tests/board-ui-live.test.ts`（丢响应已落盘自动核对、未落盘重试/放弃、明确拒绝、坏响应、读取失败/超时、not_applied；断言实际写次数=1、回执唯一、两次 commit 的 requestId/envelope/digest 相同）；`tests/edit-ui-static.test.ts`（四语言未确认条、无关闭/解释小字）；`tests/ui-components.test.ts`（App 挂载位置两种工作区可见）；`tests/client-mutation-app.test.ts`（重试刷新一次、放弃不写、被挡一句原因）。
- 真实无头流程（本机，非 CI）：`node tests/browser_format5_lost_response.mjs --screens <本卡 screens 目录>`。真实格式 5 内核 + 真实 HTTP project service + 生产 session/notice/未确认条/`createRequestOutcomeClient`；只在浏览器网络层中断 `sequence.commit` 的响应（先转发真实写入再 abort，或先 abort 不转发）。覆盖：已落盘丢响应 → 未确认条 → 回执核对为已应用（history +1、回执 1 条）→ 重试/放弃各一次不重复写。证据 `screens/report.json`（仅本地）。
- 不变项：三套 Mio 请求指纹逐字节不变；`.github/test-timings.json` 未改；回执写路径/表结构/`findSequenceEditReceipt` 的 replay 语义未改；未新增 `*.test.ts` 测试文件。
