# 波纹删除

`timeline.clip.rippleRemove` 删除一个已保存片段，并将**同一轨道**中位于它之后的片段整体前移被删片段的时长。片段之间已有的间隙保留；其他轨道、字幕、素材和源入点不移动。普通 `timeline.clip.remove` 继续在原位置留空。

输入为 `{projectId, expectedRevision, requestId, clipId}`，与普通删除相同，返回完整时间线。使用稳定的 `requestId`；同一请求重放返回原始结果，不会再次前移。HTTP、CLI 和 MCP 共用严格契约，不接受额外 `mode` 字段。

CLI 操作为 `pnpm exec mioon timeline clip rippleRemove --input <JSON>`，MCP 工具名为 `timeline_clip_rippleRemove`。未知结果先用原输入与原键对账，不生成新键自动重试。

一次波纹删除只增加一个时间线版本和一个撤销历史条目，可整体撤销、重做。保留的片段仅修改 `startFrame`，其素材、版本来源、源范围、画面、淡入淡出、音量和自动化曲线保持。所有写入、历史和原始响应在同一个事务中提交。版本冲突、片段不属于项目、前移后重叠或保留字幕超出新的时间线结束帧都会拒绝整次操作；不会自动裁剪或移动字幕。

普通44/恢复45是波纹删除的独立 profile：44直接继承40，不经过 opacity 候选42。迁移只扩展编辑任务的操作 CHECK，保留任务原始输入字节、位置、序列高水位、索引与触发器。旧40备份继续由原固定 catalog 恢复为41，旧恢复目录不会自动改写为45，因而旧恢复 profile 不提供波纹删除。

opacity 与波纹删除的组合使用**显式候选46/47**：只有应用内部显式入口可以创建或重开。原42/43入口、catalog 和备份协议保持独立；普通启动和普通备份入口不会据更大的版本号取得 opacity 能力。新46备份仅通过对应候选入口恢复为47，继承的请求、任务和未知结果仍被隔离，新的本地操作须携带恢复工作区 origin。

前端入口为片段“更多”菜单的“波纹删除”和 ⇧⌫；普通删除使用 ⌫。确认信息显示前移帧数。输入框、输入法、弹窗以及未保存或待确认的编辑仍遵循既有快捷键与请求保护。
