## 1. 优先顺序与产品边界

原定先[项目首页](PROJECT-HOME-PLAN.zh-CN.md)，再实时音频预览与统一响度，当前进展见上方。
后续按下面三层逐步交付，
不是一次性重建专业音频工作站或完整影视后期软件，也不是固定日期承诺：

1. **可听见、可检查、可明确应用的声音。** 真正的时间线实时混音预览，
   本地响度与 true-peak 分析，先区分素材/对白响度匹配和整片目标响度，
   再交付可试听、可审核、可撤销的应用流程。
2. **常用声音编辑与画面处理。** 人声/音乐/音效角色、音量关键帧、交叉淡化、
   可编辑 ducking、明确启用的 limiter、基础 EQ/降噪；画面先位置/缩放/
   透明度动画及渐显渐隐/叠化，再裁切/旋转/曝光/对比度/饱和度/模糊。
3. **内容生产与高级效果。** TTS、录音、音效生成及可替换平台的素材返回；
   文字动效、蒙版跟踪、抠像和高级合成。逐项核对实现代价、权限及平台能力，
   不因写入路线图自动启用外部服务、上传素材或发生费用。

继续本地优先，复用共享 UI/API/CLI/MCP 业务服务。用户维护的界面和已有使用流程
应保留；后续 UI 设计从具体任务出发，与音频处理能力分开验收。本计划不新增内置
Agent 的执行权限；外部 MCP 能力与内置 Agent 的有限审核工具不可混为一谈。

## 3. 第一层：实时音频预览与统一响度

### 3.1 实时预览是时间线混音

首片先覆盖已有音频语义：源入点/时长、播放头、跨轨重叠、视频内嵌音频、
片段 gain、轨道 mute、clip-local fades。用户编辑后能够试听这些效果，
不必每次生成完整预览 MP4。普通 HTML 源视频/音频播放只能标记为源素材试听；
多个播放器同时启动也不能直接算通过同步混音验收。

- 先定义共用的、版本化的效果参数、处理顺序、时间线时钟、源采样映射和快照。
  现有编辑仍为 30fps，音频渲染为 48kHz；新增实时引擎不偷偷改变时间线时基。
  播放范围、源偏移、fade 和未来自动化必须有同一组明确的半开区间语义。
- 实时和离线渲染的实现可以不同，但必须消费同一效果规范与冻结快照。
  不要求不同平台解码器逐字节相同；先定义容差、不可比情况及可复现的参考输出。
- 明确“已保存时间线”与“仅试听未保存候选”。候选试听有可见标记、随时返回原版，
  不写业务状态，也不冒充已经保存/导出的结果。旧播放快照不得吞掉新草稿。
- 定义播放、暂停、seek、重复 seek、循环区间、切项目、设备变化、后台隐藏、
  解码取消及迟到回调的所有权。缓冲不足应显示具体状态，不能静默漏播或错时。
  首片可显式拒绝未覆盖的循环/设备情形，不能把它们隐含标成支持。
- 解码、缓存、内存与并发设有容量和取消边界；不在项目打开、查看波形或读取
  API 时无条件启动整片重算。硬件不足应降低明确的预览能力或给出限制，
  不静默改变输出效果。

验收至少使用可知 PCM、44.1/48kHz 源、单/双声道、相位相反声道、静音和视频原声，
覆盖 seek 前后、源裁切、fade 中途、其他轨片段边界、多轨重叠、gain/mute、
隐藏视频仍发声及连续多次播放。对比共用效果规范下的实际实时混音输出与离线
PCM，并分别测量时序偏差、幅度差异、缓冲/延迟、长时间漂移；不能只看截图或
仅凭源播放器发声。原生听音与数值/时钟证据分别记录。

### 3.2 “统一响度”分为两种任务

**素材/对白听感匹配：** 选择若干片段或明确角色，让不同录音/对白段落的听感
更一致。首片分析对象建议为各片段的明确源入点/时长、已保存 gain/fades 后的
独立信号，不混入其他轨道；分析报告必须显示实际处理阶段。原始源分析若另行
提供，应使用不同标签。算法只能提供可审核建议，不能承诺同一数值等于完全相同
的主观听感；不同音乐/对白/音效不能默认一律拉到同一值。

**整片目标响度：** 对已经混好的完整时间线或明确选区，根据用户选择的交付
配置分析，再生成整片调整候选。选区测量不能冒充全片测量；混音后整片目标
也不能替代片段之间的对白匹配。

这两种任务都不等于 peak normalization，不是把所有素材设置成相同 gain，
也不是默认接入实时压缩器。第一版先落实测量能力、命名配置与审核方案；
不在本文武断规定统一 LUFS 或 true-peak 数值。引入精确标准/目标值前需核对
官方标准或目标交付方的规范，记录测量算法版本、门限/门控规则、测量范围、
单位、true-peak 方法及误差边界，并用确定性音频与受认可参考结果交叉验证。

### 3.3 分析只读，应用是明确编辑

采用“选择范围与目的 → 显式分析 → 检查报告/候选 → A/B 试听 → 确认应用 →
重新测量”的流程。每一步状态清楚，不能因为打开项目、完成导出或模型建议而
自动执行后面的步骤。

1. **只读分析。** 不改片段、轨道、任务、历史、原媒体或导出文件；本地解码属于
   有成本的观察操作，要公开资源上限与取消语义。若未来保存派生报告，必须独立
   声明缓存效果、容量及失效规则，不能继续声称严格零写入。
2. **绑定依据。** 报告与候选至少绑定 project/timeline/revision、明确片段/轨道集、
   完整或半开选区、源 asset ID 与 SHA-256、当前效果链/顺序/参数、测量阶段、
   算法/配置版本和快照摘要。源、目标、范围或编辑变化后视为过期，必须重新核对。
   不能只凭文件名、当前选中行或相似项目名称应用旧结果。
3. **候选不是修改。** 显示测量值、目标、预计改变量、改前/改后绝对参数、
   峰值与余量风险、将加入的任何新效果，以及未覆盖的听感限制。
   首片优先生成明确 gain 候选；当前 0–2 范围无法表达时要拒绝或提示后续能力，
   不静默截断、不偷偷拓宽历史参数范围。未来 master gain/limiter 需独立设计契约。
4. **批量审核。** 展示逐条候选与跳过原因，允许取消选择、逐条试听和整组试听。
   确认必须绑定确切候选集合与值；首片按一次原子编辑应用整组通过项，任一已批准
   目标过期则整组不落地。若以后允许部分应用，必须先展示并批准确切子集，
   不能后台悄悄跳过失败项。
5. **应用与复核。** 应用是有 timeline CAS、稳定 requestId、确切输入摘要和
   undo/redo 的 mutation。保留原媒体和旧快照；撤销应恢复原参数与效果顺序。
   提交丢失 ACK 或进程中断后保留原请求，只能明确对账/重放，不新造一批调整。
   预估不是验收，应用后重新测量实际混音/输出，报告是否达到所选目标及限制。

### 3.4 异常、余量与峰值冲突

- 静音、无有效样本、非有限值、坏音频、不完整解码、未知通道布局分别给出状态。
  静音不计算无限补偿，不把错误当作零响度；不能对坏音频生成可应用的调整。
- 极短片段、只有瞬态/停顿的片段或有效信号不足时，应提示测量不足，保留原值；
  所选测量配置需定义有效性，不用任意大增益填补不可靠估计。
- 静音轨/零增益片段默认排除可听混音目标，不自动解除静音。若用户明确分析源，
  显示“源分析”并保留独立范围，不能把源结果直接冒充当前混音结果。
- 强提升、已削波素材、明显噪声或很小余量要提示风险。单片段不超峰值不代表
  多轨叠加后安全；每个整组候选都需要重新检查对应混音快照。
- 响度目标与峰值/余量约束冲突时，明确显示无法仅靠 gain 同时满足。
  可建议降低目标、手动调整混音，或在后续具备能力时单独审核启用 limiter；
  不能偷偷压缩、限幅、修改目标或宣称已经达标。limiter 不是降噪或恢复源削波。
- 保留“编码前测量”和“实际输出解码后测量”的区别。即使前者通过，AAC 重建或
  播放端仍可能有不同峰值；测量/处理选择及未验证范围应随交付报告保留。

验收覆盖静音、极短语音、片段间响度差、低电平强提升、噪声、瞬态、已削波源、
多轨叠加过载、目标与峰值冲突、混合角色、选区/全片差异、应用/撤销/重做、
批量冲突、丢失 ACK、重开恢复和原文件不变。每种支持的配置都要验证测量与应用，
不拿峰值测试、通过的原生 UI 截图或一个示例代替响度算法验收。

## 4. 第二层：常用音频编辑与画面处理

### 4.1 音频

- 人声/音乐/音效角色先作为可见、可编辑的分类；角色不能在赋值时自动改音量。
  后续角色路由/总线、整片处理要显式定义，避免分类隐含改变旧混音。
- 音量关键帧定义点时间、插值、端点、源裁切/移动/分割后的保持规则，以及与
  现有 gain/fades 的相乘或替代顺序。不能通过加入默认字段改写旧快照/回执。
- 专用 crossfade 定义两个参与片段、持续时间、曲线和重叠语义；当前同轨禁止重叠，
  需要明确是跨轨方案还是受限模型扩展。不要把已有两个独立 fade 控件重新包装
  成已具备完整交叉淡化。用实际 PCM 验证衔接及多轨交界，不只画出曲线。
- Ducking 输出可查看、可改、可撤销的音量包络，明确检测人声来源、触发区间与
  作用目标，不自动把全项目媒体发送给模型。改动人声/范围后旧候选失效。
- Limiter、基础 EQ、降噪各自限定参数、算法版本、处理顺序和可用平台；
  候选试听与最终处理共用参数。分析结果不能自动启用处理，自动标准化也不得
  默认串入压缩/降噪。CPU/延迟、音质损伤和不支持情形需单独验收。

### 4.2 画面

按依赖小步做，避免先建无限效果框架：

1. 在已有静态 rect/分层之上定义位置、缩放、透明度关键帧，先配有限插值与
   渐显渐隐/叠化。转场必须绑定确切两个片段/版本和时间范围。
2. 再做裁切、旋转、曝光、对比度、饱和度、模糊。先明确 SDR/色彩元数据与
   预览/导出一致性；HDR/log 不支持时显式提示，不能把颜色改变当作兼容转换。
3. 文字动效、蒙版跟踪、抠像和高级合成移到第三层，分别定义素材、坐标、
   跟踪失效、遮挡与版本返回。AI 重绘与确定性合成提供清楚区分，
   不承诺未验证的像素不变、主体锁定或精确身份保持。

所有画面效果需冻结版本化参数、渲染顺序、画布/时间坐标与源身份，保留原素材。
先检查起止帧、叠加/转场边界、选区导出、subtitle 时序、撤销重做、旧快照复现与
真实成片解码/像素对比，再宣称 UI 和导出一致。FFmpeg 存在某个滤镜不等于产品
已支持它。变速、更多字幕导入格式和任意效果脚本仍须单独限定具体交付范围。

## 5. 第三层：生成、录音和高级合成

- TTS、录音、音效生成是后期能力，不是当前功能。录音需明确设备与麦克风权限、
  起止/取消、故障保留和结果导入；不能在后台默认采集。
- 生成来源可替换平台；用户审核的素材、文本、服务商/模型和费用范围固定。
  保存配置不等于发起生成，失败不自动换服务商或重发，未知结果走原请求对账。
  用户批准排期不等于批准某次外部上传、凭据配置、软件安装或付费调用。
- 结果作为受管理的音频资产/不可变版本返回，保留来源、所选模型与明确授权范围；
  与普通导入素材共用编辑链。新版本不自动替换时间线，更换平台不破坏旧项目。
  如涉及真实人物声音或复制声音，另行确认权利、同意与产品边界。
- 文字动效、蒙版/跟踪、抠像和高级合成优先复用受限本地处理或受审核的外部结果
  返回。需要第三方执行时沿用[扩展架构](EXTENSIONS-ARCHITECTURE.md)的隔离与
  能力边界；不直接接受任意脚本/滤镜作为可信项目参数。
