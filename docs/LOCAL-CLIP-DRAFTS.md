## 覆盖的入口

右侧“时间线片段”属性表单：名称、轨道、开始帧、持续帧、源入点、矩形、音量和已有音频淡入/淡出字段。保存原始输入字符串，包括未填完的数字；仅用户明确“保存片段”时才转换并走原 `timeline.clip.update` 验证、CAS、历史和持久编辑任务。

镜头提示词、成片名称、字幕、生成输入、Agent 输入以及桌面最近项目定位不在本片。恢复分支本片保留原有本地编辑能力，但明确显示自动草稿暂不可用。

## 存储与权限

- 普通工作区的固定私有旁文件 `local-drafts-v1.json`，格式版本独立于业务 SQLite。既有 schema24 和恢复 schema25 不迁移、不增加业务回执字段。
- 每个项目/时间线/片段一个槽；最多128个槽（包括清除后的版本墓碑），每槽最多8KiB、完整文件最多2MiB。达到容量上限明确拒绝保存，不自动淘汰旧身份；首片尚未提供压缩历史槽功能。
- 复用既有私有目录、文件身份、symlink 拒绝和有界原子写入。仅实际持有工作区锁的后端可写，同步服务调用串行 CAS；这不是另一个跨进程分布式锁。
- 稳定作用域绑定实际工作区目录/SQLite 文件身份和可信渠道。端口变化不改变作用域，复制旁文件到其他工作区不会自动导入。开发/生产默认工作区分离，浏览器来源不是唯一身份。
- 文件内容是本地明文用户数据，不是密钥保险库。严格白名单不含认证、连接令牌、配置、任意路径或媒体；用户自己在片段名里写的敏感文本仍会成为私密草稿。
- 已有离线备份只捕获固定业务库和受支持媒体/暂存目录；本片草稿旁文件不包含在备份中，也不改变原备份/恢复格式。不能把工作区备份说成草稿备份。
- GET/列表只读且不创建文件；损坏、不安全权限、换身份或不可读不被当成空记录重置。写入 fsync/原子发布及父目录确认的具体故障由测试区分；不承诺突然断电、坏硬件或崩溃前最后一个按键绝不丢失。

## 恢复与业务保存

重开后读取可恢复草稿，用户明确恢复到表单后才出现待编辑值。读取、恢复提示、切换页签和恢复到表单本身都不提交业务、模型、上传或渲染。

恢复保留原时间线 revision 和固定素材/版本来源；当前数据已改变时显示冲突，不自动刷新基线。仍有未确认的业务请求时先到任务中心核对原编号，不从草稿制造“重试”的新编号。已有持久编辑任务负责原请求身份，草稿不代替该台账。

确认应用后只能清除对应的精确草稿 revision，且需与该次提交内容、目标、来源及当前所有者一致。新输入、另一窗口、项目导航或迟到回应不能清掉较新草稿。显式“放弃修改”使用同样的条件清除；清除失败不伪装成功并丢弃输入。

## 保存异常与安全退出

草稿请求失败后，本次表单的自动草稿写入暂停。界面区分服务明确拒绝（例如128槽已满）、版本/服务实例冲突，以及网络或确认无效导致的未知结果。后续“重新核对本地草稿”只读取记录，不会自动重新PUT；一次空记录不能证明较早的未知写入不会稍后完成。先前未知状态不会被随后拒绝或空GET清除。

用户可明确确认“放弃当前输入，保留草稿记录”：只重置当前属性表单，既有或仍在写入的本地记录保持原状，之后可能再次出现。它不会DELETE草稿、取消业务任务或清除原请求身份。确认期间的新输入、项目/片段切换及晚到回应不能作用于新表单。已进入业务保存或任务仍未确认时，此退出动作不可用，仍需核对原任务；如果业务保存尚只在等待本地草稿PUT，则可退出并阻止之后交给业务保存。

原“放弃已保存草稿”仍是独立的精确版本DELETE。暂停不会因只读核对、重新联网、继续输入或视图刷新而自行恢复写入；重新打开该入口后重新读取记录并按当前状态处理。没有承诺清除128槽的保留版本，达到上限时仍可用原明确业务保存流程，自动草稿容量扩展/压缩另行实施。

## 接口与范围

草稿使用已认证的独立本地 HTTP 边界和同一个后端业务模块；不是任意业务执行器，也没有加入公共 RPC、CLI/MCP 工具目录或内置 Agent 目录。所有写操作绑定后端返回的作用域与本次服务实例，旧实例请求需重新只读发现，不能盲目重试。

- `GET /api/local-drafts/clip?projectId=…&timelineId=…&clipId=…`
- `PUT /api/local-drafts/clip`：精确键、作用域/实例、expectedRevision、原 baseRevision、来源与字段白名单。
- `DELETE /api/local-drafts/clip`：精确键、作用域/实例与 expectedRevision。
- `GET /api/local-drafts?projectId=…`：有界项目内发现，不自动选择或恢复。

具体字段与边界以 `packages/contracts/src/local-drafts.ts` 的严格运行时 schema 为准；调用端不能用草稿字段指定路径、其他服务操作或授权。

## 关闭保存与有界客户端：后续可靠性收口

本节基线 `e74130ccabb3d4adf8e88f37ef4d6bcfc8b40148`，不改写上面第一片的历史结果。既有片段草稿曾仅依赖 250ms 定时保存，App 的关闭/隐藏保存未纳入该控制器；客户端等待响应也没有独立期限和流式载荷上限。本次只补这两个已核缺口与退出提示，不新增草稿字段、数据库结构、公共操作或通用草稿引擎。

- 正常桌面关闭会通过既有固定生命周期函数，立即尝试保存当前片段的本地草稿并等待确认；只写草稿，不点击业务“保存”、不改时间线、不自动重交旧请求。隐藏/pagehide/beforeunload 也请求刷新尚未持久化输入，但浏览器卸载并不保证等待完成。
- 原 `flush(): Promise<void>` 保持兼容；新增关闭专用布尔确认，按当前 owner/serial/raw/baseRevision/source 复核。一个旧 PUT 在途时最多接续一个合法的下一 CAS，之后的新输入回到正常去抖，不在关闭循环里无限追写。并发关闭合流；已确认旁文件不等于已保存到时间线，原未保存业务确认仍在。
- dirty 且未知、冲突、容量拒绝、未完成 GET 核对、正在删除或 owner 已变时不能返回“已确认”。其他面板保存等待期间的新输入或新的持久化不确定状态，App 还会在所有等待结束后再次复核。明确“放弃当前输入，保留草稿记录”仍可安全离开，不要求删除历史未知身份。

- 期限只取消本次 HTTP 等待与响应读取，**不取消后端保存/删除，也不证明未写入**。空 GET 不撤销未知 PUT，迟到 ACK 不解锁、更不产生第二次 PUT；原业务请求 ID 和 CAS 没有改变。真实 client 与 controller 组合因果测试覆盖超时→空读取→原 PUT 仍晚提交。

## 后端发布与保存确认护栏补齐（2026-10-13）

本轮开发基线为 `41151bafa7291f7a44272598a9f24df9ba7c332b`。仅修改片段草稿的后端发布/确认边界，界面由用户维护，本轮不修改 UI、表单、退出交互或客户端权限。前述 2026-10-12 原生结果仍属于其当时版本，不当作本轮重新执行。

只读审查发现：较早的片段草稿实现弱于后续最近项目、成片名称和镜头文字旁文件。它在 `beforePersist` 后没有完整复查，在父目录同步后和响应组装完成前也缺少最终检查；打开的父目录描述符未核对身份。受控注入曾使已撤销 owner 或已 abort 的请求仍返回成功保存 ACK。该证据是同步边界注入，不证明普通退出会在同一同步 JavaScript 调用中间执行，也不代表已观测真实用户数据损失。

现在的行为：

- 发布前重新检查服务中止状态、实际工作区锁与固定工作区身份；身份读取期间失去锁同样拒绝。确认在发布前拒绝时不创建或改写草稿，保留原错误类别。
- 父目录打开后核对实际 fd 的目录类型、dev/ino、当前用户及私有权限，再进行 fsync；所有路径关闭该 fd，不修复权限、不删除或替换未知文件。
- 发布后、父目录确认前后，以及历史来源/目标/响应组装之后，再复核 owner、abort 和作用域。已发布后无法完成这些证明，统一保持 `LOCAL_DRAFT_SAVE_UNCERTAIN`。这不是回滚或“保存失败且未写入”的证明。
- 识别为原精确 PUT/DELETE 重放后，使用同一保存确认边界；确认失败不能返回成功，也不会重写槽、增加 revision 或制造新业务请求。先重新读取原草稿，再按原 revision/input 明确处理。
- 原文件格式、稳定身份算法、raw 文本、128 槽/2MiB 上限、CAS、清除墓碑、来源检查和精确匹配规则保持。没有迁移、新台账、自动重试、通用旁文件引擎或其他三个旁文件的行为改动。

这是既有单工作区 owner 契约的补强。同步调用仍依赖独占后端；检查不能消除所有路径式文件系统 TOCTOU，也不把同一操作系统用户的恶意进程列入 ACL 隔离保证。突然断电、硬件故障和原生平台仍有原先边界。
