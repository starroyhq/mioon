# 生成服务设置基础模块

本 PR 为 G1a 提供独立的 v2 设置契约和私有持久化模块。现有应用启动、HTTP、client、CLI、MCP 和设置页面尚未接入，生产入口继续使用现有格式。这一阶段不修改项目结构、history、固定 Mio 工具 schema 或请求指纹。

## 视频设置

v2 将当前内置视频服务限制为每家一份，自定义服务可有多份。连接用启用开关，模型仍可归档。每个连接拥有自己的稳定身份、配置修订和密钥接收者；同公司、同地址或同模型不共享密钥。

换区域或自定义地址只断开该连接当前使用的密钥引用，原有历史引用继续供已经冻结的任务使用。显式删除自定义服务则删除该连接的配置、历史凭据和会话材料，只留下不可复用的 UUID。冻结执行绑定及视频密钥包装仍使用原来的 v1 协议和命名空间，不把保存设置当作生成授权。

v2 不提供历史密钥恢复动作。已保存的持久密钥仍可按原引用取得；仅本次运行的密钥在应用退出后消失，普通保存产生的新引用不能代替旧任务的引用。后续页面接入必须在该选项旁显示：“应用退出后，正在进行的生成没法继续查询结果。”

## 自定义图片设置

v2 将单槽改成按 UUID 区分的集合。集合修订用于保存和增删的比较后写入；单项配置修订用于准备、确认和派发的精确核对。改 B 不会把 A 的密钥或批准转给 B，同模型的两个服务仍是两份独立配置。

密钥绑定包含该项身份、独立命名空间、完整规范化地址、模型和固定输出选项。仅本次运行的密钥只在对应模块的内存中，持久文件只保存密文。删除清掉该项全部密钥材料并保留 UUID 墓碑，不能靠重建同名服务恢复旧批准。

官方图片和本机 ComfyUI 的格式不变。自定义图片仍是既有的固定 JSON/PNG 能力，不增加图片编辑、探测或供应商协议。

## 文件和生命周期

严格验证通过的旧视频 v1 或自定义图片 v1 只在内存中呈现为空 v2，并携带供页面一次性显示的安全提示。读取不写盘、不解密旧密钥，也不把旧连接映射到新身份；第一次明确保存才写 v2。

不安全路径、损坏文件或未知版本保持拒绝，不能仅按版本号清空。旧文件在读取后被替换或修改时，首次保存应拒绝覆盖。私有文件继续沿用受限路径、有界读取和原子写入。

修改操作受串行比较后写入约束；一批修改只保存一次。等待密钥存储、保存或关闭期间仍要核对所属实例和配置。保存失败或结果未知时不能自动重放，不能把部分成功说成整批完成。

## 后续接入顺序

G1a 激活另行接入网页 HTTP 和 client，以及设置改名和入口调整。多个自定义图片服务通过显式连接 ID 准备审核；旧无 ID 入口只在恰好一家时精确解析，多家时固定拒绝。CLI/MCP 新操作和 Mio 显式选择多服务留到 0.1.x，两套既有请求指纹保持不变。

图片审核的新严格分支需要 history 10。V5 的 history 8 和 S8 的 history 9 合入后，先合入最新 main，再冻结真实旧结构并实施窄升级。本基础 PR 没有提前增加 CHECK 或迁移入口。

三段式页面属于 G1b，等待 G1a 和 X6a 合入，复用 X6a 唯一的中间栏、详情区和底栏组件。
