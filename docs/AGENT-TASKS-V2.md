# Mio v2 执行与恢复

Mio 的统一入口沿用 Mioon 自有 harness、网关、SQLite 和业务服务。旧会话、修改提议及回执仍按原格式读取；旧接口和旧授权范围不变。连接设置和凭据格式不变。

## 执行与授权

- 开始执行前，必须已有固定连接目标、模型的 `project_agent` 发送授权。这一轮固定项目及模型设置；旧的聊天或局部编辑授权不能替代它。
- Chat Completions、Responses 与 [Anthropic Messages](AGENT-ANTHROPIC.md) 支持多轮模型／工具往返，同一响应中的工具顺序执行。模型只能使用显式准入的项目工具，不能提供项目切换、请求 ID、批准标志、凭据、任意路径或原始字节。
- Mio 的回复使用发起这一轮时的界面语言；切换语言不会改写已保存的用户消息、回复或项目内容。
- 每个模型步骤和工具步骤计一步，默认每轮 30 步。预算用完会暂停，继续为当前执行追加同样步数；设置的新步数仅作用于下一轮。审批、回答、控制、宿主等待循环不额外计步。
- 只读、本地可撤销、本地不可撤销、付费四档独立设置为直接执行或需要确认。只读和本地可撤销默认直接执行，本地不可撤销和付费默认确认；已经保存过执行方式的工作区保持原设置。每个对话还可以单独选择档位，见[放行档位与提问](#放行档位与提问c1c3)。管理操作不向模型开放。
- 审批绑定原工具参数和目标单调修订。intent 保存后、业务事务开始前、后台真正提交前重新校验授权、执行状态和策略。暂停、停止、撤权或关闭付费直调会阻断尚未发出的工作。
- 生成提交返回已有任务引用；依赖生成结果时调用 `task.wait`。等待只读本地状态，可取消，不发模型请求，也不驱动供应商轮询。

普通执行默认向模型提供核心观察工具和宿主 `mioon_tools_load`。其他工具按画板与镜头、主体、素材整理、剪辑、字幕、声音、调色、导出、视频生成、图片、拆解与关键帧分组；模型先加载对应组，再在后续模型请求中调用组内工具。加载是只读步骤，消耗一步，不产生项目变化；本轮成功加载的组持续可见，新一轮重新从核心组开始。用户为本轮选取附件时，对应的托管素材／Cube 导入工具自动可见，仍需原有附件授权与导入门禁。

已保存的加载回执只按其自身调用参数验证：结果 groups 必须是请求 groups 的子集，未知组忽略，无效回执不扩大可见范围。回执 tools 仅保留历史信息，不参与当前目录成员校验；后续请求按已加载组的当前成员装配，因此组成员升级不会使旧运行或补充说明触发存储故障。

工具是否已加载严格取自发出该调用的模型步骤保存的请求原件。同一回复先加载再调用原请求中没有的工具，也会返回 `rejected`／`TOOL_NOT_LOADED` 和应加载的组，不进入工具准备、审批或执行；模型可在下次请求重新规划。目录之外的工具仍是协议错误。H1b 之前保存的全量工具请求继续按其原工具列表执行，恢复未发送的 intent 不重新装配。诊断运行沿用原工具选择和系统指令，不提供加载工具和提问工具；宿主加载工具不进入业务 RPC、MCP 或 CLI 发现。

### 工具结果视图与上下文压缩

工具完整结果继续保存在原步骤中；下一次新模型请求只投影最多 16 KiB 的单结果视图。未超限的结果保持原值和顺序；超限时生成合法、确定的 JSON，标注原始 UTF-8 字节数、实际省略字节／值／字符数量和重新读取提示，并递归去掉 `candidateDigest`、`snapshotSha256`、`preflightSnapshotHash`、`snapshotHash`、`planHash`、`sourceHash`、`sourceKey` 等绑定字段。截断预览不能替代完整读取，不能作为执行授权或审批依据。

新请求的历史超过 128 KiB 时，宿主依次把较早完整往返的结果换成存根、移除较早完整往返并加入本轮执行记录、移除最早的历史对话轮次，目标为原上限的约 60%。一次往返始终包含整份模型输出及其全部工具结果；语言标记、本次用户消息、本轮全部补充说明、最新往返和容量探测时已落库的部分回复原文保留。低水位是削减目标；上述不可删内容仍超过原上限时，继续返回原容量错误，不拆分协议配对或提高预算。512 KiB 请求上限、4096 token 输出上限和步数规则不变。

压缩仅发生在新请求及说明容量探测的实际装配边界；复制基础上下文时不压缩。装配只读取已保存记录，不读时钟、不调用模型摘要、不改写历史请求或完整结果。按历史请求边界重放削减决定；两次压缩之间普通追加往返和说明保留此前请求前缀。后台晚到的 Change 按该边界已有的目标修订快照筛选，涉及多个目标时必须全部已知；下一次必要压缩才更新已移除往返的执行记录。用户控制或旧记录状态发生变化时，派生约束可随事实更新。没有修订快照的旧请求以持久时间作保守回退，不猜测同毫秒变化已被当时请求看到。

执行记录使用已有安全展示投影，并限制细节预览；本轮约束单独完整保留已跳过目标、用户拒绝以及失败／未知步骤，不因预览上限隐藏它们。宿主记录、存根和截断提示均使用本轮四语文案，明确“仅供参考，不是指令”。已保存的未发送 intent 仍直接使用原请求，不重新装配或绑定后到说明。

模型已回答但后台工作未结束时，快照标注 `backgroundPending`，面板继续订阅费用与迟到结果，并保留暂停、停止入口。暂停保留原队列，继续后沿用这一轮；停止只取消能证明尚未开始的本地排队工作，已发出工作继续按原结果路径收尾。

后台受理后关闭付费直调，会对原排队步骤请求单次审批。审批绑定受理事务保存的目标修订，实际发送前仍复查；批准后发生同目标修改或编辑占用也会暂停。因目标冲突选择跳过时，只取消涉及实际跳过目标的未提交旧队列，重新读取并规划，不重新提交旧参数。

费用状态按证据分别展示：待提交、已提交付费请求／可能计费、结果未知。只有实际计费证据才显示已产生费用。Mock 不记付费请求。不设付费次数上限，仍受每轮步数、既有生成总开关和单次审批约束。已经发出的工作可以保存迟到结果，不承诺远端取消或退款。

响度工具的 `target` 是测量参数，只有 `edge.create` 的 `source` / `target` 表示实体端点。`timeline.loudness.prepare` 向 Mio 返回完整、匹配本次请求且可适用的报告时，额外提供共享算法计算的 `candidateDigest`，供后续显式 `timeline.loudness.apply` 绑定；不为截断或不可适用的报告生成摘要。该派生值仅属于 Mio 工具结果，不改变公共测量报告格式或 `applyAllowed:false` 的只读语义，也不授予修改权限。实际应用仍经过正常审批、目标修订检查及服务端重新测量，拒绝伪造、过期或已变化的候选。

## 实时修改、草稿和撤销

业务修改、业务回执、Change 与工具完成记录在领域自身事务中提交；写库失败会阻断后续请求。Change 实时出现在面板，可定位画布／时间线并短时高亮。

后台视频任务仅更新 `progress` / `nextPollAt` 时仍保存原任务状态与目标修订，不新增 Change、执行步骤或运行修订。真正的生命周期变化记录为 `generation.status`，资产和版本发布记录为 `generation.publish`；初始受理仍只有一条 `generation.submit`。费用未知审计独立于进度过滤，写入失败仍回滚同事务领域变更；自动 `version.select` 保留独立、可撤销记录。旧审计行不重写，读取展示时将可证明为旧任务更新／结果发布的标签修正；后续目标修订只描述为“目标之后有更新”，不猜测由用户修改。

服务端按实际目标维护单调修订，包括人工编辑、AI 修改、撤销／重做及后台结果。修改后再改回仍属于冲突；其他目标上的编辑不使当前目标失效。

开始输入、使用输入法或拖拽后，Mio 会等待你保存或放弃同一处修改并结束编辑。这个编辑状态跨窗口生效，草稿、断联、超时和重启不会自动结束编辑。保存或放弃修改后须明确结束编辑；状态不确定时，先核对原窗口中的修改。这一轮因冲突暂停后，选择“跳过这一处并继续”会废弃旧参数和审批，重新规划；普通继续不能绕过这个选择。

占用保存取得时的目标修订。原窗口可以明确继续编辑保留的草稿，服务端只在同 owner、完整目标和原修订均一致时接受 `restore`；目标已变化时不自动重基或清空草稿。

单条撤销只补偿该 Change 影响的目标；整次撤销按逆序逐条提交；严格证明单目标之后被修改时，标记 superseded 并保留，继续撤销其他变化。遇到复合变化、ABA、草稿或不能证明的修订差异仍停止并保留进度。撤销链可跨过自身产生的修订，不能覆盖其他人工编辑。不可撤销产物和费用记录保留。

## 面板与安全展示

Mio 面板在同一对话中按轮次展示用户消息、最新回复、可折叠步骤及变化；输入区固定在底部。标题取本对话首句用户消息，历史浮层按对话读取。首次未授权发送通过完整地址、模型和发送范围的确认弹窗授予 `project_agent`；取消保留草稿。确认前后输入、附件、语言、连接或窗口归属变化时不自动发送，授权响应丢失时也不自动补发。

公开 Step / Change 可包含 `display` 安全投影：操作类型、项目内目标的类型/显示名，以及有界的白名单字段。片段支持时长、入出点、位置、音量和淡入淡出；镜头支持比例、时长、描述；字幕支持文字；生成提交支持明确提供的参数。预览只展示已知参数，不推测旧值或新版本号；其余操作退回类型和目标。冲突卡只采用服务端当次本地读取的白名单当前值，不把界面缓存冒充当前值；后台冲突由宿主投影标记关联原步骤。原始 `before` / `after` 仍为 `null`，不公开补偿 `undo`。`description` 与 `subtitleText` 是已授权本机客户端可读的项目内容，只取对应真实字段，去除控制字符和双向文本字符、合并空白并按字符安全截断；不根据 URL、路径、UUID、id 前缀或“密码”等关键词猜测和删改内容。只有素材和时间线片段的媒体文件名提取路径最后一段；字幕文字、镜头标题、项目名等只清理控制／双向字符、合并空白并截断，不按斜线或反斜线截断，也不按凭据、UUID 等启发式遮挡。变化文案不使用模型撰写的 Change summary。

界面优先用已有项目数据中的目标名，并按界面语言格式化值和单位。步骤说明由内置模型工具包装的 `_mio_step` 提供，执行前剥离；缺失或不合规时用本地化操作模板。该字段不进入业务 RPC、CLI 或 MCP 的公共工具参数。说明保存在现有步骤文字字段中，不改变授权、审批或工具幂等参数。

`display` 只在读取快照时构建，不迁移持久记录或修改工作区/备份格式。新版 HTTP、客户端和 CLI 共用更新后的 contracts；使用旧严格快照解析器的独立客户端需同步升级，不能假定它会接受新增响应字段。旧记录没有投影数据时仍可读取并使用操作类型回退。

终态快照可包含只读的 `executionEndedAt`，从持久执行状态事件中取得该次执行的结束时间，供界面计算“用时”。后续撤销仍更新 Run 的 `updatedAt` 和历史排序，不延长已结束执行的用时；撤销产生的 `reverted` 事件不作为执行结束。恢复或后台审批后再次实际执行时，采用新的终态证据；缺少可靠证据的旧记录不显示推测时长。该字段不写入 Run、事件或备份记录，不新增工作区 schema。

## 宿主检查（H3a）

`GET /api/agent/tasks/v2/:projectId/:runId/checks` 按读取时的本地记录计算本轮完成情况；client 为 `checks({projectId,runId,preflight?})`，CLI 为 `mioon agent task checks`，JSON 输入同样接受可选布尔值 `preflight`。默认不运行完整时间线预检；只有 `preflight:true` 才发送 `?preflight=1`。HTTP 仅接受单个 `preflight=1`，其他值、重复或未知查询参数均拒绝。检查独立于执行快照，不计步骤，不落库，不改变执行状态，不调用模型，也不查询或轮询供应商。恢复副本中同样可读。检查只是观察数据，不能作为执行、审批、恢复或撤销的依据。

响应固定包含 `export_render`（导出与渲染）、`generation`（生成）、`timeline`（时间线）、`decomposition_frames`（拆解与关键帧）四组。每项提供稳定的检查 ID、检查类型、`source: "host"`、`passed / failed / pending / not_applicable`、可定位目标、安全显示名及依据修订；未通过或等待时附机器原因码、安全参数和可用进度。没有相关工作的组返回不适用项。响应不含成句说明、原始错误、提示词、凭据、路径或审批绑定值，界面文案由后续 H3b 提供。

后台工作按本轮持久来源绑定关联；旧记录只在同项目当前记录仍绑定原请求身份时回退读取。导出检查状态、托管产物是否存在以及冻结参数的一致性；存在性检查验证归属、托管路径、普通文件与记录尺寸，不代表对产物重新全量哈希或解码。生成分别检查终态、版本发布和费用状态；已提交但费用未确认仍为等待，费用未知单列，Mock 不适用。拆解与关键帧检查终态。本轮改过时间线时，每次读取都重新检查当前引用；默认 `timeline_preflight` 为 `pending`／`PREFLIGHT_NOT_REQUESTED`，不会读取或沿用上次的完整预检结果。显式带 `preflight=1` 才运行既有的完整本地导出预检。预检读取和哈希媒体、运行有界本地探测，可能较慢，不加入快照、SSE 或执行循环；客户端断开会取消这次本地预检，服务关闭也会取消并回收，恢复副本沿用原只读来源门禁。

完整预检的 client 默认请求超时至少为 60 秒，为服务端 30 秒预检预算及响应收尾留出余量；更长的全局超时保留，显式 `options.timeoutMs` 优先。默认轻量 checks 沿用普通请求超时。

后台完成、人工编辑或删除产物之后，服务端重新读取会反映当前结果；服务端不缓存先前通过状态，也不触发重新执行。预检期间依据变化、检查繁忙或能力不足会显示等待／不可完成原因，不能伪称通过。目标检查和自动补做留到 H4a。

### 完成情况界面

Mio 最后回复后，仅 `completed` 轮次在“本轮变化”之后显示完成情况。分组沿用接口顺序，隐藏不适用项和空组；组内未通过项排在前面。没有可显示项且没有完整预检进行中时不显示标题或空提示，首次读取前也不显示“没有适用的检查项”。全部通过默认折叠，未通过或等待默认展开。标题为“完成情况 5 项 · 1 项未通过”，未通过的整段摘要与原因使用 danger 色，等待摘要用正文色，不整块填色。名称、原因、进度及接口已提供的时间线信息由四语文案生成；费用待核对或记录不可用不会显示为正在进行。检查结果不影响轮次状态或执行控制。

界面只对进入可视区域的轮次按需读取，全局最多并发两个 checks 请求，按工作区、项目、轮次和轮次修订缓存。新快照的轮次修订变化或 `backgroundPending` 从 true 变为 false 时立即轻量重读；仍有等待项的可见轮次另外每 5 秒轻量重读，因为拆解完成、进度和费用变化不保证产生运行事件。没有等待项、面板隐藏、历史覆盖层打开或页面不可见时停止轻量读取与轮询。已经开始的完整预检继续到结束，不受可见性变化或轻量刷新打断；期间的轻量刷新合并丢弃。只有卸载、切换对话／项目或轮次不再 completed 才取消完整预检。读取失败保留上一份结果并显示可重新检查的错误提示，不回显底层诊断信息。

“重新检查”只发送只读 `checks?preflight=1`，至少等待 60 秒，进行中禁止重复操作；成功后显示“刚刚检查”直到下一次刷新。最新一轮首次显示且轻量结果含 `PREFLIGHT_NOT_REQUESTED` 时，本次打开应用期间最多自动完整预检完成一次：成功或失败后不再自动重试，被取消则释放本次占用，下次这一轮可读时可重新尝试。完整预检只按该轮检查项 `basis` 中的时间线 ID／修订复用；轻量刷新发现时间线修订变化就作废，用户仍可手动重新检查。没有完整结果时，未请求的预检项不显示、不计数、不旋转。

恢复副本中的读取、重新检查和已有定位路径照常可用，没有新增写操作。定位只复用本轮变化与后台记录的现有入口；无入口的对象不显示定位按钮。检查界面不会请求模型或自动补做，不增加 RPC／MCP／CLI 工具。

## 模型缓存与私有用量

仅 `anthropic` 预设的官方 `https://api.anthropic.com` Messages 请求添加 5 分钟 `ephemeral` 缓存断点。工具按核心组、稳定的已加载组顺序排列，断点依次放在核心工具末尾、全部工具末尾、系统指令末尾、末条消息的最后内容块；核心与全部工具末尾重合时去重，每个请求最多四个。兼容端点（包括 MiniMax）、自定义地址和其他协议不发送 `cache_control`。断点在构建请求时写入原件，恢复未发送 intent 直接使用原件，不重新排序或移动断点。

Anthropic 按工具、系统指令、消息的顺序计算缓存前缀。核心断点保留加载工具组前后的核心字节前缀，但工具列表变化仍可能使后续缓存失效，跨列表复用须以服务方实测为准。压缩改写较早往返会使其后的历史前缀变化；项目概况仍放在历史之后，不为缓存改动上下文语义。离线字节相同只表示前缀稳定，不代表达到模型的最小 token 门槛、20 块查找窗口或实际命中。

三种协议将已报告的输入、输出、缓存读取及缓存写入计数写入模型步骤的私有 `result.usage`，不加入公开快照、事件或 CLI。输入表示含缓存的总输入：Anthropic 只有未缓存输入、缓存读、缓存写三个分量齐全时才计算总数；其他协议直接使用总输入。缺失或无效计数不补零、不阻止完成；流式累计值按字段保留最后有效的非递减值，不逐帧相加，也不代表完整结算。Chat Completions 没有通用的缓存写入计数，DeepSeek 的未命中数不算写入。只有具有官方文档依据的 OpenAI、Qwen、DeepSeek 官方端点主动请求 `stream_options.include_usage`；Qwen 目前限北京／新加坡固定兼容端点，未确证的工作空间端点及其他连接仅被动读取返回值。输出上限仍为 4096 token。

## 请求回执与恢复

发送、策略、编辑占用和执行控制都使用稳定请求 ID。控制操作同时校验执行版本并保存持久回执。响应丢失后只查询原请求；界面刷新、SSE 重连不会自动重发操作。

重新显示已确认结束的对话时，只读重校验不会阻止正常关闭或重启；读取期间仍禁用发送、上传、授权与执行控制。首次读取、切换到另一段历史、尚未结束或有后台待核对工作的对话继续保留原关闭检查。草稿仍需确认，待确认回执与未知结果仍会阻止关闭；重校验新发现未知结果时，原关闭许可立即失效。

重启将未结束的执行标为 `interrupted`，不会自动续跑。尚未处理的目标冲突或编辑占用会保留；用户继续只把它恢复到冲突暂停，仍须明确选择跳过或停止，不执行旧工具参数，也不唤醒关联后台队列。旧版本只保存 `restart` 原因的记录，同样按未处理的持久冲突证据恢复这一选择。存在模型或工具未知结果时，必须先明确处置，不能借恢复冲突绕过未知结果门禁。未发送的模型 intent 可在普通继续后发送一次；已发送但无完成回执的模型结果必须先明确标记失败。可证明原子事务未提交的本地步骤可核对后废弃并重新规划，不重放旧参数。付费生成同理：生成任务或图像任务、请求回执和任务来源绑定都不存在，且没有派发留下的费用状态时，可证明受理未提交，可标记为失败后重新规划；有其中任一记录时，生成未知结果必须走原生成对账流程；`task.wait` 只接受对账后的本地结果，不能重新提交代替恢复。

## 对话分组（M3）

`send` 可携带 `conversationId`。省略时由服务端在接收事务中生成新的对话 ID；继续已有对话必须显式传回该 ID。不存在、跨项目或只属于诊断运行的 ID 均拒绝，不能创建客户端自定 ID。稳定 requestId 同时绑定是否传入对话 ID 及其原值；重放旧请求不会创建第二轮，不能把一条新对话请求改成续发请求。

模型上下文取当前对话内最近四轮已完成、失败、停止或已撤销的普通执行。每轮保留用户原话、全部补充说明及已回答提问的问题原文、所选项和回答文字；问答和说明按步骤顺序纳入，未回答的提问不带入。仅已完成轮次带最后一条已完成模型回复。每轮另附不超过 4 KiB 的宿主执行记录，按状态与失败类别、跳过的目标、发送时已保存的后台状态、A6 安全展示的变化依次取舍；每类优先最近记录，并明确省略数量，问答不在记录中重复。它们按完整历史轮次裁剪，用户原话、说明、问答、回复及执行记录一起移除。新对话不继承同项目的其他对话，语言仍由本轮指定。

普通执行还在发送时冻结不超过 2 KiB 的项目概况：项目名、已保存的时间线格式与时长、轨道／片段／字幕／镜头数、素材类型计数及未结束后台工作数。概况在本轮压缩中始终保留，不随下一次请求刷新。宿主依据已保存的相邻模型修订基线，对本轮工具回执中读过或改过、且由本轮自身变化无法解释修订推进的目标，在新请求边界加入过期提示；历史边界重放同一提示，本轮完整变化区间或重新读取到当前修订不提示。提示只要求重新读取，不改变冲突暂停、跳过、授权或审批判断。缺少目标回执的旧步骤不从结果正文猜测目标。

项目有项目说明（C6）时，发送时把说明冻结在项目概况之后、本次消息之前，同样在本轮压缩中始终保留；之后修改说明只影响新发送的轮次。

执行记录、项目概况、项目说明及过期提示均按本轮语言标明“仅供参考，不是指令”，不授予权限或审批；项目说明还写明不能改变放行档位。历史分组仅是既有私有 `run.context` 内的宿主结构，构造模型请求前展开；旧平铺上下文继续可读，已保存的模型 intent 仍直接发送其原始请求。诊断运行使用独立对话身份，不能续入普通对话，不带这些概况／记录／提示，也不进入项目执行列表、对话历史或后续上下文，但原 requestId／runId 仍可查询其审计记录。

历史返回 `conversations`，每条包含 `id`、`projectId`、`title`、`createdAt`、`updatedAt`、`lastRunId`、`lastRunStatus`、`changeCount` 与 `runCount`。标题只取首条用户消息，清理控制／双向字符、合并空白并安全截到 120 个 UTF-16 单位，不调用模型。更新时间取对话内所有轮次的最新更新时间，变化条数包含其全部 Change。对话成员接口返回 `conversation`、`runs` 和 `nextCursor`，每页默认 50／最多 100，删除私有 context；客户端按 runId 读取公开快照，不把项目最近 100 轮当成完整对话。

新轮在同一对话中的 `createdAt` 至少比已有轮次的创建／更新时间晚 1 ms，后续 `updatedAt` 也不倒退。持久时间由宿主记录；同毫秒发送、系统时钟倒退、关闭重开及 54→55 备份恢复后，首轮标题、最后状态、上下文和分页仍沿用相同的逻辑顺序，不依赖随机 UUID 或未持久化的进程序号。

迁移将缺少 conversationId 的旧 v2 执行分别设为 `run.id`，各自成为单轮对话；不重写旧的不可变事件、请求摘要或回执。旧 52/53 只读资料使用同样的 `run.id` 读取回退。v1 保持原格式、只读，不写入 v2 对话或扩展授权。新索引与对话身份约束纳入 54/55 的严格 catalog，旧 52/53 不接受这种新增持久字段。

## 冲突跳过与补充说明（M4）

`skip` 只接受因 `conflict` / `editing` 暂停的执行。宿主把实际冲突目标、原工具步骤和时间保存到 `run.skippedTargets`，与稳定控制回执同事务提交；不把同一步中无关的目标加入名单，不产生 Change，不释放用户编辑占用。整个当前 Run 按目标类型和 ID 匹配，后续显式涉及这些目标的工具返回 `denied` / `TARGET_SKIPPED`，模型按本轮语言收到“这一处由用户保留，本轮不要再改”的说明。范围不明确的项目整体只读检查仍可用，其他目标仍可重新规划，新 Run 的跳过名单为空。停止不写跳过名单。旧 `resume` 不再接受冲突暂停，返回 `AGENT_TASK_SKIP_REQUIRED`；预算或用户主动暂停的普通继续语义不变。

跳过会废弃旧响应中尚未执行的工具参数和单次审批，再读取当前状态规划。后台实际发送前同样检查持久跳过名单；只阻断尚未发送的关联请求，已经发送的工作仍可保存结果。已发结果的自动选择仍经过原授权与目标门禁：已处理的跳过／后台拒绝不重复制造冲突，授权拒绝保留原原因供重新授权后继续；存储或未知异常仍向上传递，不当作已处理选择吞掉。公开已跳过行由名单产生，具体值来自读取时的真实 A6 当前值，不冒充跳过时的历史快照。

`note` 接受 `{requestId, runId, expectedRevision, action:"note", text}`，仅运行中、等待确认或已暂停可用。文本校验和 send 相同，最多有 5 条未绑定的说明；超限返回 `AGENT_TASK_NOTE_LIMIT`。数量和单条长度之外，已保存上下文、已知回复／工具结果（包括已经落库的流式回复正文）与排队说明的组合，使用与新请求相同的结果视图和整轮压缩后，仍受原有 128 KiB 历史和 512 KiB 请求上限约束（按 JSON 序列化后的 UTF-8 字节计算）。可削减旧历史时允许受理；压缩后的已知组合仍超限时，在受理事务内返回 `AGENT_TASK_NOTE_CAPACITY` 并保存 rejected 回执，原执行、已有说明和界面草稿不变；不先确认受理再因这些已知内容使执行失败。尚未产生的模型／工具输出仍按原上限检查，不预估或承诺它们一定能容纳。同一个请求 ID 只能对应原版本与原文，重复读取原回执，不重复排队；写库失败时正文、绑定和回执都不部分生效。

每条说明保留 `requestId`、`text`、`createdAt`，第一次进入新模型请求时在同一模型 intent 事务内绑定 `modelStepId`。已写 intent／已发请求不被后到说明修改。同一响应的原工具批继续顺序处理，说明在下一次模型请求作为用户消息加入，不计步骤。若说明在最后回复期间到达，同一 Run 在现有预算内再请求模型；到限时保留排队说明，不自动加预算。完成后的同对话上下文也保留说明，沿用原字节上限并按整轮裁剪历史；当前说明不会被静默丢弃。未知模型结果仍须明确处置，不能因为有说明就重发原请求。完成后输入属于同对话的新一轮，使用 send 而非 note。

新字段在公共 Run 读取契约中可选，以兼容旧 52/54 快照；新 56/57 资料必须包含数组并满足引用、去重、排队上限和模型步骤顺序约束。控制命令只属于宿主 HTTP／client／CLI，不加入业务 RPC、模型目录或 MCP 工具发现。

## 失败与撤销（M5）

`retry` 使用既有控制身份 `{requestId, runId, expectedRevision, action:"retry", stepId?}`。仅 failed 轮次的最后一步也是 failed 时可用；有 unknown / dispatch_started 步骤、指定了另一条步骤或同项目已有其他未结束轮次均拒绝。状态与回执在同一事务内保存，响应丢失后查询原回执，不自动重发。旧失败步骤和已完成结果保留，新模型请求另计一步。已用步骤和预算不变，预算耗尽直接按步数用完暂停，之后仍须明确继续。

模型步骤在两种情况下记为 failed，可明确重试：
- 网关证明请求尚未发出；
- 运行中的进程亲自观察到这次模型请求失败，包括服务商返回非 200 状态（如 401、429、500）、超时、连接中断、流被截断、协议或服务商错误、超出流量限制、请求了未授权工具。

模型步骤完成之前不会执行任何工具，所以这些失败不会改动项目；重试只会再发一次模型请求，上一次请求可能已经计费。以下情况仍保留 unknown，先明确处置才能继续：进程在请求途中退出（没有记录结果）、存储故障、未归类的异常，以及明确的未知结果。确定的工具失败停止当前轮，后续同批工具不执行；用户重试时把失败结果交回模型、废弃同批旧参数，由模型按新的目标基线重新规划。发送及执行前授权复查、网络策略、分档确认和本轮跳过名单全部沿用；重试不复用失败工具的单次批准。

只有仍处于未派发 `intent`、被本地合同校验拒绝的 `generation.submit` 参数错误，可以记录为 `rejected` 并把闭集字段反馈交回模型纠正。反馈先检查宿主字段、跳过名单和同项目镜头归属；精确匹配连接／配置修订／模型条目后重新计算能力，不引用供应商消息、原始异常、凭据、URL 或参数原值。非 Wan 连接收到 Wan 专属时长／画幅等字段时，会说明应使用已保存镜头字段。修正后的新步骤仍执行完整校验和付费确认，消耗原有步数；已进入 `dispatch_started`、UNKNOWN 或其他工具错误不进入这条纠错路径，不自动重发。

每条公开 Change 增加可选只读 `modifiedAfter`（当前目标修订大于原 revisionAfter）和 `undoDisposition`（逆序预判为 undo / retain / blocked）。同 Run 后续修改可使早期变化不能单独撤销，但整体预判会模拟相邻补偿链，因此不把本轮可连续回退的变化误列为外部修改。遇到阻断项时，更早尚待撤销项也标 blocked，确认弹窗不把它们计入本次可撤销数量。预判复用时间线领域校验，并识别新增连线、绑定墓碑及生成依赖。预判只供展示，实际操作在领域事务中再次核对。`undo_all` 可携带 `undoChangeIds` 绑定确认时可撤销的 Change ID 集合（去重且最多 10000 个）；集合变化时保存 rejected 回执且不执行补偿，实际每条补偿也限制在已确认集合内。面板始终发送该字段，旧 CLI 省略时保持原行为。

整体撤销只在严格单目标、当前修订确实更晚、当前内容与原 after 不同且无草稿时标记 superseded。标记、运行修订和变化事件一起提交，不执行补偿，不伪称已撤销，不删除原 before / after 或费用依据。当前内容已改回原 after（ABA）、复合变化或缺证据时，保留原停止规则。已经撤销的变化和不可撤销产物保持原语义；单条撤销不允许覆盖后续修改。

M5 不升级工作区版本：retry 回执的 action 原为受限字符串，superseded 已在固定 Change 状态枚举中，未增加表或持久字段；公开展示字段明确不进入固定存储格式。普通 56 / 恢复 57 以及旧 52/53、54/55 的各自验证与恢复规则保持不变。

流式正文合并写入：缓冲超过 8 KiB UTF-8 时立即追加正文并生成文本事件；其余非空缓冲由单一尾部定时器在请求开始或上次写入后的 250 ms 内写出，后续 delta 不推迟期限，正常结束时补写剩余内容。异常时先保存已收到的缓冲，再标记失败或未知；写入失败不自动重试。面板继续通过已保存的正文显示流式回复。补充说明的容量检查只计入已落库的正文。停止或关闭时取消定时器并丢弃未写缓冲，保留已写正文，返回后不再补写或完成步骤。进程中断时尚未写入的缓冲不保留；已发送但没有完成回执的模型步骤仍按原规则标为结果未知，必须明确处置，不自动重发。

## 历史容量与模型请求去重

普通工作区升级到 60，备份恢复为 61（`restored-local-v19`），保留主线场景功能的 58/59 固定格式。迁移不删除或改写旧执行、请求和事件；旧 52/53、54/55、56/57 及主线场景 58/59 仍由各自固定格式和原 64 MiB 配额验证。此前开发验证已使用的私有存储 58 按精确目录识别，无损补齐场景定义后迁移到 60；其私有恢复 59 保留原来源身份和只读语义，不按版本号将两种格式混同。新格式将执行历史字节上限有界增加到 256 MiB，保留 20000 行和单行 2 MiB 限制，不改变模型上下文、请求或步数上限，也不触发旧任务重发。

新模型步骤完整保存一次已冻结的原请求；其新事件仅以版本、步骤 ID、SHA-256 和 UTF-8 字节数引用该原件。模型请求、步骤身份不可修改或替换。读取时校验事件归属、引用版本、原件归属、哈希和大小，只还原请求字段，状态、文字和结果仍来自各条历史事件。旧内联事件保持原文。引用损坏会阻断读取，不能从当前配置或上下文重新拼装；合法项目删除仍能按原范围删除所属历史。

内部事件读取每页最多 2000 行且还原后不超过 8 MiB，按连续序号继续分页。SSE 只检查序号变化并返回既有安全快照，不展开私有模型请求。备份、恢复和打开恢复副本会验证引用及其原件，恢复历史仍只读。

在线备份在入场和关键阶段完整验证工作区；分块复制与清单检查期间复用该次验证，持续检查取消、锁归属、恢复状态及冻结的 `total_changes`、`schema_version`、`data_version`。本连接或其他连接写入、结构变化、跨异步等待的源库事务、锁丢失均拒绝继续，不刷新指纹或自动重试。这样不会为每个分块反复扫描全部历史；素材哈希、文件身份、冷副本验证和最终发布校验仍完整执行。

`mioon agent doctor` 的 `storage` 字段只读返回全工作区聚合容量、剩余额度、各固定表计量及格式；不发送模型请求，不输出请求正文、提示词、密钥或文件路径。执行写入达到配额时明确返回 `AGENT_TASK_STORAGE_LIMIT`；其他存储故障仍为 `AGENT_TASK_STORAGE_UNAVAILABLE`。失败后停止后续派发，不自动重试或生成第二份请求；未知结果仍走原对账流程。手动编辑的回执沿用原规则，不因 Mio 历史已满而阻断手动编辑；它占用的字节会计入之后的执行写入校验，因此容量诊断可能显示已满。

## 设置与测试连接（M7）

设置中心的 Mio 页按设计稿 07-09、07-10 排列，外框、标题和关闭沿用设置中心：
- 模型连接：服务商预设（多平台时另有平台 / 地区）、接口地址、协议、模型、密钥状态（更换 / 清除，不显示密钥本身）、连接测试。
- 执行方式：本地可撤销、本地不可撤销、付费各一行。查看类始终直接执行，只有存储里不是直接执行（例如经 CLI 修改过）时才显示为可调的一行。改付费为直接执行仍先确认，再带 `acknowledgePaid` 保存。
- 每轮步数上限（下一轮生效）、已授权目标（完整地址、模型、发送范围、授权日期与撤销）。

连接与执行方式由页底一次保存；没有改动时“保存”不可点，“放弃”恢复为已保存值。各自的回执、未知结果核对和不自动重发保持原样。

“测试连接”对已保存的连接发送一条 `diagnostic:{profile:"text"}` 诊断运行：
- 不带工具和项目上下文，也不进入对话历史。草稿未保存时不测试。
- 运行放在一个项目下：从项目内打开设置时用当前项目；桌面设置窗口和首页没有当前项目，依次用最近打开、最近更新的项目。没有项目时不可测试。
- 该项目有未结束的执行时返回 `AGENT_TASK_BUSY`，界面提示先处理。
- 目标尚未授权时先显示首次发送授权（5.7）。确认只授予所审阅的地址、模型与范围，再发送测试；取消不发送。
- 发送结果不明时只查询原回执，不重发。

结果从 `GET /api/agent/tasks/v2/diagnostics/latest` 读取（CLI：`mioon agent diagnose latest`）：
- 返回全工作区最近一次文本诊断的运行 ID、项目、状态、时间、协议、地址、模型，失败时另有失败代码；不含测试文字、模型回复或密钥。
- 界面只在协议、地址和模型都与已保存连接相同时，把它显示为当前连接的结果。

诊断运行不在对话中显示，也没有需要核对的副作用。因此启动恢复时，未结束的诊断运行记为 `stopped`（`pauseReason: "restart"`），已发出的模型步骤记为 unknown，不再留下一条看不见、却会挡住该项目后续发送的 interrupted 执行。普通执行的中断与恢复规则不变。M7 不升级工作区版本，也不新增持久字段。

## 放行档位与提问（C1、C3）

### 放行档位

每个对话可以有自己的四档执行方式（`override`），没有时沿用全局策略；每轮步数上限始终取全局。每一步都按所属对话当时的有效方式判断，所以运行中改档从下一步生效。

- 新对话在 `send` 里带 `policy:{modes, acknowledgePaid?}`。它和第一轮在同一事务中保存为修订 1，并以这次发送的 requestId 留下回执；重放必须带完全相同的 `modes`，原来没带的也不能补带。继续已有对话时不接受 `policy`。
- 已有对话用 `PUT /:projectId/conversations/:conversationId/policy` 修改，输入 `{requestId, expectedRevision, modes, acknowledgePaid?}`，`modes` 为 `null` 时清除覆盖、回到全局。清除后这一行和修订号保留，修订只增不减；同一 requestId 只能重放原输入。
- 付费从需要确认变为直接执行时（包括清除覆盖后全局付费为直接执行）必须带 `acknowledgePaid:true`，否则返回 `AGENT_TASK_APPROVAL_REQUIRED`，与全局策略一致。
- 放宽档位不会豁免已经出现的确认：等待确认的步骤，以及后台受理后要求的单次审批，都仍须明确批准。全局策略放宽同样如此。
- 输入区的三个预设：逐步确认 `step`（只读直接执行，其余确认）、默认 `default`（与默认全局策略相同）、完全放行 `full`（全部直接执行）。其他组合显示为自定义。

### 提问

宿主工具 `mioon_ask`（核心组，只读）让 Mio 向用户提一个结构化问题：

- `question`：1–200 字；`options`：2–4 个，`label` 1–60 字且互不相同，可选 `description` 不超过 80 字；以上都只占一行。可选 `multiple`（多选）和 `allowOther`（允许在选项之外补充文字）。
- 参数不合规时不等待回答：步骤记为 `rejected`／`VALIDATION_ERROR`，把出错字段和规则交回模型，不回显参数原值；模型可以修正后重新提问，这一轮不因此失败。
- 合规的提问不派发任何工作，步骤和执行都进入 `awaiting_answer`。

回答使用控制 `{requestId, runId, expectedRevision, action:"answer", stepId, choices, text?}`：

- `choices` 是选项下标，互不重复，最多 4 个；单选题最多 1 个。
- `text` 是 1–2000 字的文字，可以换行。与选项一起提交时问题必须允许 `allowOther`；只提交文字（`choices` 为空）总是可以，相当于用户在输入区直接回复。
- 回答成为该步骤的结果 `{answer:{choices, text?}, selected, text?}`，`selected` 是所选选项的标签；同一事务内继续这一轮，下一次模型请求把它作为工具结果。回答只是用户输入，不是付费或修改的确认，之后需要确认的步骤照常等待批准。
- 稳定 requestId 精确重放；改变选项或文字的重放返回 `AGENT_TASK_REQUEST_CONFLICT`。

等待回答时 `resume` 返回 `AGENT_TASK_STATE_CONFLICT`，`pause` 不改变状态。`stop` 结束这一轮，问题保持未回答。重启后执行标为 `interrupted`；继续后回到同一个问题，不再请求模型。提问本身计一步，回答不计步。上下文压缩时，本轮约束原样保留已回答问题的 `question`、所选标签和文字；没有提问的执行不增加这一项。

### 存储

普通工作区升级到 66，备份恢复为 67（`restored-local-v22`）：

- 新增 `agent_task_conversation_policies_v2`：每个对话一行，记录修订号和 `modes`（`null` 表示跟随全局）；`agent_task_conversation_policy_requests_v2` 记录请求回执，回执不可修改，必须对应已保存的修订。
- 两张表只能随项目删除，各最多 20000 行；对话策略必须和该对话的执行属于同一项目。备份包含这两张表，恢复副本中只读。
- 执行和步骤状态增加 `awaiting_answer`，只有 66/67 接受；旧的 52–65 固定格式仍然拒绝这一状态。迁移不重写已有执行、步骤、事件或回执。

## 技能包、项目说明与连续性检查（C6）

### 内置方法

- 4 份方法：`script-to-shots`（剧本拆镜头）、`shot-prompts`（镜头提示词）、`character-consistency`（角色一致性）、`continuity-check`（连续性检查）。源文件是 `packages/business/src/agent/skills/*.md`，由 `node scripts/generate-agent-skills.ts` 原文嵌入 `task-skill-catalog-v2.ts`（桌面后台经 esbuild 打包，运行时读不到 .md）；测试检查两者一致。
- 提供 `mioon_skill_read` 时，系统指令按本轮语言附上方法名称和简介，不附正文。
- 宿主工具 `mioon_skill_read {name, section?}`（核心组，只读，计一步）：不带 `section` 返回 `{name, version, title, sections, text}`，`sections` 是章节标题；带 `section` 返回 `{name, version, title, section, text}`。结果不超过 12 KiB，低于 16 KiB 的结果视图上限。未知方法或章节按参数纠错返回可读的章节，这一轮不失败。

- Mio 的 `mioon_project_notes_set` 在 canvas 组，本地可撤销；变化记录保存项目记录前后快照，撤销与 `project.rename` 相同。
- 说明随备份恢复，也随项目文件导出、导入和复制（见 `docs/PROJECT-PACKAGE.md`）。

### 连续性检查

宿主工具 `mioon_continuity_report {issues}`（核心组，只读，计一步，不产生变化）：

- 最多 20 条；每条 `{category, shotIds, text}`。`category` 取 `wardrobe`、`props`、`injury`、`position`、`direction`、`eyeline`、`lighting`、`sound`、`other`；`shotIds` 是 1–4 个不重复且属于当前项目的镜头；`text` 是一行、1–200 字的说明。
- 结果只有 `{issues, shots}` 两个计数；面板从保存的参数显示问题。
- 参数不合规或镜头不属于当前项目时不执行，按参数纠错返回出错字段，不回显镜头标识。

诊断运行不提供 `mioon_skill_read` 和 `mioon_continuity_report`，也不带项目说明。

## 机位预演（C8 v2）

三个工具都在 canvas 组，场景格式、单位和取景估算见 `docs/PREVIS.md`。

- 宿主工具 `mioon_previs_inspect {nodeId}`（只读，计一步）：读取当前项目的一个预演节点。结果是 `{nodeId, label, revision, sceneRevision, frame, scene, framing}`；`scene` 不含 `schemaVersion` 和关键帧 `exports`，可以修改后整体写回；`framing` 列出当前机位和每个关键帧在项目画幅内拍到的人偶、道具 ID，关键帧另有 K 编号、导出图片数和使用这些图片的镜头首尾帧。
- `mioon_previs_create` 是 `previs.create`，本地不可撤销（创建回执引用节点、不可删除，画布节点也没有删除），默认档位先确认。
- `mioon_previs_scene_set` 是 `previs.scene.set`，本地可撤销。给模型的参数说明坐标轴和单位，数组不用元组形式，名称规则写成文字（共享 Zod 仍做完整校验）；参数里没有 `schemaVersion` 和 `exports`。宿主在校验前把数值四舍五入到三位小数、补 `schemaVersion`、把机位的 `lookAt` 换算成 yaw 和 pitch、按关键帧 ID 保留被替换场景的导出（新 ID 为空），选中关键帧在模型给出有效值或 `null` 时采用，否则保留原值或清空。不合规时按参数纠错返回出错字段路径，不回显取值和未知字段名。
- 两个写操作的结果都是和 `mioon_previs_inspect` 相同的读取结果，在保存事务内生成。
- 撤销把修改前的场景保存为新的场景修订号（旧修订号可能还有保存回执，打开的编辑器也按修订号比较），并删除已不存在或机位改变的关键帧缩略图；节点之后有任何改动就不能撤销。
- 预演写入在单个事务内完成；用全新 requestId 时被 `NOT_FOUND`、`PREVIS_NODE_REQUIRED`、`REVISION_CONFLICT`、`PREVIS_REVISION_LIMIT`、`PREVIS_EXPORT_INVALID`、`PREVIS_CAPACITY` 拒绝，会标 `mutationOutcome: "not_applied"`，步骤直接失败，不进入结果未知。结果未知的场景保存按 `previs_requests` 核对。
- 编辑器打开期间持有节点的编辑保护，Mio 写这个节点时按 `editing` 暂停。
- 变化显示为“写入预演场景”，字段是人偶、道具、关键帧的数量（`figureCount`、`propCount`、`keyframeCount`）的前后值；执行前的确认卡片和冲突卡片只显示目标节点，整个场景的数量说明不了计划改什么。画板卡片和其他画板节点一样短暂显示“Mio 修改”。
- `previs.thumbnail.*` 仍不对 Mio 开放。

## 交叉淡化与多段增益

两个操作原先只在界面里用，现在也是 Mio 的本地可撤销工具。参数就是共享 schema 生成的那份，宿主补 `projectId` 和 `requestId`；操作规则见 `docs/API.md` 的 Crossfades 和 Clip gains 两节。

- `mioon_timeline_clip_crossfade` 在 editing 组：为不同轨道上首尾重叠的两段有声片段写两条线性曲线。`mioon_timeline_clip_setGains` 在 audio 组：一次设置 1–100 段有声片段的增益，建议增益由 Mio 先用 `mioon_timeline_clip_loudness` 测量得到。
- 目标是交叉淡化的两段和增益批次里列出的每一段，每段都必须是当前时间线上的片段。用户正在编辑其中任一段时，Mio 按 `editing` 暂停。
- 和其他片段编辑一样，宿主核对的是这些目标片段的修订号，执行时把模型给的时间线修订号换成当前值：别的片段被改不算冲突，目标片段在计划之后被改过就停下。
- 两个操作都是一个时间线修订、一条历史。Mio 的这一步记一条变化，撤销时所有目标片段一起复原；之后任一段被改过，这条变化就不能撤销。
- 用全新 requestId 时被确定拒绝（重叠关系不对、已有音量曲线、素材无声、增益都没变等）会带未执行证明，步骤直接失败；结果未知时按 `timeline_requests` 核对。
- 变化行：交叉淡化列出两段片段，没有字段；增益批次每段显示增益的前后 dB。执行前的确认卡片和冲突卡片显示每段计划的增益和当前值。
- 片段变换（`timeline.clip.setTransform`）仍只读；主体补角度和打光（`subject.variants.*`）还不开放。

## 本地接口

所有接口都经过现有 Host、Origin 和本地身份校验。

| 路径（前缀 `/api/agent/tasks/v2`） | 用途 |
| --- | --- |
| `GET /:projectId`、`POST /:projectId` | 项目执行快照、发送 |
| `GET /:projectId/history?cursor=…` | 按对话聚合的稳定游标分页历史（排除诊断） |
| `GET /:projectId/conversations/:conversationId?cursor=…` | 同一对话的轮次摘要，按持久化的创建顺序升序分页；完整细节仍按 runId 读取 |
| `GET /:projectId/conversations/:conversationId/policy`、`PUT …/policy` | 对话的执行方式：覆盖、全局和有效值（C1） |
| `GET /:projectId/:runId` | 执行的完整公开快照 |
| `GET /:projectId/requests/:requestId` | 查询原发送回执 |
| `GET /:projectId/:runId/events?after=…` | SSE 变更通知，收到后读取持久快照 |
| `POST /:projectId/:runId/actions` | 暂停、继续、失败重试、停止、批准、拒绝、跳过、补充说明、回答提问、撤销及未知结果处置 |
| `GET /:projectId/:runId/actions/:requestId` | 查询原控制回执 |
| `GET /policy`、`PUT /policy`、`GET /policy/requests/:requestId` | 执行策略及原请求回执 |
| `GET /diagnostics/latest` | 全工作区最近一次文本诊断（设置页的测试连接），只含身份、时间、结果与失败代码 |
| `GET /editing`、`POST /editing` | 目标修订与编辑占用，使用 owner／generation／sequence |
| `POST /:projectId/uploads`、`GET /:projectId/uploads/requests/:requestId` | 用户所选文件的托管句柄及受理回执 |

发送文本上限 32 KiB UTF-8。用户选文件后先托管到本地，执行只携带选定句柄；模型不能自由导入其他文件。M4 使用普通库 56、备份恢复格式 57（`restored-local-v17`），新增 Run 的 `notes`、`skippedTargets` 及严格验证；旧普通库迁移时补空数组，不重写旧事件、摘要或回执。M3 的 54/55（`restored-local-v16`）和 52/53 继续按各自原固定格式读写恢复，不复用或改写：52、54、56 备份分别恢复为 53、55、57 只读副本。旧的 50/51 固定格式、验证器和旧数据不变。v2 数据及托管字节纳入严格分类、计量、项目删除、备份、恢复和普通数据迁移。恢复副本中的 v2 执行记录只读。

在线备份和项目删除的静默检查包含 v2 执行器，模型等待不因发送接口已返回而被视为空闲。备份冻结期间，v2 写请求在读取请求体后及异步设置读取后再次检查维护状态；后台工具仍经过领域和实际发送前的保护。
