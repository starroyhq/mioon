# 智能助理任务 v2

统一任务入口沿用 Mioon 自有 harness、网关、SQLite 和业务服务。旧会话、修改提议及回执仍按原格式读取；旧接口和旧授权范围不变。连接设置和凭据格式不变。

## 执行与授权

- 新任务必须单独取得固定连接目标、模型的 `project_agent` 发送授权。任务固定项目及模型设置；旧的聊天或局部编辑授权不能替代它。
- Chat Completions 与 Responses 支持多轮模型／工具往返，同一响应中的工具顺序执行。模型只能使用显式准入的项目工具，不能提供项目切换、请求 ID、批准标志、凭据、任意路径或原始字节。
- 每个模型步骤和工具步骤计一步，默认每轮 30 步。预算用完会暂停，继续为原任务追加同样步数；设置的新步数仅作用于新任务。审批、控制、宿主等待循环不额外计步。
- 只读、本地可撤销、本地不可撤销、付费四档独立设置为直接执行或需要确认。前三档默认直接执行，付费默认确认。管理操作不向模型开放。
- 审批绑定原工具参数和目标单调修订。intent 保存后、业务事务开始前、后台真正提交前重新校验授权、执行状态和策略。暂停、停止、撤权或关闭付费直调会阻断尚未发出的工作。
- 生成提交返回已有任务引用；依赖生成结果时调用 `task.wait`。等待只读本地状态，可取消，不发模型请求，也不驱动供应商轮询。

模型已回答但后台工作未结束时，快照标注 `backgroundPending`，面板继续订阅费用与迟到结果，并保留暂停、停止入口。暂停保留原队列，继续后沿用原任务；停止只取消能证明尚未开始的本地排队工作，已发出工作继续按原结果路径收尾。

后台受理后关闭付费直调，会对原排队步骤请求单次审批。审批绑定受理事务保存的目标修订，实际发送前仍复查；批准后发生同目标修改或编辑占用也会暂停。因目标冲突继续时取消该旧队列，重新读取并规划，不重新提交旧参数。

费用状态按证据分别展示：待提交、已提交付费请求／可能计费、结果未知。只有实际计费证据才显示已产生费用。Mock 不记付费请求。不设付费次数上限，仍受任务步数、既有生成总开关和单次审批约束。已经发出的工作可以保存迟到结果，不承诺远端取消或退款。

## 实时修改、草稿和撤销

业务修改、业务回执、Change 与工具完成记录在领域自身事务中提交；写库失败会阻断后续请求。Change 实时出现在面板，可定位画布／时间线并短时高亮。

服务端按实际目标维护单调修订，包括人工编辑、AI 修改、撤销／重做及后台结果。修改后再改回仍属于冲突；其他目标上的编辑不使当前目标失效。

输入、IME 和拖拽开始前须取得对应目标的服务端编辑占用。占用跨窗口生效，保留草稿、断联、超时和重启不自动解除保护。人工保存／放弃草稿后显式释放；不确定的保留占用须由用户核对解决。任务因冲突暂停后，手动继续会废弃旧参数和审批，重新规划。

占用保存取得时的目标修订。原窗口可以显式恢复保留草稿的编辑保护，服务端只在同 owner、完整目标和原修订均一致时接受 `restore`；目标已变化时不自动重基或清空草稿。

单条撤销只补偿该 Change 影响的目标；整次撤销按逆序逐条提交，遇到外部修改就停止并保留进度。撤销链可跨过自身产生的修订，不能覆盖其他人工编辑。不可撤销产物和费用记录保留。

## 请求回执与恢复

发送、策略、编辑占用和任务控制都使用稳定请求 ID。控制操作同时校验任务版本并保存持久回执。响应丢失后只查询原请求；界面刷新、SSE 重连不会自动重发操作。

重启将未结束任务标为 `interrupted`，不会自动续跑。未发送的模型 intent 可在用户继续后发送一次；已发送但无完成回执的模型结果必须先明确标记失败。可证明原子事务未提交的本地步骤可核对后废弃并重新规划，不重放旧参数。生成未知结果必须走原生成对账流程；`task.wait` 只接受对账后的本地结果，不能重新提交代替恢复。

## 本地接口

所有接口都经过现有 Host、Origin 和本地身份校验。

| 路径（前缀 `/api/agent/tasks/v2`） | 用途 |
| --- | --- |
| `GET /:projectId`、`POST /:projectId` | 项目任务快照、发送 |
| `GET /:projectId/history?cursor=…` | 稳定游标分页历史 |
| `GET /:projectId/:runId` | 任务完整公开快照 |
| `GET /:projectId/requests/:requestId` | 查询原发送回执 |
| `GET /:projectId/:runId/events?after=…` | SSE 变更通知，收到后读取持久快照 |
| `POST /:projectId/:runId/actions` | 暂停、继续、停止、批准、拒绝、撤销及未知结果处置 |
| `GET /:projectId/:runId/actions/:requestId` | 查询原控制回执 |
| `GET /policy`、`PUT /policy`、`GET /policy/requests/:requestId` | 执行策略及原请求回执 |
| `GET /editing`、`POST /editing` | 目标修订与编辑占用，使用 owner／generation／sequence |
| `POST /:projectId/uploads`、`GET /:projectId/uploads/requests/:requestId` | 用户所选文件的托管句柄及受理回执 |

发送文本上限 32 KiB UTF-8。用户选文件后先托管到本地，任务只携带选定句柄；模型不能自由导入其他文件。适配 `origin/main` 后，普通库升级为 52，备份恢复格式为 53；远端已有的 50/51 固定格式、验证器和旧数据不变。v2 数据及托管字节纳入严格分类、计量、项目删除、备份、恢复和普通数据迁移。恢复副本中的 v2 任务只读。

在线备份和项目删除的静默检查包含 v2 执行器，模型等待不因发送接口已返回而被视为空闲。备份冻结期间，v2 写请求在读取请求体后及异步设置读取后再次检查维护状态；后台工具仍经过领域和实际发送前的保护。

```sh
pnpm typecheck
node --test tests/agent-task-*-v2.test.ts tests/agent-tasks-v2-ui.test.ts tests/agent-editing-protection.test.ts tests/agent-manual-collaboration.test.ts
pnpm --filter @mioon/web build
```

SIGKILL 测试只终止专用合成子进程，覆盖模型 intent／发送、本地业务事务提交前后、生成受理和结果落库。模型服务、生成和媒体均使用合成服务、Mock 或本地媒体；不能使用真实付费接口代替这些验证。
