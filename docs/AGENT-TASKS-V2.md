# Mio v2 执行与恢复

Mio 的统一入口沿用 Mioon 自有 harness、网关、SQLite 和业务服务。旧会话、修改提议及回执仍按原格式读取；旧接口和旧授权范围不变。连接设置和凭据格式不变。

## 执行与授权

- 开始执行前，必须已有固定连接目标、模型的 `project_agent` 发送授权。这一轮固定项目及模型设置；旧的聊天或局部编辑授权不能替代它。
- Chat Completions 与 Responses 支持多轮模型／工具往返，同一响应中的工具顺序执行。模型只能使用显式准入的项目工具，不能提供项目切换、请求 ID、批准标志、凭据、任意路径或原始字节。
- Mio 的回复使用发起这一轮时的界面语言；切换语言不会改写已保存的用户消息、回复或项目内容。
- 每个模型步骤和工具步骤计一步，默认每轮 30 步。预算用完会暂停，继续为当前执行追加同样步数；设置的新步数仅作用于下一轮。审批、控制、宿主等待循环不额外计步。
- 只读、本地可撤销、本地不可撤销、付费四档独立设置为直接执行或需要确认。前三档默认直接执行，付费默认确认。管理操作不向模型开放。
- 审批绑定原工具参数和目标单调修订。intent 保存后、业务事务开始前、后台真正提交前重新校验授权、执行状态和策略。暂停、停止、撤权或关闭付费直调会阻断尚未发出的工作。
- 生成提交返回已有任务引用；依赖生成结果时调用 `task.wait`。等待只读本地状态，可取消，不发模型请求，也不驱动供应商轮询。

模型已回答但后台工作未结束时，快照标注 `backgroundPending`，面板继续订阅费用与迟到结果，并保留暂停、停止入口。暂停保留原队列，继续后沿用这一轮；停止只取消能证明尚未开始的本地排队工作，已发出工作继续按原结果路径收尾。

后台受理后关闭付费直调，会对原排队步骤请求单次审批。审批绑定受理事务保存的目标修订，实际发送前仍复查；批准后发生同目标修改或编辑占用也会暂停。因目标冲突选择跳过时，只取消涉及实际跳过目标的未提交旧队列，重新读取并规划，不重新提交旧参数。

费用状态按证据分别展示：待提交、已提交付费请求／可能计费、结果未知。只有实际计费证据才显示已产生费用。Mock 不记付费请求。不设付费次数上限，仍受每轮步数、既有生成总开关和单次审批约束。已经发出的工作可以保存迟到结果，不承诺远端取消或退款。

## 实时修改、草稿和撤销

业务修改、业务回执、Change 与工具完成记录在领域自身事务中提交；写库失败会阻断后续请求。Change 实时出现在面板，可定位画布／时间线并短时高亮。

服务端按实际目标维护单调修订，包括人工编辑、AI 修改、撤销／重做及后台结果。修改后再改回仍属于冲突；其他目标上的编辑不使当前目标失效。

开始输入、使用输入法或拖拽后，Mio 会等待你保存或放弃同一处修改并结束编辑。这个编辑状态跨窗口生效，草稿、断联、超时和重启不会自动结束编辑。保存或放弃修改后须明确结束编辑；状态不确定时，先核对原窗口中的修改。这一轮因冲突暂停后，选择“跳过这一处并继续”会废弃旧参数和审批，重新规划；普通继续不能绕过这个选择。

占用保存取得时的目标修订。原窗口可以明确继续编辑保留的草稿，服务端只在同 owner、完整目标和原修订均一致时接受 `restore`；目标已变化时不自动重基或清空草稿。

单条撤销只补偿该 Change 影响的目标；整次撤销按逆序逐条提交，遇到外部修改就停止并保留进度。撤销链可跨过自身产生的修订，不能覆盖其他人工编辑。不可撤销产物和费用记录保留。

## 面板与安全展示

Mio 面板在同一对话中按轮次展示用户消息、最新回复、可折叠步骤及变化；输入区固定在底部。标题取本对话首句用户消息，历史浮层按对话读取。首次未授权发送通过完整地址、模型和发送范围的确认弹窗授予 `project_agent`；取消保留草稿。确认前后输入、附件、语言、连接或窗口归属变化时不自动发送，授权响应丢失时也不自动补发。

公开 Step / Change 可包含 `display` 安全投影：操作类型、项目内目标的类型/显示名，以及有界的白名单字段。片段支持时长、入出点、位置、音量和淡入淡出；镜头支持比例、时长、描述；字幕支持文字；生成提交支持明确提供的参数。预览只展示已知参数，不推测旧值或新版本号；其余操作退回类型和目标。冲突卡只采用服务端当次本地读取的白名单当前值，不把界面缓存冒充当前值；后台冲突由宿主投影标记关联原步骤。原始 `before` / `after` 仍为 `null`，不公开补偿 `undo`。`description` 与 `subtitleText` 是已授权本机客户端可读的项目内容，只取对应真实字段，去除控制字符和双向文本字符、合并空白并按字符安全截断；不根据 URL、路径、UUID、id 前缀或“密码”等关键词猜测和删改内容。只有素材和时间线片段的媒体文件名提取路径最后一段；字幕文字、镜头标题、项目名等只清理控制／双向字符、合并空白并截断，不按斜线或反斜线截断，也不按凭据、UUID 等启发式遮挡。变化文案不使用模型撰写的 Change summary。

界面优先用已有项目数据中的目标名，并按界面语言格式化值和单位。步骤说明由内置模型工具包装的 `_mio_step` 提供，执行前剥离；缺失或不合规时用本地化操作模板。该字段不进入业务 RPC、CLI 或 MCP 的公共工具参数。说明保存在现有步骤文字字段中，不改变授权、审批或工具幂等参数。

`display` 只在读取快照时构建，不迁移持久记录或修改工作区/备份格式。新版 HTTP、客户端和 CLI 共用更新后的 contracts；使用旧严格快照解析器的独立客户端需同步升级，不能假定它会接受新增响应字段。旧记录没有投影数据时仍可读取并使用操作类型回退。

## 请求回执与恢复

发送、策略、编辑占用和执行控制都使用稳定请求 ID。控制操作同时校验执行版本并保存持久回执。响应丢失后只查询原请求；界面刷新、SSE 重连不会自动重发操作。

重启将未结束的执行标为 `interrupted`，不会自动续跑。未发送的模型 intent 可在用户继续后发送一次；已发送但无完成回执的模型结果必须先明确标记失败。可证明原子事务未提交的本地步骤可核对后废弃并重新规划，不重放旧参数。生成未知结果必须走原生成对账流程；`task.wait` 只接受对账后的本地结果，不能重新提交代替恢复。

## 对话分组（M3）

`send` 可携带 `conversationId`。省略时由服务端在接收事务中生成新的对话 ID；继续已有对话必须显式传回该 ID。不存在、跨项目或只属于诊断运行的 ID 均拒绝，不能创建客户端自定 ID。稳定 requestId 同时绑定是否传入对话 ID 及其原值；重放旧请求不会创建第二轮，不能把一条新对话请求改成续发请求。

模型上下文只取当前对话内最近四轮已完成的普通执行，保留原有字节裁剪和本轮语言；新对话不继承同项目的其他对话。诊断运行使用独立对话身份，不能续入普通对话，不进入项目执行列表、对话历史或后续上下文，但原 requestId／runId 仍可查询其审计记录。

历史返回 `conversations`，每条包含 `id`、`projectId`、`title`、`createdAt`、`updatedAt`、`lastRunId`、`lastRunStatus`、`changeCount` 与 `runCount`。标题只取首条用户消息，清理控制／双向字符、合并空白并安全截到 120 个 UTF-16 单位，不调用模型。更新时间取对话内所有轮次的最新更新时间，变化条数包含其全部 Change。对话成员接口返回 `conversation`、`runs` 和 `nextCursor`，每页默认 50／最多 100，删除私有 context；客户端按 runId 读取公开快照，不把项目最近 100 轮当成完整对话。

新轮在同一对话中的 `createdAt` 至少比已有轮次的创建／更新时间晚 1 ms，后续 `updatedAt` 也不倒退。持久时间由宿主记录；同毫秒发送、系统时钟倒退、关闭重开及 54→55 备份恢复后，首轮标题、最后状态、上下文和分页仍沿用相同的逻辑顺序，不依赖随机 UUID 或未持久化的进程序号。

迁移将缺少 conversationId 的旧 v2 执行分别设为 `run.id`，各自成为单轮对话；不重写旧的不可变事件、请求摘要或回执。旧 52/53 只读资料使用同样的 `run.id` 读取回退。v1 保持原格式、只读，不写入 v2 对话或扩展授权。新索引与对话身份约束纳入 54/55 的严格 catalog，旧 52/53 不接受这种新增持久字段。

## 冲突跳过与补充说明（M4）

`skip` 只接受因 `conflict` / `editing` 暂停的执行。宿主把实际冲突目标、原工具步骤和时间保存到 `run.skippedTargets`，与稳定控制回执同事务提交；不把同一步中无关的目标加入名单，不产生 Change，不释放用户编辑占用。整个当前 Run 按目标类型和 ID 匹配，后续显式涉及这些目标的工具返回 `denied` / `TARGET_SKIPPED`，模型按本轮语言收到“这一处由用户保留，本轮不要再改”的说明。范围不明确的项目整体只读检查仍可用，其他目标仍可重新规划，新 Run 的跳过名单为空。停止不写跳过名单。旧 `resume` 不再接受冲突暂停，返回 `AGENT_TASK_SKIP_REQUIRED`；预算或用户主动暂停的普通继续语义不变。

跳过会废弃旧响应中尚未执行的工具参数和单次审批，再读取当前状态规划。后台实际发送前同样检查持久跳过名单；只阻断尚未发送的关联请求，已经发送的工作仍可保存结果。已发结果的自动选择仍经过原授权与目标门禁：已处理的跳过／后台拒绝不重复制造冲突，授权拒绝保留原原因供重新授权后继续；存储或未知异常仍向上传递，不当作已处理选择吞掉。公开已跳过行由名单产生，具体值来自读取时的真实 A6 当前值，不冒充跳过时的历史快照。

`note` 接受 `{requestId, runId, expectedRevision, action:"note", text}`，仅运行中、等待确认或已暂停可用。文本校验和 send 相同，最多有 5 条未绑定的说明；超限返回 `AGENT_TASK_NOTE_LIMIT`。数量和单条长度之外，已保存上下文、已知回复／工具结果与排队说明的组合仍受原有 128 KiB 历史和 512 KiB 请求上限约束（按 JSON 序列化后的 UTF-8 字节计算）。已知组合超限时，在受理事务内返回 `AGENT_TASK_NOTE_CAPACITY` 并保存 rejected 回执，原执行、已有说明和界面草稿不变；不先确认受理再因这些已知内容使执行失败。尚未产生的模型／工具输出仍按原上限检查，不预估或承诺它们一定能容纳。同一个请求 ID 只能对应原版本与原文，重复读取原回执，不重复排队；写库失败时正文、绑定和回执都不部分生效。

每条说明保留 `requestId`、`text`、`createdAt`，第一次进入新模型请求时在同一模型 intent 事务内绑定 `modelStepId`。已写 intent／已发请求不被后到说明修改。同一响应的原工具批继续顺序处理，说明在下一次模型请求作为用户消息加入，不计步骤。若说明在最后回复期间到达，同一 Run 在现有预算内再请求模型；到限时保留排队说明，不自动加预算。完成后的同对话上下文也保留说明，沿用原字节上限并按整轮裁剪历史；当前说明不会被静默丢弃。未知模型结果仍须明确处置，不能因为有说明就重发原请求。完成后输入属于同对话的新一轮，使用 send 而非 note。

新字段在公共 Run 读取契约中可选，以兼容旧 52/54 快照；新 56/57 资料必须包含数组并满足引用、去重、排队上限和模型步骤顺序约束。控制命令只属于宿主 HTTP／client／CLI，不加入业务 RPC、模型目录或 MCP 工具发现。

## 本地接口

所有接口都经过现有 Host、Origin 和本地身份校验。

| 路径（前缀 `/api/agent/tasks/v2`） | 用途 |
| --- | --- |
| `GET /:projectId`、`POST /:projectId` | 项目执行快照、发送 |
| `GET /:projectId/history?cursor=…` | 按对话聚合的稳定游标分页历史（排除诊断） |
| `GET /:projectId/conversations/:conversationId?cursor=…` | 同一对话的轮次摘要，按持久化的创建顺序升序分页；完整细节仍按 runId 读取 |
| `GET /:projectId/:runId` | 执行的完整公开快照 |
| `GET /:projectId/requests/:requestId` | 查询原发送回执 |
| `GET /:projectId/:runId/events?after=…` | SSE 变更通知，收到后读取持久快照 |
| `POST /:projectId/:runId/actions` | 暂停、继续、停止、批准、拒绝、跳过、补充说明、撤销及未知结果处置 |
| `GET /:projectId/:runId/actions/:requestId` | 查询原控制回执 |
| `GET /policy`、`PUT /policy`、`GET /policy/requests/:requestId` | 执行策略及原请求回执 |
| `GET /editing`、`POST /editing` | 目标修订与编辑占用，使用 owner／generation／sequence |
| `POST /:projectId/uploads`、`GET /:projectId/uploads/requests/:requestId` | 用户所选文件的托管句柄及受理回执 |

发送文本上限 32 KiB UTF-8。用户选文件后先托管到本地，执行只携带选定句柄；模型不能自由导入其他文件。M4 使用普通库 56、备份恢复格式 57（`restored-local-v17`），新增 Run 的 `notes`、`skippedTargets` 及严格验证；旧普通库迁移时补空数组，不重写旧事件、摘要或回执。M3 的 54/55（`restored-local-v16`）和 52/53 继续按各自原固定格式读写恢复，不复用或改写：52、54、56 备份分别恢复为 53、55、57 只读副本。旧的 50/51 固定格式、验证器和旧数据不变。v2 数据及托管字节纳入严格分类、计量、项目删除、备份、恢复和普通数据迁移。恢复副本中的 v2 执行记录只读。

在线备份和项目删除的静默检查包含 v2 执行器，模型等待不因发送接口已返回而被视为空闲。备份冻结期间，v2 写请求在读取请求体后及异步设置读取后再次检查维护状态；后台工具仍经过领域和实际发送前的保护。
