# 原生关闭准入与独立窗口前置检查

基线：`1bb99548db4ccbf5b8bb38195dfac3abf1409fa1`。本片修复单窗口的安全关闭与固定当前页面重载；独立 launcher/editor 尚未实现。H1 的既有证据见 [项目首页](PROJECT-HOME-H1.md)。

## 问题与范围

旧 App 的 `beforeunload` 只检查镜头、片段、规格和成片名等编辑状态，遗漏 Agent 未发送文字、图片草稿及设置表单。旧 Electron `will-prevent-unload` 的通用“放弃”处理还可能越过未知或正在提交的状态。

新增逻辑分别位于 [renderer 准入](../apps/web/src/native-close-state.ts)、[来源状态适配](../apps/web/src/native-close-sources.ts) 和 [desktop 协议](../apps/desktop/src/native-close.ts)。旧 JSX/MJS 仅接线，业务提交、项目导航、权限、持久化格式及模型调用合同不变。

- 新来源同步报告 `dirty/busy/blocked/version`；注册、卸载与替换绑定明确 owner。原有四类连接设置继续复用已实现的设置状态注册表。
- 未发送文字/图片/非秘密设置输入可经明确确认放弃；busy、待确认请求或未核对的设置结果不能由通用放弃绕过。
- 三个准入确认/提示使用异步原生对话，等待用户期间主进程心跳继续；不放宽 backend 的 30 秒心跳租约或票据时限。
- 原有本地视图/草稿 drain 保留。该 drain 的原有失败确认不等同于新增来源可丢弃；新增来源先检查，最终再次复核。
- 已接受的持久任务有自己的生命周期。关闭适配器不会重新提交、批准、停止或取消它们；整个应用退出仍沿既有 backend shutdown 行为。
- 捕获票据绑定当前窗口、backend/session、document generation、页面 URL、目标动作、项目/工作区 scope、来源 owner/version 与输入事件计数。确认后又输入、换项目或换来源即失效。
- 最后 `commit` / `beforeunload` 准入检查同步且只读，不调用旧 controller 的同步/自动保存入口，不调度计时器、不发写请求。镜头原 `hasUnsaved` 会同步上下文，改由[独立纯状态适配](../apps/web/src/native-close-legacy.ts)与本地表单身份作最终核对；Inspector 的程序化确认续接即使早于 React layout，也会使旧决定失效。已放弃输入不会仅因旧 ref 尚未重绘而重新标成未保存。原有独立生命周期 flush 仍可能运行，不能将整个浏览器事件称为绝对零写入。
- 票据一次性、短时有效；晚到确认、超时 executeJavaScript、旧 cancel、renderer 替换不能授予另一次关闭权限。缺失、异常或无响应时保留原窗并说明受阻。
- 固定“重载当前页面”使用相同准入；它只读取当时已验证的当前 URL，不接收任意目标。close 与 reload 的票据不可互换。取消、renderer veto 和 `ERR_ABORTED` 不作为启动 fatal；真正初次启动加载失败仍走原错误路径。 主文档已提交后释放旧 reload 准入，不等待全部资源加载完成才允许新的关闭检查；旧加载完成/失败观察仍绑定原 generation 与操作序号。主文档尚未提交或无法读取状态时继续保留窗口，不强制销毁。

## 已确认 renderer 崩溃的既有恢复入口

Electron 确认 `render-process-gone` 后，旧 renderer owner 已不存在，不能要求死亡页面执行准入脚本。既有恢复对话分别提供明确重载、退出和保留窗口；关闭对话/Escape 对应保留。

- 重载与退出共用同一份、仅可消费一次的事故证明，绑定窗口、backend、页面 URL、document generation 和动作序号。新窗口、新 backend、新导航或另一事故使旧对话失效。
- 明确重载只加载被捕获的当前 URL；不重提模型或业务请求。明确退出仅给既有 `QuitCoordinator` 同步发出的那一次 close 放行，服务仍等窗口实际关闭后停止。
- 对话未结束时若后来确认同一窗口进程死亡，旧对话决定不授权新事故；记录的较新事故仍有新的明确恢复入口，重复通知不重复消费或自动执行。
- `unresponsive` 不是进程已经死亡。仍活着但 unknown/busy 或无法核对的 renderer 继续保留，不能使用崩溃证明绕过。
- 崩溃前未保存输入可能已经丢失；恢复不是保存确认。后台接受的任务保留既有状态与恢复语义。

## 未确认状态如何解除

这里没有以刷新、隐藏或 toast 作为保存证明，也没有自动重试业务。

| 来源 | 保留条件 | 既有明确解除途径 |
| --- | --- | --- |
| Agent 聊天 | pending / unknown、首次读取失败、提交或停止中 | 同请求身份只读核对取得已接受结果；或现有明确风险确认的结束本地待确认动作。未发送文字仍需另行处理 |
| Agent 编辑提议 | 本地 uncertain、已批准/dispatching/unknown 或动作正在提交 | 现有提议/编辑任务读取取得确定状态；关闭检查本身不执行提议 |
| 图片生成 / Comfy | pending、remote pending、请求存储受阻、提交或处理动作中 | 现有严格同键 ACK / 对账或既有明确处理流程；接受后的任务状态不被当作新的本地请求 |
| 图片拒绝审批 | 拒绝 POST 已发但终态未确认 | 同 review 身份摘要与精确后继 revision 的 rejected/approved/dispatched 记录。pending 的再次读取不能解除 |
| Agent / 官方 Images / 兼容 Images / Comfy 设置 | saving/reconciling/checking 或 recovery/review | 各自既有重新读取与明确核对动作；钥匙输入仍按原隐藏清除规则，不写入草稿或关闭元数据 |

图片拒绝的补充标记只保留本地有界 ID/revision/摘要，用现有审批数量与字段容量上限；它不改变审批、回执、请求键或网络行为。异常身份/摘要失败保持拒绝，不能通过清空标记冒充核对完成。

## 首轮真实包发现并保留的问题

首轮生产包在实际 Linux 原生操作中确认：Agent 取消退出、图片输入取消重载能保留输入。但后续明确重载被拒绝，之后出现本地服务停止，故该包不算最终验收通过。

- 三个准入提示沿用了同步原生对话，等待用户会阻断主进程心跳。修正为异步对话，保留原选择与每次 await 后的归属/输入复核；后端租约不变。
- 主体库已有 window focus 自动只读刷新。以整个 state 对象作为输入身份，会把归焦后的列表读取误认新输入。按真实本地草稿、选择目标与未处理状态比较，列表读取阶段本身不授权，也不阻断相同输入的确认。
- 首轮原图、日志与包 hash 保留。修正后的最终包实际验证了 40.076 秒的对话等待：5 次健康读取均成功，backend PID、进程启动身份与端口不变；取消保留输入，明确放弃后重载成功。

## 验收归属

- 因果红例：基线 App 真实关闭绑定不能阻止新增来源；新实现测试覆盖 Agent/Image/settings、确认后编辑、来源替换、项目/工作区变化、晚 ACK 与卸载。
- 协议测试：真实 renderer 核心与 desktop 固定脚本配对，检查 busy/unknown 不可放弃、短期票据、关闭/重载隔离和同步最终否决。
- 原有草稿 drain、窗口归属、startup/restart、各设置及 Agent/Image renderer 测试保留原业务断言。
- 最终受影响检查 947/947，通过且无跳过；typecheck、fresh Linux 生产包构建与 ASAR 内容核对成功。原生完成 Agent/图片/非秘密设置取消保留、明确放弃重载、干净重载、正常退出与同包重开。两次精确自有 renderer SIGKILL 分别验证“保留后显式菜单重载恢复”及“明确退出”，正常退出均为 code 0。所有原有业务行保持原值，仅视图偏好变化；普通供应商初始化另建了两张空 Mock 表，因此不称 schema 字节不变。该原生样本原本没有媒体，未新增媒体。busy/unknown、竞态与票据过期的覆盖来自确定性协议/组件测试，未冒充真实供应商原生测试。父级首次全量 6483 项，6477 通过、4 失败、2 跳过；修正后独立全量实际 exit 0：6486 项、6484 通过、0 失败、0 取消、2 既有跳过，耗时 1,151,930.487063ms，前置 typecheck 成功。
- 首轮全量失败保留：一项旧成片名关闭源码断言、两项 compiler consumer 白名单/隔离复制遗漏，以及一项异步 SHA 完成等待测试。前三项改为真实纯状态读取与精确 consumer/source 接线，保留原 ACK、编译错误负例和 noEmit 断言。
- SHA 测试原先用 100 次 `setImmediate` 代表完成，全量约 5ms 后就断言失败，原日志没有记录线程池完成时刻。受控摘要保持 pending 跨过该循环可确定性重现旧等待器错误；新测试以真实状态发布事件为完成证明，5 秒仅作挂起失败上限，未完成时继续 blocked。实际 WebCrypto 与真实组件链路保留。改后来源套件 20 次串行复验均 15/15；六项受影响测试文件合计 90/90，typecheck 成功。
- 本轮全量后仅修改测试与此事实说明，生产源和最终 ASAR hash 不变；沿用上列已执行原生证据，不声称重新运行原生。
- macOS/Windows 未执行本片原生验收。普通正常退出不能代替强杀、OS 杀进程或机器掉电保证；本片不提供新增自动草稿存储。

## 后续独立窗口实施顺序（已批准规划，尚未实现）

先完成本片 P0，再单独实现一个 launcher 和最多一个 editor 顶层窗口，共享一个工作区 backend。复用 H1 首页；Web 保持单页，不能直接把完整 App 挂两次以制造重复启动或设置 owner。

1. 角色与 generation 明确：重复打开/启动恢复只有一个选择者，保留显式 URL → 有效定位 → 首项目的优先级。
2. editor 正常关闭与退出应用分开：前者在安全准入后显示 launcher；后者先完成所有窗口准入再停服务。quit requesting 期间不得复活 launcher。
3. App 级 durable/unknown owner 保留；隐藏不等于已保存或取消任务。不得通过清空 currentProject / 重建 controller 伪造安全关闭。
4. 全局设置有单一表单 owner；跨窗只传固定导航身份，不传密钥、输入正文或任意路径。
5. 下载与原生操作继续绑定正确 editor webContents、当前 generation 与已验证同源成片；不能把任意同源窗口视为获权。
6. 验收含正常关闭/退出、dirty 取消、busy/unknown、确认后新输入、无响应、晚回调、重复打开、多窗口恢复、下载归属与固定重载。全部通过前不称双窗口已交付。
