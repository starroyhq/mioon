状态：受影响门、生产包与 Linux 合成原生闭环完成；等待根独立全量，尚未发布。基线 `f8b91713af0c8ed3994e32fa57447827a0ab3883`。

## 用户流程与权限

1. 对已保存的完整时间线填写明确 LUFS 与 dBTP 目标，执行 `timeline.loudness.prepare`。
2. 原报告及候选的 `applyAllowed:false` 保持原义：报告是观察，不能授权修改。只有另一次明确确认可创建应用请求。
3. `timeline.loudness.apply` 再次读取同一版本、完整来源/双哈希、原混音及固定倍率候选，核对绑定后一次事务修改整组可听片段的 gain。
4. 一个时间线 revision、一个历史条目、一个不可变回执一起提交；现有 undo/redo 恢复编辑状态，旧成功回执永远不随撤销改写。
5. 导出配置仍默认原 `mp4_h264_v1`。用户可明确选择 `mp4_h264_float_checked_v2`；应用增益不会自动替用户换模式或导出。实际成片需再次执行已导出文件响度测量，才可核对编码后目标。

零 gain、静音轨道及无音轨来源不进入应用集合。源文件、trim、时间、几何、音轨顺序、字幕等均保持。候选达标不保证 AAC 编码后的 LUFS/真峰值，也不表示 legacy s16 路径与浮点路径相同。

## 精确公共合同

输入仅有 `projectId`、`expectedRevision`、`requestId`、`mixProfile`、`measurementProfile`、`target`、`snapshotSha256`、`candidateDigest`。

- 混音与测量配置沿准备操作的固定字面值。
- `candidateDigest` 为 `timeline-loudness-candidate-v1:` 加 SHA-256。材料为版本化规范 JSON，包含完整严格准备报告，仅排除 `checkedAt`。客户端可用共享 `timelineLoudnessCandidateDigest` 计算；服务器独立重算。
- 不接受客户端 gains、任意路径/过滤器、时间租约、approved 或 report DTO。摘要只是内容绑定，不是秘密、权限或省略重测的凭证。
- ACK 为 `{operation,requestId,timeline,application}`。`application` 固定原/新版本、全部增益、目标、实际双测结果及预留 0.5 dB。
- 不改变任何旧操作 ACK。新 ACK 上限320 KiB，网络信封含任务意图/身份最多336 KiB；客户端默认125秒，服务器完整测量工作预算120秒，超时不承诺完成。

同键先查原回执，再考虑当前版本或媒体。相同请求在撤销、重启、工具失效之后仍返回原 ACK；同键异内容冲突。复用身份绝不生成第二条历史。结果未知保留原 requestId；网络断开/本地取消/125秒超时不是业务取消或未应用证明。

## 持久意图与恢复

界面沿原 `/api/tasks` 持久编辑通道：保存标量意图后才执行。开始应用前必须取得可信的稳定工作区恢复身份；缺失/阻挡时不创建请求，并提示修复连接后重新准备。摘要与确认等待期间身份变化会使确认失效。重启只读取/对账原记录，不自动重新计算或提交。prepared/dispatching/unknown 仍由原任务中心显式恢复，同一工作区、项目、操作、请求与输入摘要全部绑定。

本窗口发起后未确认的请求由固定原生关闭来源保留；普通 busy 结束、隐藏面板、切项目与 cleanup 均不是完成证明。只有原工作区/项目/操作/请求/完整输入/任务身份与新的终态 ACK 一致才解除；关闭最终读取只读缓存，不启动写入或计时器。新窗口重开后的历史任务仍由原持久任务中心读取，不把全部历史请求无限期当成新窗口草稿。

只允许事务确认回滚、未开始业务写、仍持有原 owner 且原回执不存在时，产生精确 `not_applied` 证明。来源变更、解码失败、未确认子进程退出、提交/回滚结果不明均不得伪装为确定拒绝。后置媒体异常不能把已成功提交改写为失败。

恢复副本：原25继续冻结；新27持有源26继承记录。所有继承应用状态和回执原样归档/held，仅允许严格历史读取，不允许新应用、自动执行或重试。历史读取仍核项目、当前时间线身份/版本与历史素材的数据库归属；不要求历史片段仍在当前时间线，不访问媒体文件或重新测量。
