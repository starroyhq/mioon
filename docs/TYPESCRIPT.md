## Development rule

New application/domain logic must be written in `.ts`; new browser components in `.tsx`. The incremental migration is complete, so the remaining legacy-JavaScript allowance is empty: any `.js`/`.jsx`/`.mjs`/`.cjs` runtime source path now fails the language guard. Do not hide a new feature's implementation inside a grandfathered JavaScript file to evade this rule. Migrate older modules incrementally in separately reviewed changes; runtime input validation, ownership, approval, replay and persistence checks remain mandatory.

The first actual migration was the dependency-free `packages/contracts/src/agent-protocol.ts`. The previous `.mjs` path explicitly re-exports the same two runtime symbols. The package barrel and public operations are unchanged. Erased executable equivalence and unchanged rejection cases are tested against the frozen baseline, rather than a hand-authored declaration that merely promises compatibility.

## Commands and checked surface

Run `node scripts/tooling.ts typecheck` or `pnpm typecheck`. All three fixed projects run serially with strict checking, no emit, no unchecked library skipping, and no caller-provided project/command flags. Each verified compiler child has a fixed 4096 MiB V8 old-space cap so the complete tests project can compile in Linux environments with a smaller Node default; V8 adds young-generation headroom. This does not accept caller `NODE_OPTIONS` or change runtime application memory settings. The standalone command does not require media, Electron, a workspace, settings or provider access. It never installs dependencies or falls back to a global compiler.

- `tests/typecheck/tsconfig.foundation.json`: all `.ts` under application/package `src` roots except browser/UI roots, plus `server/**/*.ts`, `scripts/**/*.ts`, the desktop build-config surface (`apps/desktop/*.ts`, `apps/desktop/scripts/**/*.ts`) and the actual protocol compatibility seams/compile consumers. Uses real Node24 declarations, ES2022 and DOM URL types.

Runtime `.mts`/`.cts` and TSX outside browser/UI fail explicitly because this configuration does not cover them. Symlinked source trees cannot silently evade the scan. Every remaining runtime application/package source module is TypeScript and covered by one of the three fixed projects; `skipLibCheck` stays off. New typed code must use checked leaf contracts or a genuinely checked narrow adapter.

## Runtime and packaging

Desktop bundles now trace the fixed local `createRequire(import.meta.url)` adapters through an AST-checked build transform. Packaging configuration is generated from typed source into the ignored `apps/desktop/.generated/` directory as described above; only those generated CJS files are loaded by electron-builder. The transform is limited to repository-owned business/contracts/server TypeScript leaves, rejects dynamic or escaped require calls, and keeps each relative literal at its original resolve directory. Source-level `unknown` validation and the exact legacy schema catalogs remain unchanged. A runtime test executes the resulting CJS outside the source tree and verifies ordinary48, explicit46, backup/restore47, and refusal by the ordinary/old42 openers. Native source execution still uses Node's normal local require semantics.

The repository's Node24 source workflow uses native type erasure for `.ts`, with explicit extensions and `import type`. The observed pnpm workspace symlinks resolve to real source paths outside `node_modules`; actual CLI/MCP entrypoints are tested. Node deliberately refuses native type stripping for TS physically inside `node_modules`. Publishing bare-TS npm packages or using `--preserve-symlinks` is not supported by this slice.

`erasableSyntaxOnly`, `verbatimModuleSyntax`, `isolatedModules` and explicit import extensions keep the supported syntax narrow. Runtime enums, parameter properties, namespaces with values, TS import aliases, decorators and path-alias-dependent imports are outside this source-runtime contract. Node ignores tsconfig and does not typecheck. Compiler success alone does not prove Node parser/runtime compatibility; real entrypoint tests remain required. Node cannot execute `.tsx` directly.

Vite and the existing esbuild Desktop build erase types into JavaScript. Electron receives ordinary bundled main/backend CJS and built web assets; it does not need the TypeScript compiler or raw application TS in its archive. React TSX is separately compiled/rendered against the installed React implementation. Existing UI wrapper provenance rules still apply when a future imported wrapper needs a type correction.
