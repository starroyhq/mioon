# 已导出文件响度检查（首片）

基线：`1829dd02a97f1cd433ce0ce5b99210550660a9fc`。本片已完成独立验收；实现合同、首次失败及最终完整门分别记录如下。

## 用户可用范围

导出记录中的“已导出文件响度检查”显式测量一个已成功发布的时间线 MP4。它显示完整实际文件的综合响度（LUFS）、解码样本峰值（dBFS）和估算真峰值（dBTP）。如果文件来自选区导出，结果只代表该选区文件；不是当前时间线或整部节目的证明。历史文件对应当时冻结的版本，即使当前时间线继续编辑，仍可检查原文件。

可选参考目标由用户填写：−60 至 −5 LUFS、−20 至 0 dBTP，两项均留空则只测量。范围是本应用首版限制，不是平台标准。没有默认 −14/−16/−23 LUFS，也没有默认广播或流媒体认证。结果中的建议只计算这份已测文件达到目标所需的固定增益及其与真峰值余量的冲突；不会降低目标来假装达标。

建议摘要直接标明“可用余量（已预留0.5 dB）”：参考上限减实测真峰值，再扣固定 0.5 dB 应用参考余量。它不是误差上限、编码器保证或安全认证。实际固定增益后必须重新测量；原来的绝对门控成员可能变化，AAC 编码、重采样或播放链也可能改变峰值。此片不改 gain、不限幅、不归一化、不重导出，不恢复源音频里已产生的失真。没有“应用”按钮或 mutation 权限。

## 固定测量配置

profile：`bs1770-5-48k-stereo-fir4x-v1`。完整自然 EOF 解码实际唯一 AAC、48 kHz、双声道音轨为原生 f32le，不重采样、downmix、限幅或截短。每个声道独立进行 K-weighting；综合响度使用完整 400 ms 块、100 ms 步进、绝对及相对门控。不足一个完整块的尾部不参加响度门控，仍必须完整解码且参与峰值检查。

纯 TS 实现使用 ITU-R BS.1770-5 的固定 48 kHz 系数和 Annex 2 四倍插值 FIR。真峰值包含原采样点峰值作为保守下限，结束时排空 FIR 尾部；补出的滤波尾部不增加解码帧数或响度门控时长。这是指定算法的估算，不是任意频带信号的精确连续峰值，也不宣称通过完整标准认证。现有 `timeline.export.samplePeak` 含义和响应不变；float-v2 导出的编码前样本峰值检查仍不是响度／真峰值检查。

特殊状态分别处理：

- `digital_silence`：全部有限采样精确为零；峰值对数为 `null`，显示 −∞，没有有限 LUFS 或增益建议。
- `too_short`：非零音频短于 400 ms；峰值仍可有效，综合响度不可用。
- `below_gate`：有非零信号但没有合格门控块；不能误称数字静音或把 −70 当有效响度。
- `valid`：完整信号有合格门控块，返回 integrated LUFS 与门控数量。
- 没有音轨、损坏、非有限采样、残缺字节帧、格式变化或预算超限不会产生成功测量／建议。无音轨不等于静音。

官方依据，核验日期 2026-10-14：

- [ITU-R BS.1770-5（2023），Annex 1/2](https://www.itu.int/dms_pubrec/itu-r/rec/bs/R-REC-BS.1770-5-202311-I!!PDF-E.pdf)
- [EBU Tech 3341（2023），门控、时标及测量定义](https://tech.ebu.ch/docs/tech/tech3341.pdf)
- [FFmpeg ebur128](https://ffmpeg.org/ffmpeg-filters.html#ebur128)：作为独立真实媒体对照，产品不解析其舍入摘要为精确算法输入。
- [FFmpeg loudnorm](https://ffmpeg.org/ffmpeg-filters.html#loudnorm)：其 linear 条件不满足时可切换动态处理，本片完全不调用该滤镜。

## 共享 API、CLI、MCP

`timeline.export.loudness` 输入严格限定：

```json
{"projectId":"11111111-1111-4111-8111-111111111111","exportId":"22222222-2222-4222-8222-222222222222","expectedArtifactSha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","measurementProfile":"bs1770-5-48k-stereo-fir4x-v1"}
```

示例 hash 是占位值，必须换成当前已核验输出资产的真实 SHA-256。可选 `target` 为 `{ "integratedLufs": -23, "truePeakCeilingDbtp": -1 }`；这只是自定义值示例。先用 `mioon schema timeline.export.loudness` 发现合同，再通过 `mioon timeline export loudness --input '<JSON>'` 或 MCP `timeline_export_loudness` 显式调用。这里的 CLI 命令沿用[连接指引](../skills/mioon/references/connection.md)指定的已运行服务，不能为检查启动第二个同工作区后端。

服务自行检查 SQL/JSON 项目归属、成功导出与原始不可变受理回执、固定 snapshot、输出资产及专属路径；调用者的 hash 只是期望值，不是已验证证明。准备前后核实际文件身份和两次完整 SHA，响应绑定 profile、实际文件 hash、snapshot hash、冻结 revision/name/range 和目标。返回路径、媒体字节、凭据、任意 filter/命令参数均不在合同内。

`readOnly:true, localProcess:true, fileWrite:false`：只读仍会消耗本机 CPU 和文件读取。单次上限 512 MiB 文件、600 秒、230,400,000 PCM bytes、两遍累计 1 GiB hash、总 120 秒、8 KiB 响应；client 默认 125 秒，显式更短 timeout 仍生效。门控统计最多 5997 个块，不保存整片 PCM。与样本峰值共用当前原生数据库身份的单活跃导出音频检查槽，不排队、不缓存、不自动重试。

取消只终止该观察，资源只有在精确子进程退出确认后释放；未确认退出继续失败关闭。失去观察者、切项目、隐藏历史、修改目标或重启不会自动测量，也不影响原导出任务或下载。恢复隔离工作区在输入解析／媒体访问前拒绝本操作；内置 Agent 工具目录不新增权限。
