## 先检查日常操作

1. 启动
   - doctor 检查通过，开发版构建成功；记录 nativeReadiness 仍未验证，不能以 doctor 退出 0 代替 Mac 通过
   - 使用明确工具路径或原生文件选择框后窗口正常显示工作区，FFmpeg 有 libx264/aac
   - 没有白屏、反复启动、隐私检查错误或意外密钥要求
   - 结果：未做

2. 素材和时间线
   - 确认没有复用旧数据或凭据，新建项目，导入一份试用图片或短视频
   - 加入时间线，修改一个属性并保存
   - 更新预览后能看到新的结果
   - 结果：未做

3. 导出和另存为
   - “交付检查”通过后明确“确认导出”，任务实际完成，再从结果的“下载”入口另存为
   - 原生另存为能选定位置，检查通过与导出完成分别记录
   - MP4 可在本机播放器打开，画面和预期声音正常；仅图片或无声素材不应期待声音
   - 取消一次另存为后仍能再次保存同一导出结果
   - 结果：未做

4. 重开和继续
   - 关闭最后一个窗口后，从 Dock 重新打开
   - Cmd+Q 完全退出，再从同一源码启动
   - 重新选择同一项目，素材、已保存片段和完成的导出仍在
   - 结果：未做

5. 本地模拟生成
   - 明确选择 Mock · simulated motion 的“正常完成”，提交一次任务；未配置或调用 Agent 模型
   - 得到带 SIMULATED MOCK 标记的可播放视频；这是无声模拟视频，不是真实 AI 生成
   - 可以选定该版本并加入时间线
   - 结果：未做

6. 任务中心与草稿
   - 打开“任务”，确认本地编辑、当前会话待确认请求和生成任务按实际状态显示
   - 请求列表加载失败不能显示为“没有待确认请求”，也不能继续受阻的编辑
   - 打开/关闭任务中心不丢失未保存属性草稿；不为首次试用故意制造中断或强杀
   - 结果：未做

## 宣称 Mac 桌面试用可用前还需工程验收

下面不是要求使用者自行诊断的清单。由验收人员在相同源码、同一架构的 Mac 上补齐：

- 核实实际 utilityProcess 的 Node/SQLite 版本、沙箱、权限拒绝和私有 discovery 文件
- 使用隔离试用项目检查本地 FFmpeg 导出进行中的正常退出、再次启动后的渲染恢复；确认直接持有的后端/媒体进程确实退出，且没有重复发布。这里的实际导出不涉及真实 AI 供应商
- 对十二类持久本地编辑的代表性恢复场景，记录原请求编号、完整参数及账本/领域回执；重建应用后发现同一请求，启动/列表读取不执行编辑，明确恢复后只产生一次业务变更。完整边界按 [TASK-RECOVERY.md](TASK-RECOVERY.md) 验收，不能把生成/导出等会话参数宣称为全面持久恢复
- 检查仍存活旧会话的明确转存不执行编辑；已丢失旧会话不推测重建，未确认结果不以新编号重提
- 验证 Application Support 的实际路径、原生 Save As、播放解码和单实例行为
- 验证旧数据/不安全目录遭拒绝时数据保持原样；不自动迁移、修权限、删除凭据或绕过 macOS 安全阻止。测试只使用合成副本，保留原数据
- 将本次 Mac 结果与精确源码清单和生成的构建文件哈希绑定

如果只完成浏览器入口，上述 Electron 桌面项保持未做。隐私存储拒绝不能靠浏览器入口绕过。Keychain 凭据持久化、强杀孤儿进程恢复、双架构安装包、签名、公证、升级和 Windows 仍是独立范围；本文不要求执行这些操作。
