# Interface languages

Mioon supports Simplified Chinese (`zh-Hans`), Traditional Chinese (`zh-Hant`), English (`en`) and Japanese (`ja`). Traditional Chinese is one region-neutral application locale, labelled **繁體中文**; there are no Taiwan/Hong Kong resource variants.

The language control is available in project, editor and connection-settings headers. **System default** resolves the operating system/browser language, including Chinese script/region input, and falls back to English when no supported language is available. A manual choice takes precedence.

## Preference and content boundaries

- Desktop uses a separate private, atomic `app-preferences.json`; web-only mode uses `mioon.app-language.v1` in site storage. Language preference is not project data and is not added to backups, tasks or receipts.
- Switching language updates the mounted interface. It does not save forms, submit requests, approve confirmations, clear drafts or rename existing content.
- Project/shot/clip/track names, prompts, subtitles, model output, paths, IDs, hashes and frozen workflow data remain exactly as supplied. A localized default name becomes ordinary user data when created.
- Native app-owned menus, warnings, chooser titles, primary buttons and filter labels follow the preference. OS-owned file chooser navigation, Cancel/overwrite controls and system services remain native OS UI.
- A failed preference read/save is shown explicitly. The selected language may apply only to the current session/window; it is not reported as durably saved.

## Adding or changing UI copy

Use a semantic key and a complete four-locale entry in `packages/i18n/src/catalogs`. Use typed `message()` descriptors for pending notices and confirmations, and translate at render time. Do not store resolved translations in controller identity, request payloads or durable history. Do not use source-language error text as a branch condition or translation key.

Use complete `one`/`other` templates for English count-dependent phrases. Both branches and every locale must retain matching placeholders. Unknown errors require a safe localized summary, with unchanged original diagnostics only under an explicit diagnostic label when shown.

Run the catalog/IPC/state tests and `node scripts/audit-ui-localization.mjs`. The AST guard rejects new CJK source literals, static visible JSX prose, unreviewed exceptions, duplicate approvals and stale allowances. Each checked-in exception names its exact display boundary or invariant technical token. Passing this guard is not semantic or visual acceptance: dynamic helper consumers, safety meaning, pending-state switching, narrow/expanded layouts and real native persistence still require review.

CLI/MCP human-readable help uses the opt-in compatibility boundary described below. Machine schemas, command names, JSON, IDs, statuses, outcomes, retryability and receipts are not translated.

## CLI and MCP presentation language

Both entry points accept an invocation-only `--locale zh-Hans|zh-Hant|en|ja`
(or `--locale=ja`). For example: `pnpm cli --locale zh-Hant --help`, or
`pnpm mcp --locale ja`. Traditional Chinese remains region-neutral 繁體中文.
The option is not an RPC/tool argument. MCP fixes it at process launch; CLI
fixes it for that invocation. It never saves a preference, consults OS/environment
language settings, changes workspace identity, or submits/replays an operation.

Omitting `--locale` deliberately preserves legacy output, including mixed-language
MCP descriptions. Explicit `--locale en` selects English prose. Default CLI help
is preserved byte-for-byte; the extra locale option description appears in
explicitly localized help and is documented here for legacy callers.

Only CLI help option/connection/safety prose, owned argument-parser stderr, MCP
`tools/list` descriptions, and initialization instructions are localized.
CLI usage syntax, JSON keys/envelopes, identifiers, operation names, JSON Schema
(including embedded descriptions), effect annotations, schema discovery results,
call results, error messages in stdout JSON, receipts and exit codes are unchanged.
CLI stderr for other errors shows a localized safe summary and a labelled,
unchanged sanitized original diagnostic; arbitrary backend or user text is never
interpreted as a translation key. Parser diagnostics follow the locale once its
valid option has been parsed; errors before that option retain legacy English.
Invalid locale values are rejected before any connection or action.

Changing a launch option requires a new invocation; it does not authorize
re-running an effectful command. Keep the same request identity and frozen input
when explicitly recovering an uncertain request.

MCP launch and transport diagnostics remain English in this phase, including
invalid workspace-origin errors with an explicit locale. The separate backup
command and development/doctor scripts are outside this presentation phase.
See `i18n-coverage-cli-mcp.md` for the validation boundaries and compatibility record.
