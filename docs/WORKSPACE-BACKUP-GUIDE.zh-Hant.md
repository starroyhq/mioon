# 工作區離線備份操作指南

此入口處理整個工作區，不只目前專案。SQLite 會原樣儲存所有專案、聊天、提示詞、工作、回執、歷史及資料庫內的波形快取。這些是私密的未加密資料：應用程式金鑰、連線權杖及設定檔不會複製，但使用者自行寫入提示詞或聊天的敏感內容，仍會隨資料庫儲存。

已提供離線建立、驗證，以及下文的「安全還原至新的獨立工作區」。還原僅接受受支援的原始備份，不能覆寫既有工作區；還原分支允許新的本機匯入、編輯、預覽及匯出，繼承的工作與核准保持歷史狀態，不會重新執行。還原分支暫時無法再次建立備份，必須保留原始備份。所有步驟均在本機進行，不會呼叫服務商或自動重新提交工作。

## 使用順序

1. 在右側屬性面板展開「工作區備份」，視需要讀取資料庫計數。此讀取不會檢查媒體檔案，也不代表冷備份已就緒。
2. 正常關閉 Mioon，以及使用相同工作區的 Web/CLI 後端。不要刪除鎖定檔、WAL 或 journal，藉此強行通過檢查。
3. 在具備專案鎖定版本相依套件及 Node24+ 的原始碼目錄執行：

   `node apps/cli/src/backup.mjs create --source /absolute/workspace --destination /absolute/new-backup`

   source 是既有的 Mioon 工作區；destination 必須是全新且與來源互不包含的私有目錄。不要把使用者的素材資料夾當作工作區。路徑僅在本機使用，不會傳送至後端或模型。
4. 驗證：`node apps/cli/src/backup.mjs verify --directory /absolute/new-backup`。
5. 僅在命令成功、完整標記與全部檔案重新驗證一致後，才能稱為已驗證的備份。仍不可據此宣稱已還原，或允許舊的付費工作重新執行。

預設 desktop 工作區位置及版本通道差異，請參閱 [DESKTOP.md](DESKTOP.md)。自訂啟動目錄以原有啟動設定為準；本工具不會猜測或切換目錄。

## 範圍與上限

- 固定版本目錄：manifest.json、最後發布的 COMPLETE.json，以及 payload 中的原始 SQLite、已登記媒體及已知工作的暫存／未提交結果。
- 資料庫最多 512MiB；單一檔案 8GiB；總 payload 64GiB；最多 20,000 個檔案；manifest 8MiB；單一串流區塊 1MiB；最多顯示 100 項問題。上限不代表保證有足夠的可用磁碟空間。
- 不會複製應用程式 credential/settings、連線權杖、瀏覽器資料、獨立快取目錄，或無法確認歸屬的未知檔案。資料庫內既有的快取資料列會保留。
- 缺失媒體、部分結果、未知工作及排除項目均會明確記錄；驗證備份檔案完整，不代表來源專案原本沒有問題。
- 既有 Windows 儲存安全檢查仍未通過原生驗收。首版依既有且受支援的 POSIX 私有目錄策略運作，不會修改既有權限。

## 檔案完整性與取消

建立備份會原樣複製關閉後的 SQLite。SQL 檢查僅在新建的私有暫存副本中進行，不會開啟或遷移來源資料庫。驗證也使用備份父目錄下的私有暫存副本，因此目前使用者必須可寫入該父目錄；來源及已完成的 payload 不會被 SQL 開啟。額外暫存空間最高為 512MiB 資料庫副本，加上最多三個 64MiB SQLite sidecar，不包含在 64GiB payload 上限內。

同一工作區僅能由持有獨占鎖的一方擷取；遇到任何既有鎖，或非空的 WAL/journal，即會停止。工具不會自動判定舊鎖可以刪除。不會修復既有目錄權限，只會以 0700/0600 建立自己的新目錄與檔案。保護範圍針對其他系統帳號，不隔離相同使用者或 root 的惡意程序，也不保證硬體或檔案系統絕不遺失資料。

Ctrl+C/SIGTERM 會要求停止後續本機步驟，並等待已發出的檔案操作結束。這不是立即中斷核心 I/O 的硬性期限。中斷或失敗可能留下沒有完整標記的新目錄，請保留並檢查，不要覆寫或自動重試。若回傳的發布狀態無法確認，請保留該目錄並單獨執行 verify；僅存在 COMPLETE.json 不能證明備份完整。

成功結果若附帶 SOURCE_LOCK_RELEASE_UNCONFIRMED，表示備份本身已驗證，但工具無法確認是否已釋放自己的來源鎖。請保留備份及來源鎖，先核對原程序已結束；不要刪除鎖後自動重試。失敗結果若附帶 sourceLockRelease: unconfirmed，同樣不可視為清理已完成。

## 安全還原至新的獨立工作區

原始備份 format1/schema24 可使用獨立的離線還原命令：

```sh
node apps/cli/src/backup.mjs restore --directory /绝对路径/原始备份 --destination /绝对路径/新工作区
```

新目標的父目錄必須存在，目標本身必須不存在。不要選擇原工作區內部的位置。
工具僅檢查固定的祖先標記；format1 未儲存原始路徑，無法辨識所有重新命名的來源。
失敗或中斷後請保留目標，不要刪除鎖、覆寫或自動重試。
若整段 stdout 遺失，可進行唯讀檢查：

```sh
node apps/cli/src/backup.mjs restore-status --directory /绝对路径/原始备份 --destination /绝对路径/新工作区
```

observed_guarded 僅表示目前目標的固定 schema 與來源綁定符合原始備份；不證明上次命令成功或先前 fsync 已完成，也不會補發布、修復或執行工作。
開啟還原分支後，可開始新的本機匯入、編輯、預覽及匯出。繼承的工作、核准及未知結果保持歷史狀態並停止執行；新生成、Agent、Comfy、影格擷取及波形解碼暫時無法使用。
還原分支首版也無法再次建立備份，保留原始備份是必要條件。
Desktop 需要將目標放在新根目錄的 workspace 子目錄，並明確選擇新根目錄；不要複製舊的 token 或工作階段檔案。完整範圍、限制及驗證狀態，請參閱[安全還原說明](WORKSPACE-RESTORE.md)。
