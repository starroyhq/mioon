## 本片实际保存什么

普通工作区的交付面板增加两种不同记录，不能混为通用草稿或通用任务台账：

1. 名称草稿：只保存 `raw.deliveryName` 原始字符串、草稿身份、原时间线ID/revision和更新时间。最多512个UTF-16码元，要求有效Unicode；空串、空白、控制字符及超过业务名称120码元的未完成输入仍可作为有界草稿保存，不裁剪、不修正。名称真正用于导出时仍须通过既有 `timeline.render` 名称校验。空串导出保留既有省略 `deliveryName` 的语义。
2. 原导出意图：用户明确确认导出后，单独冻结完整的既有 `timeline.render` 输入，固定 `purpose:'export'`，包括原 `requestId`、项目/revision、可选名称、可选闭合输出规格和可选 `preflightSnapshotHash`；同时保存时间线身份及本次捕获的精确草稿版本。可选字段的省略不改成默认值或 `null`。这不是可编辑的输出规格草稿，也不保存预检查报告或完整业务回执副本。

本片不增加镜头提示词、字幕、模型/Agent输入、生成任务或其他表单自动保存；不处理预览请求。原公共 `timeline.render` 合同、RPC/CLI/MCP和内置Agent工具目录均不扩张。它只为第一方renderer的既有本地导出提供固定私有边界。

## 存储、容量与隐私

- 固定私有旁文件 `local-delivery-v1.json`，格式版本1；不迁移业务SQLite，不增加业务表、历史、导出或回执字段。每个项目保留一个槽，槽内有独立的名称 `draftRevision` 和意图 `intentRevision`，最多一个当前名称草稿、一个最新原导出意图。
- 最多128个槽，单槽序列化最多8192字节，完整文件最多2MiB。这些是各自独立的逻辑上限，不是物理磁盘配额、可保证用满的容量或所有历史可无限保存的承诺。原始名称的512码元上限另计。
- 清除名称后保留revision墓碑，仍占一个槽；不自动淘汰、重置revision或释放槽。最新意图身份也不随名称清除而删除；只有已有意图确定终态且精确CAS匹配后，才能准备下一次新意图。没有本片记录压缩/批量清理功能，容量耗尽明确拒绝。
- 复用私有目录/文件验证、symlink拒绝、有界原子写入和现有独占工作区锁。作用域由后端根据可信渠道、实际工作区目录与SQLite文件身份计算，不由renderer传入路径建立，也不依赖动态HTTP端口。每次服务实例另有nonce；旧实例写入不能直接重用。
- 同步本地CAS、全文件读摘要核对、文件原子发布和父目录持久化确认共同约束写入。它不是新分布式锁，不能隔离同一系统用户的恶意进程，也不承诺消除路径式存储的一切TOCTOU。
- 文件是私有权限保护的本地明文，不是加密保险库。严格字段白名单没有密码、API密钥、令牌、认证配置、媒体字节、任意文件路径或任意操作名；用户在名称中自行写入的敏感文本仍是私密内容。名称删除不保证已捕获在最新意图里的同一文本也被删除。
- 既有离线备份载荷仅包含规定的业务库、媒体和受支持暂存内容，不包含此旁文件；不能把工作区备份说成名称草稿或本片意图备份。恢复分支直接返回 `RESTORED_WORKSPACE_UNSUPPORTED`，不读写原旁文件，仍保留既有明确确认的本机导出流程。
- GET只读且不创建文件。损坏UTF-8/JSON、未知格式、不安全文件、不可读或外来作用域失败关闭，不静默清空后重建。最后尚未确认保存的输入可能丢失；突然断电、损坏硬件和逐按键零丢失均不在承诺中。

## 名称恢复和明确选择

名称输入默认250毫秒去抖保存。界面显示保存中、已保存、保存失败/暂停和可恢复名称；已有关闭等待接入名称flush，但不能把有限等待说成每次崩溃都已落盘。

重开读取记录只显示候选名称、原时间线/revision和时间。用户可明确恢复名称到表单、保留当前名称替换已保存草稿，或放弃已保存名称；不操作则继续保留。恢复名称本身不导出、不检查媒体、不调用模型，也不把输出规格恢复为原意图里的规格。

名称仍绑定原基线；当前时间线不同会显示冲突。明确“改用于当前时间线”会先精确清除旧基线草稿，再用新身份保存当前输入，失败或迟到删除不授权改基线。名称草稿和原意图的目标状态分别报告，较新名称不能掩盖旧意图。

草稿保存失败后自动写入暂停。界面区分本地校验拒绝、服务明确拒绝、CAS/身份冲突和网络/响应未知；只读核对不能释放未知写入、启动重试或自行恢复暂停。空GET不能证明旧PUT没有发生。明确拒绝时可选择允许离开而不保存当前名称，当前输入仍保留至离开；这不会取消或删除原导出意图。未知结果不能借此伪装为已清除。

用户可另行明确重试名称保存。未知PUT保留原 `draftId`、原 `expectedDraftRevision`、原基线和原名称；重试先只读核对相同工作区，只采用当前服务实例nonce，然后重交同一原PUT，不能改用较新表单或当前草稿CAS。即使GET已看见原记录，仍须验证该原PUT的精确确认；后来的明确拒绝也不能否定较早未知写入。若原PUT确认后表单已有新名称，仍暂停较新输入的自动写入，要求再明确保存当前名称。另一窗口已有较新版本时保留冲突。

本地超过512码元或无效Unicode会在发送前被明确拒绝，允许修改输入后明确保存；已知服务拒绝也可明确重试当前输入。该动作不默许覆盖新发现的候选草稿或改变原基线，需要先选择恢复/替换。失败DELETE不被当成可重放的PUT。

## 两阶段导出与原键恢复

1. 用户通过原交付检查/明确确认流程发起导出。renderer先保存对应名称，再以独立意图CAS准备固定原输入。`prepare`必须完成旁文件原子发布、读回核对和父目录持久化确认，才返回可执行的准备结果；本阶段不调用渲染。
2. renderer验证准备回应与原输入完全一致，并再次核对当前项目、名称、时间线、输出规格/导航捕获和面板可执行状态。只有仍匹配时才单独调用 `execute`。若用户已改输入、切换项目/面板或确认未知，保留原意图而不因晚到prepare回应自动提交。
3. 后端执行只接受意图身份及revision，先核原持久记录和原回执。没有可验证回执时，才调用固定 `services.call('timeline.render', originalInput)`；没有任意operation、替换input或renderer提交outcome的入口。同项目相同意图的重叠执行共享一次在途调用，其他意图冲突。
4. 启动、重连、读记录、打开面板和恢复名称都不执行原意图。用户明确“确认恢复同一原请求”才可继续；它可能首次执行之前只准备而未提交的导出，界面须明确说明。恢复只用原键、原名称、原revision及原可选规格/检查摘要，不按当前表单重建请求。 此处只禁止启动时dispatch仅prepare的待定意图；已接受的queued/running导出仍沿用既有本地render worker对同一任务的重启恢复语义。
5. prepare确认丢失时保留原prepare输入；只读核对为空也保留不确定性。显式恢复可重新确认同一prepare，保留原业务输入与CAS，仅允许在已核定相同工作区后采用新服务实例nonce；不得通过刷新业务revision、换意图ID或换requestId绕过冲突。尚未真正发布的prepare只存在于原renderer内存，不能宣称该未持久窗口跨进程可恢复。

跨窗口限制：原prepare尚未得到确认且没有发现对应持久意图时，另一窗口可能已改变名称草稿。此时重做原prepare仍使用捕获的原 `draftId`、`draftRevision` 和原输入；若已不匹配，保守保持冲突，不把当前草稿CAS替换进原请求，也不自动创建新意图。这个状态不保证自动解围。若准确原意图已经持久化，则显式恢复可继续原意图；较新的独立名称草稿不能被它清除。

## 接受、确定未应用与未知

`accepted`表示既有业务服务已接受并留下严格匹配的原始 `queued` 回执，不等于FFmpeg完成或媒体已经通过解码。后端使用既有请求hash、项目/时间线归属及响应校验器验证原回执，旁文件只保存导出ID、回执摘要和解决时间。重新恢复已经接受的意图返回同一历史回执，不提交第二次导出。

`not_applied`只能来自针对原输入的既有 `hasRequestNotAppliedProof` 权威拒绝判定，并在记录终态前再次确认原回执不存在。它保存允许的证明代码及时间；读取终态时继续验证其证明语义与回执缺席。这个终态是永久的原意图结论：后来时间线恢复原revision、规格再次可用或用户反复恢复，都不会重试该意图。用户核对并重新检查后，可按当前终态身份/revision显式准备新的请求。

通用4xx/5xx、鉴权失败、损坏回应、超时/断连、缺少回执或持久化确认不完整都不是上述业务证明。结果不能确定时保留 `pending` 或确认未知，阻止新的导出意图。终态写入发生目录确认故障时，本实例对外保守显示待确认；显式恢复再次核对原记录与回执，不能把不完整确认冒充成功。

接受后只清除该意图捕获的、当前仍精确匹配的名称草稿：身份、草稿revision、原时间线/revision和原输入须同时一致。新输入、另一窗口或晚到回应都不能清除较新名称。恢复旧意图也不会把当前表单的新名称标成已导出。

## 私有HTTP边界

见 [API.md的私有交付边界](API.md#private-delivery-name-drafts-and-export-intents) 和严格合同 [local-delivery.ts](../packages/contracts/src/local-delivery.ts)。路由全部经过原Host/Origin及本地身份验证；读写为 `no-store`。

- `GET /api/local-delivery?projectId=…`：只读发现；没有项目列表或任意路径输入。
- `PUT /api/local-delivery/draft`、`DELETE /api/local-delivery/draft`：名称草稿独立精确CAS。
- `POST /api/local-delivery/prepare`：保存固定不可变原意图，不执行。
- `POST /api/local-delivery/execute`、`POST /api/local-delivery/recover`：仅按已保存意图身份执行/核对原请求；均须用户明确动作。

URL最多2048字节，JSON请求体最多12KiB；普通状态合同最多12KiB，原render回应最多4MiB，组合执行回应最多4MiB加12KiB。私有HTTP层最终还检查带 `ok/data` 包装的输出上限。renderer按流读取并限制完整响应字节：普通请求12KiB，execute/recover为4MiB加12KiB；拒绝超限/异常长度与无效UTF-8，不用替换字符修复后接受。整个传输默认期限为普通请求10秒、execute/recover 35秒，包含等待响应体；超时只中断HTTP传输，不取消后端保存或渲染，也不证明未应用，仍归类为未知并保留原请求。
