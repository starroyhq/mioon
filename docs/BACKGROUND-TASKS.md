# 后台任务：S3-A

0.1.0 的后台任务索引让项目窗口关闭后仍可继续执行，并在应用下次启动时恢复。任务和原供应商身份、冻结输入、回执仍在本机 `history.db`，应用库只保留调度目录，不复制执行权威。

## 应用库与索引

应用库格式为4。仅精确已知的3可窄升级到4；旧索引JSON及其他表数据保留，新增阶段/原因/来源/修订标量按旧格式默认解释。未知或改动过的结构拒绝；旧1/2的历史升级函数和冻结件保留供验证，不作为当前opener升级到4的生产通道。project/history/cache仍为3/9/2。

`background_task_index` 每条包含项目和任务身份、路径线索、`phase`、原因码、`sourceHistory`、索引修订及原任务修订。phase为prepared、active、blocked、archived或done，不替换领域status。键包含history代际；同taskId的另一份history不能覆盖旧归档。索引最多全应用4096、单项目512条，不是无限任务历史；原项目队列和资源上限不变。

容量在项目COMMIT前做只读预检，按同事务的最终任务集合计算，不预写prepared或应用数据；这样不会先提交超过上限的任务，再使补登永久失败。

接受任务的项目事务真正COMMIT以后，同步更新应用索引；回滚和只读事务不发布任务通知。若项目已提交而索引确认失败，返回503 `BACKGROUND_TASK_INDEX_UNCERTAIN`，详情为`mutationOutcome:'unknown'`。原任务与回执仍在，不可据此另发生成；重读原请求或重新打开项目检查。尚未结束的任务在运行时投影中暂停为索引确认不明，实际回调排空后释放 S3 租约，不把“已无执行者但领域行仍运行中”误当永久后台工作。普通到期查询不自行清除该暂停。

项目COMMIT与索引更新之间仍有小的崩溃窗口：首次关闭前被强杀的项目可能尚未出现在应用索引里。此时重启不会凭空发现它，用户下次打开后按真实未结束任务补登。关闭时继续整项目更新索引，保留旧代际archived条目。没有提交前证据链或新的项目状态表。

## 租约和任务状态

正常打开的顺序为V2备份、S3补登及自己的task租约/激活、每日版本。S3使用固定opening接缝，不在afterOpen中重新await打开同一项目。每个项目只持有S3自己的一条task租约，不释放原生音频等模块的租约。

Mio 的暂停/预算只阻止新的派发；已受理任务沿原供应商 ID 继续只读轮询/对账，不重复消耗审批。历史未知任务可在启动或显式 nextPollAt=0 时尝试一次原请求对账，无结果且无自动恢复能力就回到不保活；原权威派发、写结果和审计门禁仍由领域执行器校验。

七类任务由同一投影解释：jobs、exports、edit_tasks、image_tasks、frame_tasks、scene_tasks、subject_variant_batches。投影区分在跑、远端未知、结果待写、等用户和终态；例如edit prepared不自动执行，subject batch active不等于永久运行，图片未知结果不重新POST。

状态变化按任务ID更新缓存和索引；有界到期检查只核已纳管任务及打开项目的文件身份，不每秒扫七张表或不断重开失败项目。真实在途回调和finally尚未结束时继续保活。worker 对深层归属、冻结输入或回执明确拒绝的已纳管任务，在事务外按原 ID 重读确认后，将投影记为 `BACKGROUND_TASK_INVALID` 等用户处理；原行和回执不改。事务回滚、后来的有效行及审计/存储读取异常都不能被当作坏行发布，避免无执行者却永久持库。只剩等待用户、源位置或不可自动对账的原因时，原因落blocked并释放S3租约，记录仍算未结束工作。

重启后`manager.restore()`的租约和failures全部交S3；找不到、只读、被锁等情况保留索引及安全原因，不静默忽略。关闭窗口和退出应用不同：关闭窗口可继续，退出后本机进程停止，下次启动才恢复；远端任务可能继续。

## 项目不可用与V5

项目文件中途消失、被替换、只读或源不可用时，任务暂停、索引blocked，不把宿主故障改写成任务失败，不在旧路径创建空项目。原任务留在本机history；找回原项目后由各领域原有的对账/恢复逻辑继续。submitting先转unknown再对账，不能盲目重提。一次性请求没有原供应商查询能力时仍可能保持unknown。

0.1.0不做离线应用接收器、结果收件箱回填或弃置。项目离线太久可能超过供应商保留期，结果无法取回；不会自动重新付费生成。S3-B/C已定放0.1.x，首页“任务在等项目”的具体文案由后续界面接线提供。

V5分叉不建普通运行时。continue/restore后旧history代际的索引变archived，不删除、不注入新history；旧远端任务的本机等待就此放弃，不表示供应商已取消。重复确认或崩溃恢复只处理原代际，不能归档新history里的任务。

## 查询和生命周期门禁

应用内部`inspectProjectWork`对关闭项目读索引，对打开项目加统一任务投影和真实在途计数；blocked/unknown不能当作没有工作。原有inbox占位记录仍只读计入门禁，本卡不扩展其格式或提供结果能力。

`LocalRecordsStore.delete`在服务端删除边界检查未结束任务，存在则`LOCAL_RECORDS_IN_USE`；原项目找到/打开与有效super-journal保护继续保留。S5-C和S6 D6后续复用同一查询；0.1.0没有放弃结果动作，失踪项目仍有未结束任务就不能从最近项目移除。

首页数据为认证应用接口`GET /api/background-tasks`：只返回项目打不开且有未结束任务的项目ID、计数和安全原因码，支持有限游标分页。不打开项目，不返回任务原文、供应商URL、密钥或本机路径，不增加RPC、CLI、MCP工具。HTTP详情见[API](API.md)。

本卡只限制索引条数。跨项目运行槽、公平调度、离线媒体暂存预算，以及历史/LUT/Mio存量全局硬限留0.1.x或另卡；不把各项目已有配额改成全应用合计。

签名包Q验收仍需S6真实桌面窗口接线：关窗口后完成、项目盘不可用后找回、正常退出及强退重启。开发版和测试window lease不能替代已签名、公证的macOS包验收。
