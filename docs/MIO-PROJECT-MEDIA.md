# Mio 项目工作目录：列表与引用导入（R3-A/B）

Mio 的工作目录固定为当前原生宿主的 `store.projectDir`。提供 `mioon_project_media_list`（内部 `project.media.list`，`read_only`）和
`mioon_asset_import_project_file`（内部 `asset.importProjectFile`，`local_reversible`），
均位于 `assets` 非核心组。先按确切名称加载，后续模型回复才能使用。
没有新增 HTTP、RPC、CLI 或外部目录批准；不提供源文件修改或通用文件管理入口。

## 参数和结果

独立叶契约为 `@mioon/contracts/mio-project-media`。严格输入为
`{directory?: string, limit?: integer, cursor?: string}`；不接受项目 ID、绝对路径、
requestId、批准标志、探测开关或文件系统 adapter。目录省略或空串表示项目根。

结果为 `{directory, entries, nextCursor, truncated}`，只含相对目录和一层条目：

| 字段 | 内容 |
| --- | --- |
| `name` | 单个可见条目名 |
| `kind` | `folder`、`image`、`audio`、`video` |
| `mimeType` | S1 支持的八种 MIME，文件夹为 null |
| `sizeBytes` | 安全整数，文件夹为 null |
| `durationSeconds` | 秒；图像、文件夹、探测失败或超时为 null |

默认每页 50 条、最多 100 条，完整 JSON 最多 16 KiB；路径最多 4096 UTF-8 字节，
cursor 最多 2048 字符。文件夹优先，再按 Unicode 码点排序。单目录最多扫描 5000
条，不递归。超出扫描上限时明确 `truncated: true`，最后不伪造可继续的 cursor。
分页先保留序列化预算，再探测当前页；不会探测后又因字节预算丢弃条目。

cursor 是版本化、不透明的位置，绑定项目、相对目录、私有发布状态版本、目录身份、
目录时间和扫描快照。每页仍重新验证所有边界；目录变化报重读，cursor 不构成权限。

## 文件和生命周期边界

先检查路径原始拼写，再解析真实路径。拒绝绝对路径、盘符、UNC/设备路径、反斜线、
空段、点前缀段、父目录、控制字符、未配对代理项、ADS 和设备保留名。
不 URL 解码，不用 Unicode 归一化或大小写折叠授予访问。项目内的符号链接只能到
同一真实项目内的可见目录；即使用户批准过外部位置，也不能借本工具越过项目根。

点条目在生产枚举中排除。每次打开候选前重新用 lstat 的 dev/ino 查询内核和应用库的
真实 held registry，项目、history、cache、应用库的硬链接都不能打开。
宿主还显式提供应用 data/cache/temp 三个全局私有根，不能从当前项目的 cacheDir 猜
其他项目的缓存位置。位于项目内的私有根不显示、不能导航，内部符号链接也不能绕过；
项目 local/cache/temp 同样保护，私有根身份在每轮围栏重验，移走或替换即失败关闭。
应用 dataDir 若是项目根的严格上级，仍保留默认 dataDir/projects 下当前项目的正常目录，
不会把整个默认项目误禁；私有根恰等于项目根则拒绝列表。私有范围只由宿主注入。
宿主端口绑定 exact store、项目行和物理项目文件/目录身份；取消、关闭、移动、替换
及异步迟到结果都受同一围栏检查。失败时等已经启动的探测结束再返回。

扩展名只筛选候选，类型由 L1 最多 1024 字节文件头检查确认。仅对当前页的音视频
调用 L1 ffprobe，沿用 15 秒和全局最多 4 个探测；失败填 null，不估算。
列表不解码画面/采样音频、不读全文、不算哈希、不提供媒体字节、不写缓存。

登记值只有在登记时的文件身份、大小、mtime 全部可证明一致时才能复用。当前 S1
持久引用没有登记时的 dev/ino，生产宿主不会凭路径、大小和 mtime 冒认身份，因此
目前已登记音视频也走有界探测。底层可信注册证明回调覆盖免探测分支，不扩大模型输入。
S2 本机回执虽有身份，本版仅用于发布状态过滤，尚不把它接成时长复用缓存；
S2 已登记音视频同样由当前页的有界探测取得时长。

## 未发布文件：只读且保守

读取当前项目私有 `asset-imports` 回执时限制版本、owner/项目、文件名、相对目标、
单文件 32 KiB、总量 1 MiB、回执数 256，并校验私有目录与文件身份。
不存在的回执目录不创建；列表不恢复、重试、删除任何回执或目标。

S1 v1 回执只保存最后一次尝试路径，没有目标 dev/ino。对于仍存在而无法证明身份的
未发布尝试，整次列表拒绝；不会仅凭同名把用户文件藏起来，也不会把 partial 当候选。
`registered` 终态保留已完成的历史事实，不钉住当前资产行或旧文件元信息。合法重链接、
懒补完整哈希、文件变化或登记行移除后，当前文件仍交 L1 按普通候选重新检查；
可能拥有发布目标的 `prepared` 尚缺完成证据时仍要求精确的当前登记证明；纯路径引用准备的例外见下文。较早遗留尝试仍须保守核对。损坏、未知、超预算
或无法可信定位的回执同样拒绝列表。该策略没有改写 S1 回执格式或新增持久化状态。
无本机回执的跨机副本仍可能把 partial 当作普通未引用候选；列表不声称它已发布。

S2 合入后，宿主同时读取私有 `publications`，覆盖 `生成/`、`导出/`、`素材/` 的
普通发布、索引和导出恢复回执。两个快照的版本都绑定到 cursor，每次效果前同时重验；
列表不调用发布、完整内容查证或恢复接口，不修改 S2 的持久协议。

publication 查询最多接受 256 个发布、1024 个目录条目；普通及 restore 回执各最多
32 KiB、key 索引最多 4 KiB，全部文件合计最多 1 MiB。每次打开私有文件前检查
四类持有库，校验两遍字节及文件身份，严格核对 owner、项目、key 与 proof。
目标只做 lstat/真实路径和身份检查，不读取 stage 或目标媒体内容。
有效 key-only 预留尚不指向目标，不能据它猜文件名或称文件已发布；缺失的 intent
以及首次 restore 回执纳入快照重验，后续出现即要求重读。

已知未发布目标只有在本机 root、类别目录与目标 inode 身份可证明时才排除；无法证明
的现存目标、旧尝试残留、坏或超量回执使整次列表拒绝，不按文件名隐藏用户文件。
已保存的未完成目标身份也排除其项目内硬链接和移动后的别名；原目标路径消失不能
抹掉这份身份证据。copy intent 尚无目标身份时，不能证明文件是否已创建后移走，
因此保守拒绝；link intent 可用已保存的 stage 身份排除别名。
`prepared` 只有目标身份、大小、最终时间与精确登记证明共同成立才可见，不能仅凭
阶段名或资产行存在放行。导出恢复回执优先约束其目标，已有资产行不能放行复制中的
partial；完成的 prepared 恢复与普通 DB 已提交、registered 确认前窗口分别核验。
`registered` 是已完成的历史事实，后续重指向、文件变化或登记删除仍交当前 L1 检查。
没有回执的用户 `media/` 和普通媒体继续可导航，不被猜作发布文件。
私有发布路径按 S2 的安全定位规则核对，允许真实 producer 保留的 DEL/C1 字符；
这些名字由 Mio 现有可见条目规则跳过，不使其他合法媒体的列表失效。

## 来源准入和记录重拼

旧 `groups` 加载收据继续恢复原工具，但不会获得本次新增的文件系统工具。
只有已完成、输入与结果匹配的 `names` 收据能加载这两个工具；旧冻结 schema、同一回复内
加载后立即调用、未知或伪造回执都不能绕过来源门槛。诊断目录保持不变。

列表结果作为普通 tool-result 记录冻结。纯装配器只读记录；清成功请求原件、关库再开、
目录后来变化或消失，都不能让重拼重新扫描目录、探测文件或读取实时回执。

## 实测和请求指纹

50 个有效 1 秒 MP4（每个 12199 字节），Darwin arm64、Node 24.21.0、ffprobe 9.0.2：
完整生产宿主使用 exact store、真实应用库、六个私有根围栏、S1/S2 双快照和默认 L1 探测。
以下两组使用同版源码；已暂停本卡其他检查，未隔离机器上其他进程。

| 本机发布回执 | 首次 / 第二轮 | 结果字节 | 项目 / 应用 total_changes |
| --- | --- | --- | --- |
| 0 | 2720.868 / 2653.994 ms | 5070 B | 10→10 / 1→1 |
| 50 个发布，100 份 JSON，共 78750 B | 3780.292 / 3790.993 ms | 8970 B | 310→310 / 1→1 |

50 份发布由真实 publish、登记事务和 registered 收尾产生，较长的生产文件名使结果字节增加。
两组每轮均返回 50 条、启动 50 次 ffprobe，时长全为 1 秒；失败、超时、登记时长复用
均为 0，没有下一页或截断，两连接已关闭。这仅覆盖 0/50 份回执，不代表 256 份上限的成本。
首次指进程首次列表，未清操作系统页缓存；夹具预先生成，生成和登记不属于列表操作。

R3-A 分阶段只公布列表名，loader 的 names 数从 91→92、maxItems 同步 +1。
99 条旧场景中，三协议各 29 条普通请求仅这两个位置变化，每条 +27 字节；各 4 条诊断
逐字节不变。逐条字节数、SHA256、JSON 路径见
[指纹核对记录](verification/mio-harness/R3-A-FINGERPRINTS.md)。R3-B 新增导入名的 99 条逐项核对见 [R3-B 指纹记录](verification/mio-harness/R3-B-FINGERPRINTS.md)。


## 项目内文件引用导入（R3-B）

严格叶契约为 `@mioon/contracts/mio-project-import`：输入 `{path, name?}`，只接可见项目内
相对文件，名称沿用 S1 校验；不接项目、请求、资产 ID、绝对路径、字节或批准标志。
结果 `{registration: 'created'|'reused', assetId, asset}` 使用 S1 脱敏素材 DTO，不含私有证明。
该工具按既有本地可撤销 direct/ask 策略执行；旧 group、旧冻结 schema 和同批调用不增权。

路径和列表共用 exact native project、应用与项目私有根围栏；效果前仍重新校验词法、
真实路径、四库 held 和已知未发布 inode，项目外即使另有目录确认也拒绝。
S1 路径分支负责文件头、解码流有效性、图像/音频全哈希、视频采样及素材行登记；
本工具不另写 importer，不复制源文件，也不运行自动确认项目外路径的 trusted chooser。

审批前使用 S1 共用准备流程冻结当前项目与源文件身份、大小、纳秒时间、引用指纹和
解码元信息，私有证明存入 step.data 并纳入审批摘要。批准、恢复时不能覆盖原证明；
文件被替换、同 inode 改内容后还原 mtime 也拒绝。它不是模型参数，也不进入公开快照或请求正文。
耗时准备在登记事务外，登记前及每个异步效果都重验生命周期和源证明。

S1 事务内的 created-only 回调只产生一条 asset Change，和素材行、工具完成记录同连接
同事务提交。复用原请求只返回 `reused`，不补造新增或撤销权。同一个文件用不同 requestId
仍沿 S1 创建不同登记；不按路径或相同内容另造去重规则。请求键固定为原 stepId，模型不能改键。

S1 原请求 lookup 只读私有回执和现有行/修订证据，不重读源媒体，不创建 writer。
UNKNOWN 只有查证 `not_applied` 才能按既有控制丢弃旧参数；`applied` 接受结果只授予
reused、零 Change；`retired` 保留原请求已被移除的历史，不能复活；坏、缺失关联或未知状态继续 UNKNOWN。
ACK 在数据库提交后失败时，只用已经持久完成的工具结果证明成功，不能把曾调用过内存回调当成功。

撤销在专用分支再次核对原 step/key、S1 创建证明、原始行摘要与创建修订及 claims。
改后还原、删除重建、任何版本推进都不再满足“未改过”。只删除那一行 assets，
不把 assets 加进通用补偿删除白名单，不删除源文件、回执、Mio 审计、缓存或修订 tombstone。
原路径请求在 registered 或目标修订证明曾提交后，若行已移除，公共 S1 原键重放同样拒绝重建。

零消费者证明同时检查真实本库/跨库 FK、当前内容、时间线前后历史和可恢复回执、
冻结生成/图像/抽帧/场景/导出来源、portable 派生素材、项目版本和仍可恢复的其他 Mio undo-before。
本次导入的 Change/step/result 与 S1 回执是审计，不自拦；真正可恢复的版本仍然检查。
坏、未知、缺少字段分类或超预算都不能当成“没有引用”。

依赖扫描预算：8192 行、32768 单元、单 JSON 4 MiB、累计 16 MiB、深度 64、节点 200000；
最多 64 个去重项目版本 blob、压缩累计 8 MiB，解压长度按已核验 raw 大小限制。
预览使用只读一致快照，实际删除在同一事务重验；围栏回调后再次查 claims/消费者。
单项 DELETE、Change reverted 和控制完成一起提交。整轮撤销仍逆序逐项提交，
每项保留控制进度；中断保留已撤项并将 pending 控制标 blocked，不声称整轮全批原子。

路径准备回滚可能保留 `prepared/attempt=0/无file/无publication` 的 S1 引用回执。
这种回执没有拥有任何项目内发布目标，不能永久阻断普通列表；仍不称登记已完成。
旧上传尝试与 S2 发布回执保留原身份、完成状态和保守拒绝规则。
