# 工作区离线备份操作指南

此入口处理整个工作区，不只当前项目。SQLite 原样保存所有项目、聊天、提示词、任务、回执、历史和库内波形缓存。它是私密明文数据：应用密钥、连接令牌和设置文件不复制，但用户自己写入提示词或聊天的敏感内容仍会随数据库保存。

首版只创建和校验备份，不提供恢复、覆盖已有工作区或安全重执行承诺。保留未知任务和原始请求身份，不调用供应商、不自动重交任务。

## 使用顺序

1. 在右侧属性面板展开“工作区备份”，按需读取数据库计数。此读取不检查媒体文件，也不代表冷备份已就绪。
2. 正常关闭 Mioon，以及使用同一工作区的 Web/CLI 后端。不要删除锁、WAL 或 journal 来强行通过检查。
3. 在有项目锁定依赖和 Node24+ 的源码目录运行：

   `node apps/cli/src/backup.mjs create --source /absolute/workspace --destination /absolute/new-backup`

   source 是已有 Mioon 工作区，destination 必须是全新的、与源互不包含的私有目录。不要把用户素材文件夹当作工作区。路径在本机使用，不会发送到后端或模型。
4. 校验：`node apps/cli/src/backup.mjs verify --directory /absolute/new-backup`。
5. 只有命令成功、完整标记与全部文件重新核验一致，才能称为已校验的备份。仍不能据此宣称已恢复或允许旧付费任务重新执行。

默认 desktop 工作区位置和渠道区别请查 [DESKTOP.md](DESKTOP.md)。自定义启动目录以原有启动配置为准；本工具不会猜测或切换目录。

## 范围与上限

- 固定版本目录：manifest.json、最后发布的 COMPLETE.json，以及 payload 中的原 SQLite、已登记媒体和已知任务的暂存/未提交结果。
- 数据库最多512MiB；单文件8GiB；总payload64GiB；最多20,000文件；manifest8MiB；单个流式块1MiB；显示最多100项问题。上限不等于可用磁盘空间保证。
- 不复制应用credential/settings、连接令牌、浏览器资料、单独缓存目录或无法归属的未知文件。库内已有缓存行保留。
- 缺失媒体、部分结果、未知任务和排除项会明确记录；校验备份文件完整不等于源项目本来没有问题。
- 现有 Windows 存储安全门仍未通过原生验收。首片在既有受支持的POSIX私有目录策略下运行；不会修改已有权限。

## 文件完整性与取消

创建会原样复制关闭后的 SQLite。SQL 检查只在新建的私有临时副本中进行，不打开或迁移源数据库。校验也使用备份父目录下的私有临时副本，因此父目录需要当前用户可写；源和已完成 payload 不会被 SQL 打开。临时额外空间最高为512MiB数据库副本及至多三个64MiB SQLite sidecar，不包含在64GiB payload 上限里。

同一个工作区只能由持有独占锁的一方进行捕获；遇任何已有锁或非空WAL/journal即停止。工具不会自动判断旧锁可以删除。现有目录权限不修复，只以0700/0600新建自己的目录和文件。保护边界是其他系统账户，不隔离同一用户/root的恶意进程，也不保证硬件、文件系统绝不会丢失数据。

Ctrl+C/SIGTERM请求停止后续本地步骤，并等待已发出的文件操作收尾。它不是立即中断内核I/O的硬时限。中断或失败可能留下没有完整标记的新目录，请保留并检查，不覆盖或自动重试。若返回发布状态无法确认，保留该目录并单独执行verify；仅存在COMPLETE.json不能证明备份完整。

成功结果若附带SOURCE_LOCK_RELEASE_UNCONFIRMED，表示备份本身已校验，但工具未能确认释放自己的源锁。请保留备份和源锁，先核查原进程已退出；不要删除锁后自动重试。失败结果若附带sourceLockRelease: unconfirmed，同样不能将清理视为完成。


## 安全恢复到新的独立工作区

原始备份format1/schema24可使用独立离线恢复命令：

```sh
node apps/cli/src/backup.mjs restore --directory /绝对路径/原始备份 --destination /绝对路径/新工作区
```

新目标的父目录需要存在，目标本身必须不存在。不要选原工作区内部。
工具只检查固定祖先标记，format1未保存原始路径，不能识别所有改名来源。
失败或中断后保留目标，不要删锁、覆盖或自动重试。
若整段stdout丢失，可只读检查：

```sh
node apps/cli/src/backup.mjs restore-status --directory /绝对路径/原始备份 --destination /绝对路径/新工作区
```

`observed_guarded`只说明当前目标的固定schema及来源绑定符合原备份；它不证明
上次命令成功或此前fsync已完成，不会补发布、修复或执行任务。
打开恢复分支后，可开始新的本地导入、编辑、预览、导出。继承任务/审批/未知
结果保持历史状态且停止执行；新生成/Agent/Comfy/抽帧/波形解码暂不可用。
恢复分支首版也不能再次创建备份，保留原始备份是必要条件。
Desktop需把目标放在新根目录的`workspace`子目录，并显式选择新根目录；
不要复制旧token或会话文件。完整范围、限制和验证状态见[安全恢复说明](WORKSPACE-RESTORE.md)。
