# 项目生成与导出文件（S2）

当前项目把已生成的文件保存到项目目录，通过素材引用读取。临时文件和发布回执保存在本机私有 `tempDir`；它们不是项目媒体目录，也不能当成已登记的业务结果。

## 固定目录

下列文件夹名称固定，不随界面语言变化。目标类别由后端业务入口决定，客户端不能指定输出绝对路径。

| 目录 | 内容 |
|---|---|
| `生成/` | 视频和图片生成结果、模拟生成结果、抽帧、拆解关键帧、预演发布图像 |
| `导出/` | 时间线或分镜导出的成片 |
| `素材/` | 网页上传、附件转素材等操作产生的项目内副本 |

桌面路径导入仍引用用户选择的原文件，不因为 S2 自动复制到 `素材/`。导入、外部目录确认和媒体状态规则见 [PROJECT-FILE.md](PROJECT-FILE.md)。

普通项目目录及媒体文件不要求私有暂存目录的权限。应用数据库、本机记录、缓存和暂存目录仍使用各自的私有存储策略。

## 发布与登记

生成入口先完成下载或编码，验证完整内容、尺寸、MIME、字节数和 SHA-256，再调用共享发布器。发布器要求当前真实项目 store 和有效的应用、任务及效果权限。

发布流程如下：

1. 完整暂存文件及所在目录完成同步。
2. 在 `tempDir/publications/` 写入严格、有界、版本化的本机发布回执，并同步回执目录。
3. 按固定类别排他创建项目目标文件。
4. 核对目标身份、完整 SHA-256 和字节数，完成同步，得到可登记的发布证明。
5. 在短事务中再次检查目标身份和任务围栏，一起登记素材、版本或业务结果以及 owner outcome。
6. 事务提交后将回执标记为 `registered`，随后只清理该回执所绑定的私有暂存文件。

回执绑定项目、owner 类型及 ID、原始 requestId/inputHash、预分配 assetId/publicationId、暂存相对位置、目标相对位置、完整内容摘要和文件身份。owner 不通过解析文件名推断。名称经过规范化和有界清理，冲突使用新的 attempt，最多尝试 16 个目标；不会覆盖已有文件，也不会因为文件同名、同大小或同 SHA-256 就认领它。

同盘且支持硬链接时，发布器使用排他的 `link`。登记前暂存和目标可能共同引用一个 inode，此时只通过同一持久 intent 验证的普通目标读取，不放宽通用私有文件的单链接限制。跨盘或不支持硬链接时，发布器排他创建目标，先持久化新目标身份，再自行分块复制、核验和同步。

业务登记是原子的，文件系统与 SQLite 之间没有整体事务。复制尚未完成或业务事务回滚时，操作系统中可能已经能看到目标文件；没有素材登记的文件不会作为成功结果由媒体接口提供。

## 中断、取消与本地恢复

恢复复用已完成的本地产物，通过各业务已有的恢复或对账入口继续处理。S2 不增加供应商轮询、派发重试、定时恢复调度，也不会因本地文件存在而重新付费提交。

| 中断位置 | 处理方式 |
|---|---|
| 只有部分暂存字节，没有完整产物回执 | 保持 interrupted/unknown 等既有状态，不能视为完成结果 |
| 完整暂存及 intent 已保存，尚无目标 | 验证 owner、来源和暂存后继续本地发布，不重新解码或付费 |
| 跨盘复制中断 | 保留暂存、回执及不完整目标；普通发布重试使用新目标名，不覆盖或删除旧目标 |
| 目标完整，业务事务未提交 | 按同一 intent、assetId、完整内容及身份重新核验，再一次登记 |
| 业务已提交，ACK 或 registered 标记尚未完成 | 按精确资产及 owner outcome 确认已完成，不复制第二份结果 |
| scene 已发布部分关键帧 | 按完整批次 manifest 核验已发布项并继续剩余项，最后一次事务登记全部素材、镜头和 outcome |
| 发布后取消、效果权限失效或来源改变 | 项目文件保留；围栏未通过就不能登记新业务结果或宣称任务成功 |
| 项目位置、卷或目录不可用 | 保留本机产物和回执，暂停发布；重新取得宿主认可的真实项目位置，不在旧路径创建替代项目 |

文件保留不等于操作成功。没有匹配的完整回执、来源或 owner 时，不会自动认领文件；取消后的任务也不会借完整暂存重新打开。

S2 不自动删除项目媒体。事务失败、取消、scene undo、任务状态变化和本地恢复都不以删除项目文件收尾。允许清理的对象仅限已验证归属的私有暂存文件；手动整理项目中未引用的文件是另一项功能。尚未对账的本机发布回执不能按年龄清扫。

导出文件的显式恢复有更窄的规则：只能恢复既定的缺失位置，字节必须符合冻结摘要。目标重新出现时，即使内容相同也拒绝覆盖。中断留下的目标同样保留，不能借恢复接口任意换文件。原生打开或显示导出文件的校验见 [EXPORT-CONTROLS.md](EXPORT-CONTROLS.md)。

## scene 与预演的分工

scene 将逐帧 PNG 暂存到 `tempDir/scene-staging/`。所有关键帧验证完成后，先持久化包含每项 assetId、完整摘要、几何、段号、帧选择及源视频身份的完整批次 manifest，再进入业务 `persisting` 状态。只有部分 PNG、缺失或损坏的 manifest 都不能授权成功恢复。

启动对账可以识别完整 scene 批次，仅执行本地核验、发布和登记。owner、效果权限、源视频和任务修订围栏仍然生效。关键帧的项目文件逐项发布，但素材、镜头和 outcome 最终一起提交；undo 只撤销符合条件的镜头，已发布关键帧保留。

如果启动时 Mio 的来源日志或效果权限尚未就绪，完整 scene 批次保留 manifest 并退出活动状态，不占住其他 scene 任务的队列。权限恢复后的既有 resume 入口可继续该批次的本地登记；这不会重启解码，也不会重新打开取消任务。

预演图像使用专用发布入口，写入 `生成/`，携带 node、keyframe、sceneRevision、requestId 及完整图像内容的绑定。普通素材导入不能冒充预演发布。预演缩略图 BLOB 仍在缓存中；未知 ACK 按专用入口的精确请求身份查询，不通过“找到相同摘要的素材”认领结果，也不会自动重发。已登记后的同字节重新指向或删除 node 不会抹掉既有 ACK 和来源事实；新的发布仍核对当前来源。预演界面、请求协议和编辑审核规则由预演模块维护。

## 跨机器携带与重新指向

终态来源保存在项目素材及不可变结果中，不只存在本机暂存回执里：视频使用生成发布证明和不可变版本；frame 保存原始抽帧事实；scene 保存单关键帧的严格来源投影，并与项目中的不可变切点结果核对；预演保存其专用身份。

同 ID 项目从别处打开、缺少本机任务历史时，可以按这些可携带事实进行只读核验。它不会重建任务、重新解码、重新提交或写回历史。有本机任务、请求或执行残留时，仍严格核对本机 owner；损坏记录不能退化成“来自别处”绕过校验。

来源事实与当前文件位置分开。frame、scene、图片或视频生成结果同完整内容的重新指向可以保留 assetId 及历史来源，实际读取仍受 L1 的完整内容、状态和目录确认约束。导出不能通过任意外部重新指向冒充已发布成片。只复制项目文件不会携带媒体字节，也不会授予新的外部目录读取许可。

本机 pending/未发布状态没有可携带标记。若只复制项目目录而不携带本机 `tempDir` 回执，中断留下的文件仍不是登记产物，不能被当成成功结果；接收机器可能把它视为普通未引用媒体，不能仅凭名称区分它与完整未引用文件。这是当前协议的明确限制。目录发现功能需要利用本机发布回执跳过已知未发布目标；跨机器没有这些回执时，不能据文件名补造状态或来源。

## 项目版本

V1-B 快照保存完整的 S2 素材行，包括引用和可携带发布来源，不复制媒体文件或本机任务。恢复时，已有素材保持当前引用、修订及配套内容身份，其他可变字段恢复；缺失素材按快照补回引用与来源事实，不恢复媒体字节，也不新增外部目录许可。缺少原本机 export 记录时，补回素材不能据此伪造一次完成的导出。

版本正文会规范化 JSON 对象键顺序。发布证明按完整结构和值核对，键顺序不影响有效性；owner、assetId、完整哈希、大小、固定目录和数组顺序仍须严格一致。版本恢复后的显式成片文件恢复继续受同样的排他写入和缺失目标限制。
