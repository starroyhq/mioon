## 1. 首版的产品边界

- 未打开项目：显示独立项目首页，提供当前工作区的项目列表、明确打开和新建入口。没有画板、剪辑、素材栏、项目属性、任务或导出操作的空壳。
- 打开成功：才显示现有工作台，保留用户已经调整的布局、画板/剪辑、右侧页签及交互。已打开但没有镜头的项目仍是合法工作台，继续显示原来的创建镜头/三镜头结构引导。
- 关闭项目：在安全处理当前页面输入后回项目首页。它是本窗口的导航，不是退出应用、删除项目、停止后端或取消已接受的生成/导出。
- “打开”仅指当前已连接工作区中的项目。首页不提供任意项目文件打开、目录切换或可移植项目导入；现有离线工作区备份/恢复另有完整流程。
- 列表名称为“项目列表”，沿用当前按项目更新时间排序；有效定位记录可单独标“上次打开”。不把 `updatedAt` 叫最近打开时间，不宣称已存在多项目 MRU。
- 新页面使用现有 shadcn/Base UI 包装、颜色和字体。新增展示为独立 TSX，导航判定为窄 TS 模块；不借机重写整个 App、迁移业务状态机或重设计用户工作台。

## 3. 页面与状态

页面有三个层次，保持业务权限来源不变：

1. **应用连接层**：启动连接、访问令牌解锁、工作区身份检查、连接/配置错误及重试。认证错误、服务不可达或可信工作区身份改变不伪装成某个项目损坏。继续复用现有登录/启动错误页。
2. **项目入口层**：已连接后的 `home`、`opening`、`open-error`、新建表单。首页可显示恢复分支限制、定位记忆状态与错误，不挂项目编辑侧栏。既有无项目时也可到达的 Agent/图像/Comfy 全局连接设置保留明确入口；从首页打开时使用独立区域或页内 tab，不新增 modal，复用既有设置组件与可见性清密钥规则，不放入项目卡片或借项目授予权限。不复制设置实现，不把未打开项目的生成表单当作设置页。
3. **工作台层**：`ready` 和短暂 `closing`。只有当前请求仍属于同一工作区/项目/选择 epoch、偏好完成、加载完成且 `data.project.id` 与目标一致，才进入 `ready`。`closing` 保留当前表单与 controller，直到关闭决策完成；失败或取消留在当前工作台。

`activeProject` 表示已经成功打开并可交互的项目；`openingProject` 只是正在尝试的目标。不能把设置了目标 ID 当作打开成功。所有项目 scoped effect 的执行资格取决于当前有效 session，而不是首页中留着的上次项目 ID。

重试项目加载只重新执行已有读取与校验；不提交编辑、恢复任务或模型请求。项目加载失败留首页显示该次目标和原因，保留列表选择及明确重试。401 回连接/解锁层，工作区身份变化按已有 fail-closed 处理。

## 4. 启动、URL 与上次项目

- 普通应用启动仍调用现有 `chooseInitialProject`：有效 `?project=` 优先，其次有效定位，最后列表首项。自动选择发生在首页 `opening` 状态，成功后进入工作台。初次读取/自动显示仍不写定位记录。
- 失效 URL/定位的现有回退和说明保留；若回退目标也打开失败，留首页显示失败，不继续无界遍历或重试其他项目。
- 只有用户明确打开且真正成功的项目才走既有 `rememberOpened`。关闭项目不清 locator，不把 `null` 写入，不覆盖双窗口 CAS，不把首页当新项目记忆。
- 首版建议增加**仅页面路由** `?screen=projects`，表示用户明确回首页；关闭时去掉 `project` 并写此标记。它不进入 API、不存认证或路径、不赋予任何业务权限。显式有效 `project` 与此标记同时存在时项目链接优先；正常页面写入不会同时产生两者。
- 明确首页路由的刷新/浏览器历史仍留首页；未带此标记的桌面全新启动继续按既有 locator 自动打开。由此区分“本窗口回首页”与“下次从应用启动恢复”，不需要偷偷清除定位文件。
- 若使用其他具体路由名称，实现前固定同样的优先级合同及正负测试；不能用本地内存布尔值冒充可刷新、可后退的首页路由。
- popstate 打开、关闭和取消都经过当前 owner/草稿边界。取消历史导航时恢复当前已接受路由，不把 `project=null` 拼进 URL；较晚结果不能把已经选择首页/另一个项目的窗口拉回。
- 恢复工作区不读写正常 locator，继续使用已有来源身份与视图偏好隔离；可列出/打开允许的本地项目，限制说明与业务拒绝保持。

## 5. 打开与新建入口

首页是真实入口，不是静态展示：使用已有 `project.list`、`project.get`、`project.create` 与偏好加载路径。列表刷新不偷偷选项目、不批量读取所有项目正文或任务；更新时间标记准确。`project.get` 保留原有 `timeline.ensure` 初始化语义，不能把打开流程宣传为底层数据库绝对零写入。

首页新建可用独立内联表单，复用当前名称/描述验证和服务；工作台原有新建入口可保留现有对话框，两者共用同一创建/打开动作，避免复制业务提交逻辑。创建成功但旧页面已离开时，不能用晚 ACK 抢回首页或新项目；记录本身若已经写入仍保留。失败/响应未知不自动再次创建，先提供刷新列表核对路径。本片不声称给原 `project.create` 新增跨重启幂等保证。

打开成功后恢复已有视图和选择；本地草稿仅在对应项目及目标已验证后展示候选。首页不恢复表单、不提交草稿、不根据保存记录自动运行原 intent。

## 6. 关闭项目的安全默认

关闭入口必须单独编排，不能直接调用会 discard 的 `guardProjectNavigation`，也不能调用桌面退出/后端取消。

1. 捕获 workspace identity、成功打开项目、导航/项目 epoch、各相关 controller 及输入 capture。关闭中仍显示原工作台，禁止第二次关闭/新业务提交；新的输入或导航意图使原关闭失效。
2. 对支持的片段、镜头文字、成片名称草稿，以及视图/定位，按现有能力做有界本地 drain。它只保存旁文件/偏好，不保存项目业务编辑、不执行 intent、不重设业务基线 revision；旁文件 CAS 版本按现有 ACK 正常推进。各次 await 后及最后卸载前都复核 capture 和 scope。
3. 已确认保存的本地草稿原样保留，回同项目再提示恢复。不能用删除草稿来简化关闭，不能把“保存本地草稿”说成“已保存项目修改”。判断要用专门的同 capture 持久化结果，不能统一用 `hasUnsaved`：片段旁文件确认后业务 dirty 仍可为真，镜头文字的 `hasUnsaved` 还包含完整属性表单的 `formDirty`。标题/提示词 flush 成功不证明引用、参数等非文字编辑已保存；仅为关闭入口补必要的窄 dirty 分类，不改整套 Inspector 保存基线。
4. 未持久输入、未知 PUT/prepare/DELETE、冲突或损坏默认留在工作台，显示明确原因与原有核对/重试途径。关闭准入逐域检查 `retainedPreparation` / `intentUncertain` / `retainedDeletion` 等实际状态，不只看 dirty 或 flush 的单个返回值。不能把 GET 空值当作撤销未知写入，也不能重建 controller 或新 requestId 绕过它。
5. 现有明确退出选择只能在原条件下复用：片段“放弃当前输入，保留草稿记录”仍须满足原 pending/owner/capture 限制，且说明迟到写入可能出现；镜头文字/成片名称的拒绝后退出不能扩大到 unknown/conflict。安全关闭无可证明路径时留在工作台，不能提供一个会静默丢身份的“强制关闭”。
6. 仅内存的 Agent/图像提示、字幕、规格、素材范围、主体表单及其他未覆盖输入，继续明确询问是否放弃，允许取消。只清用户同意的当前表单，不能连带删除已经持久的其他草稿。密钥输入继续按已有隐藏规则清空，不能进入草稿。
7. 已持久的原业务 intent / 已接受任务本身不要求被取消后才能回首页。保留其原请求身份、receipt、hold 与历史；业务结果未知不等于失败。关闭只停止本窗口观察或撤销尚未执行的本地提案展示权限，不新增 cancel/retry/approve 请求。
8. 最终成功关闭才推进 session/nav epoch、设 `activeProject=null`、`viewReady=false`、隐藏/卸载项目展示并更新首页 URL。不能先清 project 再尝试保存草稿；不得让关闭前的 ACK、读取、RAF reveal 或已打开确认框重新选择项目、打开页签、显示其他项目数据。

App/session 级 task、preferences、locator、localDelivery 与其未知身份 owner 保持稳定。片段表单 controller 需要在安全关闭成功后才 dispose；不要把整个 App key 为 projectId 后重建。保留数据身份不等于保留隐藏的可交互工作台。

## 7. 隐藏、取消与效果挂载

- 首页不挂载 ReactFlow、Timeline、项目 Inspector、Agent 聊天、图像生成、TaskCenter、交付表单等项目展示；现有 app-level controller owner 不随页面消失重建。
- 隐藏/卸载先同步失效 scope/visible fence。项目轮询、波形、抽帧观察、预检、样本峰值检查等遵循原各自 stop/abort 合同；只读检查可以取消自身本地工作，但绝不把同一策略泛化成取消已接受的生成/导出。
- 付费确认窗口、编辑审批和其他项目 portal 在失效前关闭或作废；旧确认按钮与晚 ACK 不具备新项目/首页权限。返回工作台需重新取得当前选择和明确确认，不能恢复旧弹窗即自动批准。
- 全局连接/配置 owner 与项目任务 owner 分开。全局错误留在应用层；恢复分支限制不会因首页隐藏而解除。首页不报告“没有任务”来代替未读取某项目任务的未知状态。
- 多窗口关闭只改变该窗口显示。另一窗口可继续编辑，已保存记录、locator CAS 和草稿 revision 的竞争仍按现有规则处理；不新加跨窗口广播式关闭或清理。

## 8. 组件职责与预计修改范围

- `ProjectHome.tsx`（拟新增）：受控项目列表、首页新建区域、打开中/失败及可访问状态；通过窄 callback 发用户意图，不直接调用业务服务或处理 key。
- `project-session-navigation.ts`（拟新增）：有限页面状态/路由、成功打开与关闭 capture 校验；不变成通用业务执行器或新的持久台账。
- `App.jsx`：保留既有 owner，只接页面边界、已有创建/读取动作、关闭编排及 history。原用户工作台 DOM/CSS 只在确需加入“项目首页/关闭项目”入口处最小接线。
- 共享 UI 包装及现有设置组件复用；新增 CSS 限首页作用域，不改现有工作台选择器。首页不需要新 DB schema、RPC、CLI/MCP 操作或模型权限。
- 测试：独立路由/生命周期因果测试、真实 App handler 与共享控件键盘行为；更新确实受影响的旧 harness，保留原业务/身份断言。不以静态页面截图替代真实打开/关闭行为。

## 9. 验收矩阵（实施后的门，当前未执行）

| 场景 | 必须证明 |
| --- | --- |
| 全新空工作区 | 只有首页，新建/说明可点可键盘操作；不存在半工作台或隐形项目控制 |
| 已有多个项目 | 项目列表时间含义准确；有效 locator 自动打开不写新记忆；明确打开才记录 |
| 新建 | 真实创建一次并打开；慢 ACK/离开/重复点击不抢页面；未知不自动重建 |

| 恢复分支 | 首页与工作台都说明限制；正常工作区 locator不读写，held任务不执行 |

先固定上述合同与因果红测试，再做首页和最小接线；受影响/typecheck、fresh build、Linux 原生流程及父级全量都针对最终源码。不为了页面分层扩大成全 App 重构或新存储系统。

## 10. 有限交付阶段

- **H1：独立首页与正确打开。** 实现真实项目列表/新建/打开、连接层分离、成功数据和偏好校验后才展示工作台，保留既有 URL 与稳定定位自动恢复。验证空、已有、失败、恢复分支与晚响应。此时关闭项目和完整首页历史路由仍待 H2，不能称首页闭环已完成，也不先暴露不安全的关闭按钮。
- **H2：安全关闭与历史路由。** 完成第4、6、7节的显式首页路由、返回/前进、局部 close 编排、草稿与未知身份保留、多窗口及可见性边界。未知持久化保持安全退出条件，不以扩大 discard 或新增业务提交换取流畅。
- **H3：跨流程最终验收。** 在 H1/H2 的最终集成源码上完成整个矩阵，包括默认真实 Linux 包的打开→编辑→本地草稿→关闭→重开→明确恢复/保存→实际导出，以及正常退出再启的自动定位。对最终源码执行受影响、类型检查、构建/打包和父级完整门；保存失败及限制，不把正常退出冒充强杀验证。
