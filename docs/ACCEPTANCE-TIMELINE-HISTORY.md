# Durable timeline undo/redo acceptance — 2026-10-09

## Increment

The shared timeline service now records before/after snapshots for the six edit
operations: track add/update, clip add/update/remove, and seed from selected shots.
Snapshots contain only tracks, clips and duration. Undo/redo preserves stable IDs,
increments the current revision, and never rewrites media, selected versions,
provider jobs, spending, or exports. A new edit discards the redo branch; this is
an editing undo stack, not an append-only audit trail.

Schema version 3 additively introduces history entries and a persisted cursor.
Existing timeline and request-response bytes are unchanged. Old data is the
baseline for its first new edit. The read-only history operation does not create
an absent timeline. A single SQLite SELECT provides consistent history metadata;
project reads return timeline and history from one transaction.

The renderer has Base UI Undo/Redo controls, operation labels, applied/total
counts, guarded keyboard shortcuts, exact durable request recovery, pending and
dirty-draft disabling, and conflict refresh. HTTP, CLI and MCP derive the three
new operations from the same contracts and use the same backend implementation.

## Reproduction and limits

Use a disposable copy of `examples/multitrack-project` beneath
`evidence/timeline-history/runtime/`, and start the normal backend with live
providers disabled. Sign in to that local test instance in the own-cloud CUA
browser. Bundle the browser harness with the repository's installed esbuild,
then call `runHistoryBrowserAcceptance({tab, projectId, dataDir, outDir})` in CUA;
the exact bundle/run form is documented at the top of the script. Keep outputs
in the task workspace, then copy final evidence to the ignored evidence folder.
The harness refuses a data directory outside that disposable runtime area.

Direct Chromium startup in the shell sandbox could not create its Unix socket;
acceptance instead used the already available own-cloud Chromium and a native
local backend. No Chromium sandbox flags or network/security settings changed.

No new Electron package, macOS/Windows runtime verification, source archive,
Library upload, live generation, provider media upload, push or deployment was
performed. Original example data and historical deliverables remain unchanged.
The parent owns the local commit after independent review and screenshot review.
