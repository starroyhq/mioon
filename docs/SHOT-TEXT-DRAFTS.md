# 镜头标题与提示词：本地草稿和原请求恢复

开发基线：`6897d2008b0e0f113f53865c50fb2d27276b0cbe`。定向、构建、最终 Linux 原生门与父级独立全量已完成。下文描述实现合同，实际终态记录见末节。

## 用户入口与范围

画板右侧沿用同一镜头表单，标题与提示词一起使用“保存标题和提示词”。普通工作区自动保存这两个字段的原始输入；重新打开只显示恢复提示，明确恢复后才填回表单。恢复和只读核对不更新镜头、不调用模型、不生成媒体。其他字段仍使用既有保存流程；文字保存不替代参考图、时长、画幅和参数的确认，也不清除它们的待确认请求。

草稿带原镜头、原 revision 和原文字。恢复旧草稿不能把基线偷偷换成当前版本；检测到变化时保留原输入并提示冲突。用户可核对后明确保留当前输入、采用当前文字基线。新选择、新输入、关闭面板或另一个窗口的响应不能覆盖较新的表单。历史已应用回执用于确认原请求，不强行覆盖当前表单。

新文字逻辑使用 TS/TSX，App/Inspector 仅作既有表单与生命周期接线。没有新增公共 RPC、CLI/MCP 或内置 Agent 工具；既有 `shot.update` 响应、稳定请求键、数据库结构和旧历史回执不改写。

## 保存与未知结果

每次明确保存先写入不可变的文字意图并确认持久化，再调用既有 `updateShotInProject`：固定 project/shot、expectedRevision、原 requestId，以及仅含 title/prompt 的精确 patch。省略字段保留省略语义；prompt 空字符串是清空，空标题仅可作为未提交草稿。不同输入不能重用同一意图身份。

同项目最多一个尚未确认的文字意图。两窗口、重复点击、断连或重开都不能自动再次提交。明确“恢复同一原文字请求”才核对或执行该原输入，可能首次执行尚未派发的保存。SQLite 原始回执若已存在，先确认原响应；不能因后来 revision 变化改用新键。fresh `not_applied` 仅来自可信服务的实际回滚证明并核实无原回执，普通网络错误、空读取或任意 4xx 不作未应用证据。

副文件 GET 是只读发现，不是状态探针式变更。草稿 PUT 回执未知时保留原 CAS/身份/文字，只允许明确原样重试。删除结果未知也保留原删除身份；用户可明确“核对并接受当前草稿状态”，仅当同工作区的权威草稿 revision 已超过该删除所用 revision，证明迟到旧 CAS 不可能再生效，才释放本地不确定状态。该动作不宣称原删除成功，仍保留之后出现的新草稿。空记录但 revision 不变不构成证明。

从画板切换到另一个镜头后立即点击生成，必须等该目标的文字状态核对完成，再由用户明确点击；不会排队等待后自动提交。历史任务重试仍使用原固定快照。

这不是项目全部操作的全局冻结：旁文件固定文字意图有项目级 reservation，既有非文字操作继续其各自回执/恢复规则。当前表单会阻止文字待确认时的混合保存；其他服务调用仍由既有 ownership、CAS 和精确回放保护。

## 存储、容量与隐私

固定旁文件 `local-shot-text-v1.json` 使用已有私有文件适配器、临时文件原子替换和父目录 fsync。工作区服务锁是单写进程前提；不声称多写进程的独立锁。失去实际锁、信号取消、链接/权限/身份不明、损坏文件或持久化确认未知均失败关闭，不当作空白覆盖。文件模式 0600，私有目录与既有平台 gate 相同。

- 工作区最多 128 个 project+shot 槽位，删除草稿后的 revision 墓碑仍占位，不自动淘汰待确认身份
- 每槽序列化 256 KiB，整个旁文件 16 MiB；这是逻辑载荷上限，不是整工作区磁盘用量承诺
- 原始标题最多 512 UTF-16 单元、原始提示词最多 6000，要求合法 Unicode，不截断；业务保存仍遵循标题 1–150、提示词 0–5000
- 最大合法保留文本经 JSON 转义预算 162,672 字节；128 个最大槽可能先触及文件上限，服务明确报容量错误并保留已有记录
- 历史完整镜头响应最多 1 MiB，关联记录有 SQL 物化前大小/数量限制，持久化回执保持原字节
- 每槽独立 draftRevision/intentRevision；已结算最新意图仅可由精确 CAS 的下一意图替代，原业务键仍由原 SQLite journal 保留

仅允许文字、来源基线及原文字操作参数，不允许密钥、认证配置、连接令牌、任意路径或媒体字节。提示词自身可能包含敏感内容，因此这是本机明文私密数据，不是密钥保险箱。明确放弃草稿不保证清除最新意图里已捕获的文字；没有自动清理/安全擦除功能，容量满不能通过静默丢弃身份解决。

既有离线 backup 只捕获已保存项目/媒体与其既有范围，不包含该旁文件或临时文件。恢复分支在草稿文件 I/O 前返回 unsupported，右栏说明限制，原有允许的手动镜头编辑/保存保持可用。不能把本地草稿当作可搬迁的工作区备份。

## 私有 HTTP 合同

所有路径沿用 startServer 的 Host/Origin/authentication 检查，无通用执行或客户端 outcome 字段：

- `GET /api/local-shot-text?projectId=…&shotId=…`：只读发现该镜头与同项目待确认目标摘要
- `PUT /api/local-shot-text/draft`、`DELETE /api/local-shot-text/draft`：固定文字草稿 CAS
- `POST /api/local-shot-text/prepare`：持久保存精确文字意图，未执行业务
- `POST /api/local-shot-text/execute`、`POST /api/local-shot-text/recover`：原意图身份与 instance/CAS 复核后调用单一已绑定服务

输入严格字段、JSON/UTF-8 与 256 KiB 限制；HTTP 的 15 秒传输期限不取消已开始的业务，也不是未应用证明。scope/channel/instance 均由后端生成，原实例请求不能跨重启直接派发。只读 SQL 先界定当前与历史所有权/载荷，在同一只读快照中调用原共享 replay reader；无 foreign response 泄露。
